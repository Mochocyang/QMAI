Task 1 · 人物名单缓存与指纹 纯 lib

新增 src/lib/novel/bindable-characters-cache.ts

  • computeBindableFingerprint(projectPath)：对 wiki/entities 与 wiki/outlines 下的文件（路径 + 字节数 + mtime）排序后做哈希。
  • readBindableCharactersCache(projectPath)：读 <项目>/.qmai/bindable-characters.json；文件缺失、JSON 损坏、字段类型不符一律返回 null（不抛异常）。
  • writeBindableCharactersCache(projectPath, entry)：writeFileAtomic 落盘。
  • loadBindableCharactersWithCache(projectPath, compute)：指纹命中 → 直接返回缓存；未命中 → 调 compute 并写入。

数据结构

type BindableCharactersCache = {
  fingerprint: string
  names: string[]        // 已合并「本地 + LLM 精修」的最终名单
  llmRefinedFingerprint?: string  // 该指纹下是否已做过 LLM 精修
  updatedAt: number
}

测试（先红）：未变命中 / 新增文件失效 / 改内容失效 / 删文件失效 / 损坏 JSON 重建 / 目录不存在不抛。

变异：把指纹里的 mtime 去掉，必须让「改内容失效」这条失败。

Task 2 · 本地解析与 LLM 后台精修分层 修 P2a 核心

改 src/lib/novel/character-aura.ts

  • 新增 listBindableNovelCharactersLocal(projectPath)：只做实体页 + 大纲标题的本地解析，同步毫秒级、绝无网络。
  • 保留 listBindableNovelCharacters(projectPath) 签名不变，内部改为：先返回本地结果；LLM 精修作为独立导出 refineBindableCharactersWithLlm(projectPath)，由调用方在后台触发。
  • LLM 精修完成后把合并结果写回缓存（Task 1），并标记 llmRefinedFingerprint，同一指纹下不再重复精修。
  • LLM 超时下调（30s → 可配置且更短），且并发而非串行；超时或失败静默保留本地结果。

绝不能出现的形态：任何「等 LLM 回来才返回」的路径。首次调用必须在毫秒级返回本地名单。

测试（先红）：本地路径在 mock 掉 streamChat 为「永不 resolve」时仍立即返回；第二次调用命中缓存不重复精修；精修结果并入本地结果并去重；LLM 抛错不影响本地名单。

Task 3 · 解耦灵魂列表与人物扫描 修 P1

改 src/components/novel/character-aura-view.tsx（refresh() 在 :196）

  • 拆成三条独立加载线，各自 setState；setAuras 不得出现在任何与人物扫描同一个 await 链上。
  • 新增 characterOptionsLoading 局部状态，只在「绑定人物」这一小块显示 loading。
  • 人物刷新失败不得影响灵魂列表渲染（各自 catch）。

测试（先红，最关键的一条）：把 listBindableNovelCharacters mock 成永不 resolve 的 Promise，渲染 CharacterAuraView 后灵魂列表必须已经渲染出自定义灵魂的名字。修复前这条必然失败（正是 P1 的机理）。

变异：把人物扫描重新塞回 Promise.all，上述测试必须失败。

Task 5 · 忽略词表与非人名规则 修 4.2-B

新增 src/lib/novel/bindable-characters-filter.ts

  • NON_CHARACTER_NAME_RULES：强特征规则数组（如 /通用手段$/、/执行群$/、/坏路径$/、/总览$/、/当前状态$/、/^(冲突点|当前状态)$/ 等）。
  • isLikelyNonCharacterName(name)：纯函数，可测。
  • readBindableIgnoreList(projectPath) / addBindableIgnore(projectPath, name) / removeBindableIgnore(projectPath, name)，落盘 <项目>/.qmai/bindable-characters-ignore.json。
  • filterBindableCharacters(names, ignoreList, boundNames)：已绑定的名字永远保留（安全阀）。

测试（先红）：规则命中/不命中各若干例；忽略表增删落盘与读回；已绑定的名字命中规则时仍被保留。

变异：去掉「已绑定保留」安全阀，必须让对应测试失败。

Task 7 · 全量回归 + 独立终审

  • 聚焦套件 + tsc -p tsconfig.app.json --noEmit。
  • 全量 A/B：与基线同一份测试对比，要求失败数不增加、本次涉及文件全部通过。
  • 独立子代理终审：对抗性审查根因结论、缓存正确性、安全阀、无回归；并自行造变异尝试证伪。

验收清单

  1. 灵魂列表渲染路径中不存在人物扫描的 await（用永不 resolve 的 mock 钉死）。
  2. 人物名单首次返回为毫秒级本地结果；LLM 仅在后台精修且同一指纹只做一次。
  3. 第二次打开绑定对话框不再出现「正在读取小说人物」；重启后仍命中磁盘缓存。
  4. wiki 变化后缓存失效并重算（新增/改内容/删文件三种都覆盖）。
  5. 搜索实时过滤；已勾选项不因过滤丢失。
  6. 人物列表每行 5 个；窄屏降级无溢出、无重叠（浏览器实测）。
  7. 忽略规则 + 用户忽略表生效，且已绑定的名字永不被过滤掉。
  8. 绑定语义不变：仍自动入库、仍幂等。
  9. 全量回归失败数不增加；tsc 退出码 0。
