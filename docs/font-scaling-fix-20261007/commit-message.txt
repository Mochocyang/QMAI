docs(字体): 记录界面字号/字体失效的根因调查与设计方案

用户报告：界面字号调整只在部分位置生效（"只有按钮有效果"）、界面字体
设置无效果、字体选项偏少。

根因（均有实测证据）：

1. 字号 —— 单位错配。App.tsx 用根字号实现缩放，而根字号只影响 rem；
   代码里 557 处字号写死为 px（含 tsx 的 text-[Npx] 任意值 306 处），
   不随根字号缩放；Tailwind 内置 text-*（1489 处）用 rem 故会缩放，
   按钮恰好大量使用它们，因此表现为"只有按钮有效果"。
   实测：根字号 100%→150%，设置页 27 个文本元素全部未缩放。

2. 界面字体 —— ui-test.css:5 把 --ui 硬编码为苹方/雅黑栈，而按钮、
   输入框、对话框、菜单、设置、工具区共 5 处 font-family 使用 var(--ui)，
   用户选择被全面绕过（全仓 --ui 仅此一处定义，皮肤也不重定义）。

3. 正文 —— 写作区使用 var(--serif)，与"界面字体"是两条独立通路。

调查过程中的方法迭代与自我纠错（已记录，避免重蹈）：

- "字体是否生效"的判断迭代三次。截图哈希法与 canvas 测宽结论矛盾，
  坚持交叉印证后定位为截图法缺陷，推翻了先前"所有浏览器都看不到
  系统字体"的错误结论。最终采用 canvas 像素哈希（三项自检通过）。
- 早期清点只扫 CSS 得 262 处，漏掉 tsx 任意值 306 处；完整规模是
  557 处 / 67 文件。按早期结论施工只会修好一半。
- 自检断言写错：把"对照字体必须与基准不同"当作合格条件，忽略了
  "缺失字体回退到默认字体"的正常情形，导致假失败。

已建立的验收体系（含工具自检，避免用坏工具得出结论）：

- census-computed-font.mjs：计算样式普查双判据 —— 100% 时逐元素等效
  （零视觉回归）、150% 时全部恰为 1.5 倍。工具已自检：能区分等效与
  不等效，能抓到真实缺陷（设置页 27/27 未缩放）。
- check-root-fontsize-authority.mjs：排除"根字号被 React 覆盖"这一
  会伪造结论的可能（观察 3 秒稳定，rem 探针 1.5 倍、px 探针不变）。
- report-font-resolution.mjs：字体解析权威报告。

设计要点（阶段 1+2）：

- 阶段 1：557 处绝对单位换算为精确 rem（所有 px 值均为 0.5 整数倍，
  ÷16 得精确有限小数，故 100% 下计算值逐位相同），23 处 px 行高改
  无单位比值；不动容器/间距/图标尺寸；字号范围放宽至 80%–150%。
- 阶段 2：--ui 派生自 --qmai-ui-font-family；新增正文字体与正文字号
  独立设置（正文 18px 现重复 4 处，查找高亮层须与输入层同步，故引入
  单一来源变量）；字体选项扩充为只列中文字体并移除 Arial。
- 阶段 3/4 登记：Rust 枚举本机中文字体（windows-sys 已缓存，离线可做）、
  捆绑 OFL 字体并按用户安装。已确认 MiSans 许可禁止再分发字体文件，
  不可捆绑。
