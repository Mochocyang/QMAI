chore(发版核验): 交付核验区分"打标签时"与"发版后"两个不变量

打完 v4.1.1 后，main 因后续修复提交前进到 998cdc0，于是核验脚本报
「远端 main = 998cdc0，应为 bd8f2cb」—— 看起来与真问题一模一样，
实际是脚本把「打标签那一刻的不变量」当成了「永久不变量」。

拆成两条：
- 标签：v4.1.1^{} 必须**始终**等于发版提交 bd8f2cb，永不允许移动（严格）
- main：可以合法前进，但发版提交必须仍是它的祖先
  （main 恰好等于发版提交时也算通过）

同时记录 tag-message.txt（annotated tag 的正文）。

另修一处查询写法：`git ls-remote --tags origin v4.1.1` 带 pattern 时
**不会**返回 `refs/tags/v4.1.1^{}` 这一行，于是"找不到剥离引用"会被误读成
"这不是 annotated tag"。改为列出全部标签后本地筛选，并断言
对象 SHA 与 commit SHA 不相同 —— 这才是 annotated tag 的判据。
