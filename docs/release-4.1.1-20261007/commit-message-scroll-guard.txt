fix(记忆中心): scrollIntoView 加特性检测，消掉 jsdom 下的未处理异常

全量跑测试时 vitest 报 Errors 并以非 0 退出：

  TypeError: tabRefs.current.get(...)?.scrollIntoView is not a function
    ❯ src/components/novel/memory-center-view.tsx:202:33

根因：jsdom 不实现 Element.prototype.scrollIntoView。两处调用都在
requestAnimationFrame 回调里，异常逃出测试作用域，于是**用例本身仍然通过**、
只在进程级报 Errors，而且时序相关、时有时无 —— 上一轮全量 A/B 里就没出现，
所以它躲过了一次。

这不是用户可见缺陷：WebView2 / WKWebView 都实现了该方法。但它会污染测试输出，
且 app 接了 Sentry，未处理异常会成为噪音。统一收进 scrollIntoViewIfSupported
做特性检测。

为什么必须两向都测（memory-center-scroll-guard.spec.ts 4 条）：
只断言"不抛错"的话，一个永远不调用 scrollIntoView 的实现也会全绿 ——
那等于把真实功能一起删掉了。所以既有"支持时确实按选项调用"的正向用例，
也有"缺方法 / 非函数 / null"三条防御用例。

非空性证明（docs/release-4.1.1-20261007/prove-scroll-guard.mjs）：
- 去掉特性检测 → 防御用例变红
- 去掉实际调用 → 正向用例变红
两向 2/2 如期变红，源码按 SHA256 还原。

同类未做防护的调用还有 6 处（file-preview.tsx 2、graph-view.tsx 1、
book-analysis-workbench.tsx 3），本次不扩大范围，留待单独处理。
