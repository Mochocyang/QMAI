# 两个线上故障的定位与修复（2026-10-09）

用户报了两个看起来毫不相关的故障，实际都源于**同一类错误：假设被静默破坏，而系统没有兜底**。

| # | 故障现象 | 根因类别 | 提交 |
|---|---|---|---|
| 1 | 章节正文没有滚动条、滚轮滚不动 | CSS 类名撞车，破坏了 `height` 继承链 | `9f3d6d7` |
| 2 | 共创报「模型未返回 outline_discuss 协议块」 | 提示词自相矛盾，且闸门没有恢复路径 | `14a2c56` |
| 3 | 共创里模型产出了完整卷纲，却被当协议缺失丢弃、只剩 JSON 源码 | 把「讨论轮没有交付物」写死成假设，而不是判定 | `fa87d26`（见第 4 节） |

## 1. 正文滚不动：类名撞车

### 现象与直觉误区

加了写作字数状态栏后，正文区**没有滚动条、滚轮无反应**（注意是「滚不动」而不是「能滚但看不到」）。

第一直觉会去查 flex 布局，但布局本身没错。真实原因是**两个不相干的容器共用了同一个类名**：

| 元素 | 类名 | 出处 |
|---|---|---|
| 编辑器内部正文容器 | `.ui-test-editor-body` | `ui-test-editor.tsx` |
| 我为状态栏加的正文栏容器 | `.ui-test-editor-body` | `ui-test-workspace.tsx`（`c25b22e` 引入） |

而 `ui-test-editor.css` 里有一条只该作用于编辑器内部的规则：

```css
.ui-test-editor-body > div { height: auto; overflow: visible; }
```

### 为什么后果是「滚不动」

`.ui-test-editor-body > div` 命中了 `PreviewPanel` 的根 div（也就是高度链的起点）：

```tsx
<div className="flex h-full flex-col">   {/* h-full → height:100% */}
```

这条规则把它的 `height:100%` 改写成 `auto`，于是整条高度链塌方：

```
.ui-test-editor-document  height:100%   → 失效（父无确定高度）
.ui-test-editor-scroll    flex:1; overflow-y:auto → 随内容长高，永不溢出
```

滚动区既然从不溢出，就既没有滚动条、滚轮也无事可做；外层容器的 `overflow:hidden`
再把超出部分裁掉——所以表现是彻底滚不动。

### 修法与防线

把工作区容器改名为 `.ui-test-editor-slot`（此前未被占用），并在三处留注释说明**为什么不能叫那个名字**。

同一撞车还顺带修掉两个不那么明显的副作用：工作区容器此前白拿了编辑器的字体/字距规则，
以及大纲视图下 `.ui-test-editor[data-kind="outline"] .ui-test-editor-body { padding-top: 24px }`
带来的重复上边距。

回归测试从三个角度锁死（均已用 `git show HEAD:` 取修复前的文件验证「修复前必然失败」）：

1. **结构**：正文栏的直接子容器不得带 `ui-test-editor-body` 类；
2. **归属**：`ui-test.css` 不得定义 `.ui-test-editor-body`（那是编辑器样式表的所有物）；
3. **钉住肇事规则**：断言 `.ui-test-editor-body > div { height:auto; overflow:visible }`
   仍在编辑器样式表里、`PreviewPanel` 根仍是 `h-full`——这样将来若有人再冒用这个名字，
   测试失败信息会直接指向原因，而不是只报一句「结构不对」。

> 通用教训：**跨文件复用类名等于隐式耦合**。凡是「A 文件的样式只作用于自己的元素」这种
> 假设，都应该由测试钉住，而不能靠命名自觉。

## 2. 共创失败：提示词自相矛盾 + 闸门无恢复路径

### 报错链条

模型返回了完整卷纲 + 「写回清单」，**一个 `outline_discuss` 标记都没有** →
`parseOutlineDiscussProtocol` 返回 `kind: "none"` →
`outlineDiscussError = "共创协议格式无效，尚未开始生成：模型未返回 outline_discuss 协议块"`，
整轮作废。

### 根因：不是模型不听话，是提示词在自相矛盾

把 `buildOutlineAgentSystemPrompt({ mode: "discuss", discussModule: "卷纲" })` 实际拼出的
提示词 dump 出来逐行核对，发现它在要求「禁止输出完整大纲正文、必须输出 outline_discuss」
的**同时**，还带着整套生成契约：

| 泄漏的规则 | 说明 |
|---|---|
| `## AI大纲生成工作流`整段 | 其中「**生成章纲后必须列出新增设定写回清单**」正是截图里模型输出的那个「写回清单」 |
| 「生成章纲时必须使用章纲标准结构…」 | 章纲正文契约 |
| 「结构节点必须包含 CBN、CPNs、CEN…」 | 同上 |
| 「需要保存大纲时只输出 outlineSaveRequest…」 | 开头无条件出现，诱导直接交付正文 |
| 「当本轮要交付可保存的大纲正文时：最终回复只输出大纲标题和大纲正文」 | 输出边界里的生成分支 |

其中一条是**明确的改动事故**：排除数组只把 `## Markdown 格式强制要求` 这个**标题**
放了进去，正文却留在数组外面 —— 于是讨论轮提示词里仍然出现
「所有大纲正文必须使用标准 Markdown 格式输出」和整段 `# / ## / ###` 大纲范例。
**一边禁止输出正文，一边给出正文格式规范与范例。**

两套契约同时出现时，模型挑了量更大、更靠前、更具体的生成那套照做。

### 修法一：拆开共用规则，按轮次裁剪

- `sharedAnalysisRules` 拆成：
  - `sharedReadRules`（只读与分析纪律：先 `list_outlines` 再 `read_outline`…）—— **所有模式保留**；
  - `sharedGenerationWorkflowRules`（生成工作流）—— **仅生成/计划/标准模式带上**。
- 讨论轮排除：生成工作流整段、章纲结构硬要求、保存请求提示、
  Markdown 强制要求**整段（标题+正文）**、输出边界里的「交付正文」分支。
- 讨论轮**必须保留**（防止删过头）：`outline_discuss` 协议要求、本轮阶段说明、先读资料的纪律。

### 修法二：缺协议时自动「补协议」，不再把整轮判死

即使提示词修好，模型仍可能偶发只给正文。此时整轮讨论等于白跑，而模型给出的判断往往
有价值 —— 上一版直接把一份完整卷纲判为「格式无效」丢弃。

新增 `src/lib/novel/outline-discuss-repair.ts`，在**首轮**与**重新生成**两条路径上都先修复一次：

- 只让模型**转写**已有判断与分歧，提示词明确禁止「重写、扩写或继续生成大纲正文」；
- 要求**保留原正文再追加协议块**，保证用户看到的内容不会因修复而变少；
- 走 `temperature: 0` + 独立 token 上限（1600）——这是格式转写，不是创作；
- 失败只 `console.warn` 并回落到原有报错路径，**不把失败伪装成空修复**；
- 空回复或一句客套不触发（`hasOutlineDiscussRepairableContent`：长度 < 80 或已含协议块则不修）。

> 这里刻意**不**把模型产出的大纲正文写进任何落盘产物：它仍只是聊天内容，
> 是否采纳由用户在后续正常生成轮决定，不绕过「用户确认后才落盘」的既有约定。

## 4. 追加修复：共创轮「直接交付大纲」被当成协议缺失丢弃

> 本节记录 `14a2c56` 之后**同一症状的第二层根因**。用户为此追了两轮，
> 第一轮我修错了地方（见下「错路」），这里把真实根因与边界写清楚。

### 用户报的现象

共创（大纲共创）里模型明明产出了一份完整卷纲，界面上却是：

1. 一大坨 `volumeOutlineData` 结构化 JSON 源码（`scope/position/structure/theme/coreConflict/…`）
   直接显示给用户；
2. 或先报一句「共创协议格式无效，尚未开始生成：模型未返回 outline_discuss 协议块」，
   紧接着又是「修真界卷级架构」「总体定位」这样的正式标题。

关键点：**模型已经生成了内容，是软件没把它产出来。** 用户原话——
「只是将这些类似于源码的内容截断了，并没有完整产出内容」。

### 真实根因：一条写死的假设 + 一次判死

`14a2c56` 给讨论轮划的边界是「讨论轮只产出协议块，不会有可保存正文」，
这条**假设**被写死在两个地方：

| 位置 | 写法 | 后果 |
|---|---|---|
| `outline-chat-panel.tsx` 保存链路闸门 | `&& !discussPhase` | 讨论轮**永远不进** `handleAutoSaveOutlineRequests` |
| 同文件协议判定 | 讨论轮没有 `outline_discuss` → `discussProtocolError` | 整轮被判「未返回协议块」 |

于是模型直接交付完整卷纲时：

1. 结构化数据 `volumeOutlineData` **不被提取** → 折叠树不渲染；
2. 保存确认卡片 **不弹**（闸门跳过）→ 用户没有落盘入口；
3. 同一份内容又**没走正常正文显示路径**（讨论气泡只做协议剥离）；
4. 结果：既没产出、又原样露出 —— 就是截图里的那坨 JSON 源码。

`14a2c56` 的「补协议」修复（`hasOutlineDiscussRepairableContent`）救不了这种轮次：
它处理的是「有正文但缺协议」，不处理「正文本身就是交付物」。

### 错路（记下来，别再走）

第一轮的修法是：讨论气泡改用 `prepareOutlineSaveSourceContent` 去掉 ` ```json ` 围栏。
这条**从显示层下手、只删不产出**，把模型真正的交付物从界面上**藏掉了**，
用户看到的更少而不是更多 —— 方向完全反了（用户当即指出并否决）。

教训：**症状出现在显示层，不等于缺陷在显示层。**
JSON 出现在气泡里是「没被消费」的*表现*，不是「该被隐藏」的*原因*。

### 正确修法（`fa87d26`）

把「讨论轮一定没有交付物」这条**假设改成判定**：

```ts
function isDiscussDeliveredOutline(content: string): boolean {
  if (!content.trim()) return false;
  if (parseOutlineSaveRequests(content).requests.length > 0) return true; // 带保存请求
  if (extractVolumeOutlineData(content)) return true;                     // 卷纲结构化数据
  return isSaveableOutlineDeliverable(content);                           // 正文本身可保存
}
```

- 命中 → 这一轮**按生成轮处理**：不要求 `outline_discuss`、正文走正常显示路径、
  结构化数据进保存链路（提取折叠树 + 弹保存确认）；
- 未命中 → 维持 `14a2c56` 的行为，继续要求/补协议；
- 首轮与重新生成两条路径**同改**；
- 阶段机同步改用 `discussProtocolRequired`，避免「已交付」轮还去推进讨论阶段。

### 边界没有被放宽

`14a2c56` 那条不变量仍然成立：**不绕过「用户确认后才落盘」**。
命中后走的是 `presentOrQueueSaveBatch(...)` —— 只是把本就该弹的**保存确认卡片**弹出来，
由用户决定是否写入，没有静默落盘。第 2 节末尾那段「刻意不写进落盘产物」
说的是**补协议这一步**不写盘；本轮是把它的**适用范围**说清楚，而不是推翻它。

### 验证

| 项 | 结果 |
|---|---|
| 新增回归（2 例） | 修复前**必红**，且复现的正是用户所见的报错原文「…模型未返回 outline_discuss 协议块」 |
| `outline-chat-panel.spec.tsx` | 114 通过 |
| `npm run test:mocks` | **717 文件 / 6917 通过**，6 todo，exit 0 |
| `npm run typecheck` | exit 0 |
| 便携版重建 | `4907006e…`，213,587,456 字节；装配逐文件一致（fonts 21/21、skills 605/605） |
| 真机验收 | 分层 100%/0%、设置保存、浮层、用户状态复原 —— 全部通过 |

新增用例在 `src/components/sources/outline-chat-panel.spec.tsx`：
「共创轮直接交付卷纲时不再判「未返回 outline_discuss」作废」（断言不再报协议错 + 正文可见）、
「共创轮直接交付可保存大纲时进入保存确认链路（内容未丢）」（断言**弹出保存确认**，
即交付物真被产出）。

### 顺带修掉的一个门禁缺陷

`.codex-temp/verify-exe-embeds-dist.mjs` 的「反向对照」原本拿
`release-portable/QMaiWrite.exe` 当旧参照 —— 那正是**本次交付的产物本身**；
每重打一次便携版它就和本次构建同源，「旧 exe 里不该有当前入口名」必然**假红**。

已改为冻结的历史 exe（`.codex-temp/frozen-control/`，含出处与被覆盖风险说明），
并加两层守卫：**自指守卫**（参照物与本次 exe 字节相同即判失败，让这个坑不可能静默复发）
与**合成负对照**（编造的入口名必须搜不到，证明匹配器不是橡皮图章）。
变异验证：把参照物换回本次产物后，自指守卫确实变红。

## 5. 追加修复：卷纲内容被静默丢弃 + 校验问题显示位置（`81b9afe`）

`fa87d26` 之后用户再次截图报告：

> 大纲保存失败 / 卷纲内容仍不完整（138 项）：第 1 个故事缺少字段 beats。；
> 第 1 个故事缺少环节「起①」。…可保存当前内容，或让 AI 重新生成。

> 共创内容还是显示这种情况，还是要继续去修复。比如出现这种问题，是不是在生成的结果下面，
> 显示出当前出现的问题

第二句是这次的关键要求：**校验问题要显示在生成结果下面**，而不是弹一个和内容脱节的浮层。
按这个要求逐条查证，确认有四个真实缺陷。

### 5.1 解析器只认自己的键名，把模型写的内容整批丢掉（主因）

从真实存档取证（`D:/QM-BOOK/楚白/.qmai/outline-chats.json`，会话 `f52b330e`），
模型把 10 个环节写成：

```json
{ "k": "起①", "name": "沐浴昏死", "p": [3], "pay": "…", "reversal": "认知反转" }
```

而旧 `normalizeVolumeOutlineData` 只读 `stage`。于是整批环节被 `asString` 静默丢成空串，
校验器随后报「第 N 个故事缺少环节 起①…合②」——**10 故事 × (10 环节 + 1 条「环节不足 10 个」)
= 110 项假警报**，折叠树里环节标题全空。

**不是模型没写，是解析器没认。**

量化（真实载荷 + 真实校验器）：

| | 校验问题数 |
|---|---|
| 修复前 | **189 项** |
| 修复后 | **89 项**（消掉 110 项假警报） |

同一处还有三个同类丢弃，一并修掉：

| 丢在哪 | 模型实际写法 | 旧行为 | 现行为 |
|---|---|---|---|
| 环节标识 | `k` / `key` / `id` | 只认 `stage`，其余丢 | 依次容忍 `stage/k/stageId/key/phase/id` |
| 环节小标题 | `name` | 完全没读 | 收进 `VolumeOutlineStage.label`，渲染成「常态与破口 · 沐浴昏死」 |
| 12 章节拍 | `beats` 写成数组 `["平","升",…]` | `asString` 只认字符串，丢成空串 | 数组按序无损拼回字符串 |
| 反转类型 | 只写在承③/转① 环节的 `reversal` 上 | story 级 `mid/twist` 为空 → 树里「承③ · 」空标签、「反转类型分布」显示「未填」、覆盖数少算 | 仅在该值为空时**无损回填**（story 级优先；真缺则保持为空，不编造） |

实测还原结果：环节 10×10 全还原、小标题 10/10、`mid/twist` 回填成功、
反转类型覆盖恢复 5 种（认知/身份/情感/立场/力量）。

### 5.2 自动补全的提示词与校验器各说各话，补了也永远过不了

卷纲自动补全的提示词原先**手写**了一份精简清单，只要
`pay / p / link / position / roles / …`，却漏掉
`stage / who / use / range / deliver / gift / hook / climax / beats / line` ——
而紧接着的 `validateVolumeOutlineData` 恰恰要求这些。

于是「自动补全」被要求产出的东西**不可能通过校验**：
补一轮 → 仍报同样的「卷纲内容仍不完整（N 项）」，用户看到的就是「补了也没用」。

改为直接复用 `getOutlineSectionOutputRules("卷纲")`：**提示词与校验器从此共用一个契约定义**，
以后加字段不会再漏改一边。提示词构造抽成 `buildVolumeOutlineRepairPrompt` 以便测试钉住。

契约文本同时补上两处实测歧义（**只澄清、不放松校验**）：

- `range` 必须写**章号范围**（如「第 1–12 章」），不是卷名 —— 模型因此写成了 `volume: "卷一"`。
  `range` 真缺时仍如实报告缺失，**不拿卷名充当范围**（那是把分类信息当范围信息，属于污染）。
- 环节标识就用 `stage` 键；`name` 明确为可选的小标题。

### 5.3 校验问题改在生成结果下方显示

#### 一次我自己的流程错误（记下来防复发）
