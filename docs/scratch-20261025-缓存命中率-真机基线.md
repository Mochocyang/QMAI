数据来源：`C:\QM-BOOK\黑雨之下\.qmai\**` 真实落盘记录
规模：**90 条带 provider usage 的请求，累计 input 9,965,694 token**
口径：`cached / input`，两个数都直接取自 provider 返回的 usage，不是本地估算

## 2. 三条根因（按证据强度排序）

### 根因一：前缀稳定时命中极高，一变就归零

grok-4.7 的连续 4 条（`fp=65a521` 不变）：

| 序号 | input | cached | 命中 |
|---|---:|---:|---:|
| 1 | 91,953 | 1,152 | 1.3% |
| 2 | 94,420 | 91,904 | **97.3%** |
| 3 | 106,800 | 94,336 | 88.3% |
| 4 | 112,775 | 106,752 | **94.7%** |

紧接着前缀一变，立刻掉回去：`1.2% / 1.3% / 0.2% / 0.2%`。

**这说明模型和网关的缓存能力完全没问题——瓶颈 100% 在"我们每轮都在改前缀"。**

### 根因二：DeepSeek 上前缀几乎每条都在变

`deepseek-v4.1-flash` 的 14 条，前缀指纹有 11 个不同值：

```
13:50:00  3a38d9b5   84,033   0.0%
13:50:07  d233cd88   84,033   0.0%   ← est 没变，指纹变了
13:50:15  d233cd88=  84,033   0.0%   ← 指纹相同，仍然 0
13:51:44  a89dd100   87,199   0.0%
13:51:50  19f2d61d   87,199   0.0%
13:52:25  19f2d61d=  87,199  91.2%   ← 指纹相同，这次命中
13:52:42  b006ea14   98,168   0.0%
...
15:03:26  242076b8= 121,871   0.1%
```

注意 `84,033` 出现 3 次、指纹却有 2 个不同值：**上下文总量没变，但内容被替换过**。
这正是 P0 修掉的那两个毛病——「本轮资料注入当前 user 消息」和「任务契约写本轮输入」：
它们替换而不是追加，量不变、字节变、缓存全废。

### 根因三：缓存写入有延迟，短间隔重试吃不到

`13:50:07 → 13:50:15` 相隔 8 秒，前缀指纹完全相同，命中仍是 **0%**；
等到 `13:51:50 → 13:52:25`（相隔 35 秒）才吃到 91.2%。

**排查时这个坑会让人误判成"前缀没修好"，实际是 provider 还没把缓存落盘。**

## 3. 一个必须说明的口径问题：指纹会误报

`prefixFingerprint` 的 canonical 里含 `provider / model / apiMode / tools / toolChoice / reasoning`，
**不只是文本**。所以工具集或推理档位一变，指纹就变，而实际文本前缀可能一个字没动。

实测证据：grok 有一条**新指纹却命中 94.9%**。

所以「指纹重复率」只能看趋势，**不能当验收指标**。验收看两个数：
- **命中率**（`cached / input`）
- **零命中占比**（多少比例的请求一个字节都没吃到）

## 4. 这轮改造对应到哪条根因

| 根因 | 对应改造 | 状态 |

| 前缀每轮被替换（资料/契约进当前 user） | P0 资料前移 + 契约改用会话首条目标 | 已落地，真机 72.8% → 99.6% |
| 审稿自建前缀、与写作异构 | P1 审稿复用写作前缀 | 已落地，0% → 99.3% |

| 稳定块里「核心设定」夹在中间 | P4 稳定块重排 | 已落地 |

| 章节链路无 system、规则每阶段重发 | P6 `CHAPTER_SYSTEM_PROMPT` | 已落地，99.6% |

**但以上都是"请求构造层"的验证。** 这份基线说明的是另外一件事：

## 6. 局限（不能装作没有）

1. **样本小且有偏**：90 条请求，绝大多数来自同一个大纲会话（`c31b44`），不是随机采样。
2. **不含章节深度生成链路**：数据全部来自 `outline-chats`（大纲对话），
   章节产线的真实命中率还没有生产数据。
3. **多模型混在一起**：31.4% 是加权平均，被 gemini 的 458 万 token 主导；
   看你实际用的模型应看 5.7%。
4. **改造后尚未采样**：本文所有数字都是改造前基线，不能当作改造效果。
