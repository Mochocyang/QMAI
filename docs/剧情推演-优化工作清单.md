### P1-8 分支并发运行

- [!] **前提不成立，已驳回** —— 没有「跑 3 条分支」这件事，也就没有 3× 成本可降

> 逐行核对结果：
> - 全库生产代码里 `runSimulation(` **只有一个调用点**：`story-simulation-view.tsx:860`（`runSimulation(` 的其余命中都在 spec 里）。
> - `branch-manager-panel.tsx:142/181` 的文案本身就是「为当前推演状态命名，点击『创建分支』**保存快照**」；`saveCurrentAsBranch`（`story-simulation-store.ts:342`）只做快照：把 `currentAgents` / `timelineEvents` / `rumors` / `directorEvaluations` 拷进 `SimulationBranch`，**不触发任何推演**。
> - 因此分支是「同一次推演的若干存档」，不是「各自跑一次的平行世界」。清单里「分支之间语义独立（各自黑板与事件线）」描述的**数据**是对的，但不存在任何代码去分别运行它们。
>
> 结论：这条要优化的是**一个尚未存在的功能**。真要实现「每条分支各自跑一遍并对比」，那是**新增功能**（并在那时才需要考虑并发），不是「优化现有开销」。在没有该功能的当下实现并发调度，属于给假想路径写代码。若要推这条，建议先明确：谁触发分支推演、分支从哪个状态分叉、并发 3 条时 LLM 限流如何表现。
>
> 保留其唯一有效结论（已写在文末「已更正/撤回的结论」）：**同轮角色循环不可并发**，因为它有真实读写依赖；这一条与本次驳回互不影响 —— 该结论说的是「同轮不能并发」，而不是「分支需要并发」。

> **为什么必须是 LLM 生成而不是确定性映射**（这条是本项最关键的判断）：`keyEvents: string[]` 只给了「发生什么」。把 what 直接映射过去，剩下 `cause` / `action` / `result` / `use` 四个字段就只能靠字符串拼接硬凑 —— 产出的是四个空壳字段冒充因果链。那正是本分支在消灭的那类「看起来有、实际是编的」数据。所以走 LLM，并用 `validateEventPlan` 严格校验，不合格就报错。
>
> **≥6 条复用章纲的 `MIN_EVENT_COUNT`**（已从 `chapter-outline-template.ts` 导出）：两处各写一个 6 会漂移，出现「推演导出的计划过了这边的校验、章纲那边判不合格」。
>
> **三个刻意的取舍**：
> - **生成不达标时不落盘**。宁可让用户看到「计划不达标，请重试」，也不要存一份支离破碎的计划让他当成可用产物。
> - **同名文件不覆盖，加时间戳另存**。用户可能已经在这份计划上改过字，静默覆盖会直接吃掉他的修改。
> - **落点节点命中与否要区分**（`resolvePlanTargetNode` 返回 `matchedByTitle`）。分支名通常就是它推进到的那一步，所以优先按标题匹配；没匹配上退回第一个节点以保证能用，但界面必须说明「已按 X 这一章生成」—— 不能悄悄挑一个让用户以为就是对的那章。
>
> **`type: chapter-event-plan`，刻意不用 `chapter-outline`**：后者是 17 节完整章纲，用同一个 type 会被章纲校验当成残缺章纲逐项报错。
>
> **接线归父组件**：报告页保持纯展示（只接收 `onExportEventPlan` 回调），LLM 配置与落盘由 `story-simulation-view` 负责 —— 那里已有另外 8 处同类的 `resolveDefaultModel` 调用点。若在报告页内直接调用，会把模型解析链（连带 i18n）拉进一个原本纯展示的组件。
>
> **测试过程中发现并修掉一个真实缺陷**：`disabled={exportingBranchTitle !== null}` 在父组件未传该 prop 时是 `undefined !== null` → 恒为真，按钮被**永久禁用**。已改为宽松比较 `!= null`。这正是「必须有行为测试」的例子 —— 只看界面文案有按钮会以为接通了。

## P2 —— 体验收尾

- [x] 推演过程常驻状态条（当前节点/轮次/已发生事件数/已花费调用数）；数据已在 `onDebugTrace` 中

> **实现**：新增纯函数 `run-status.ts` 的 `summarizeRunStatus({ debugTraces, framework, events })`，在推演面板的进度条下方常驻显示「节点标题（N/M）· 第 R 轮 · N 事件 · N 次决策」。做成纯函数是为了能直接断言，不必渲染内联在 2900 行 view 里的面板。
>
> **取舍**：
> - **没有任何轨迹时整条不显示**，而不是显示「节点 1 第 1 轮」—— 那还没发生，是编的。
> - **只数 `round-plan` 轨迹**统计决策次数；`event-recorded` 记的是同一轮的另一件事，两边都数会把每轮算成两倍。
> - **缺框架信息时仍显示轮次与计数**，只是不显示「N/M」总分母 —— 不因为缺一项就整条不显示。
> - **节点标题优先取框架里的**（权威），轨迹自带的仅作兜底：只跑过部分节点、或框架被重新生成过时，轨迹里的标题可能已过时。
>
> **「已花费调用数」按角色决策次数呈现**，理由与 P2-3 相同：真实 LLM 调用没有被逐次记录，硬造一个会是编的数字。
- [x] 保留「自由沙盘」（不绑定章节的探索路径）

> **核实结论：这条路径今天已经存在，不需要新写功能。**「舞台情景」就是它 —— 角色从章节里提取，但它自己不绑定任何一章：`ScenarioSetup` 只有 `{ rules, format, rounds, participants }`，全库的 `scenario-*.ts*` 里没有任何 `currentFramework` / `frameworkId` 引用；落地页进它也只是切一个 phase，不需要先选中章节或框架（「没有位置」正是这个意思）。
>
> **那为什么还要动它：**另一份设计稿《功能边界整理-入口收敛方案》正在规划把入口改成**位置驱动**（从卷纲/章纲/正文选中位置直接推演），并明确写着「保留一个『自由沙盘』给确实没有位置的脑暴」。也就是说这条路径在未来会被一次入口重构正面撞上，而**把它删掉不会报任何编译错误** —— 正如本分支起点的导演 Agent 开关，坏了也没有任何测试会红。
>
> **所以加的是护栏而不是功能**（`story-simulation-hub.spec.ts` 新增 4 条）：进入推演室不需要章节/位置上下文、舞台情景不消费框架绑定、`ScenarioSetup` 里没有章节/节点字段、落地页两条入口都在。已反向验证：给 `ScenarioSetup` 注入 `chapterBinding` / `frameworkId` 会让其中 2 条立刻变红，改回即绿 —— 确认它们不是空断言。
>
> **一个容易被误读的细节**：舞台情景确实会读 `sourceChapters`（读几章来**提取角色**），但那是输入来源，不是章节绑定 —— 它不会因此被绑定到某一章，产物也是独立的对白而非某章的正文。区分「读了几章素材」与「属于哪一章」是这条护栏的关键。
- [x] 历史结果列表做成一等公民：显示分支数、总调用数、导演均分（接通后）、是否已生成草稿

> **实现**：新增纯函数模块 `result-summary.ts`（`averageDirectorScore` / `countAgentDecisions` / `summarizeSimulationResult`），历史列表渲染「N 角色 · N 走向 · N 次决策 · 导演 X.X」。做成纯函数是为了能直接断言，不必渲染 2897 行的 view 或走真实磁盘读取。
>
> **两个刻意的取舍**：
> - **没有导演数据时显示 null，而不是复用分支评分的兜底值 3.0**。3.0 用于算总分是合理的，但摆进列表会被读成「这次推演导演打了 3.0 分」，而事实是导演根本没启用 —— 正是本分支在修的那类「假数据」。
> - **旧存档没有 `debugTraces` 时不显示决策次数**，而不是显示「0 次决策」。0 会被读成「一次都没跑」，而事实是「没记录」。
>
> **连带改动**：导演均分原先只在内存分支里，列表读的是磁盘报告，不落盘就永远看不到。故 `SimulationReport` 增加可选 `directorAverageScore` / `directorEvaluationCount`，在 view 保存结果前从 `directorEvaluations` 算出并附上。
>
> **未做**：清单里的「总调用数」按**角色决策次数**（`round-plan` 轨迹的 `selectedAgents` 之和）呈现。真实 LLM 调用数并未被逐次记录，且 P1-9 之后每次决策的调用数还会因是否升级 ReAct 而不同，硬造一个「总调用数」会是编的数字。显示可验证的决策次数更诚实。
