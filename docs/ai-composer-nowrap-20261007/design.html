AI 输入框底栏：收窄时压缩模型框，而不是变成上下两排

用户原话：「当用户调整 AI 对话框的宽度与大小时，若进行收窄，应该将模型框进行收窄， 而不应该出现上下的结构。」

1. 根因

不是遗漏，是上一轮有意为之的设计。原 CSS 里写着：

位置原值导致的后果
底栏容器flex-wrap: wrap 放不下就换行 —— 这正是用户看到的上下结构
右组（思考深度+模型+发送） flex: 1 0 auto
min-width: min(100%, max-content)		 换行的直接根因。flex-shrink: 0 且最小宽度不小于自身内容宽： 空间不够时它不可能被压缩，flex 只能把它整组挪到下一排
模型那个 .relativeflex: 0 0 auto 模型框完全不参与收缩

原注释写的是「一行放不下时，思考深度、模型和发送整组落到第二排，避免末尾被裁切」—— 作者是在解决「发送按钮被裁」的问题，选择了换行。用户判定这个取舍错了： 宁可截断模型名，也不要摆成两排。

2. 设计

三处改动，核心是把「让位」的责任交给可截断的那一项：

改动作用
底栏 flex-wrap: nowrap结构上不可能再出现两排
右组 flex: 0 1000 auto（原 1 0 auto）、去掉 min-width: min(100%, max-content) 可以收缩了；大 shrink 权重让它在底栏这一层优先于左组让位
模型 .relative 变 flex 容器、按钮 flex: 1 1 auto; min-width: 44px、 span min-width: 0; text-overflow: ellipsis 模型名真的被省略号截断，且留 44px 可用下限

3. 两个非显然的坑

坑一：收缩权重必须"每一层"都给。第一版只在模型那层给了大 shrink， 底栏这一层左右组权重相当，于是实测左组被压掉一半（156px → 78.8px）， 「计划」按钮被裁掉 —— 让位的变成了一个功能按钮，而用户要裁的是模型名。 flex 的收缩量是在每一层各自按 flex-shrink × flex-basis 分配的， 所以底栏那一层也要把权重偏向右侧。这条是截图看出来的，不是断言报出来的 （见下一节：几何断言当时是"全绿"的）。

坑二：有 overflow:hidden 的容器里，"几何位置在底栏内"测不出"被裁"。 被裁掉的按钮 rect 仍然是它在布局里该在的位置，越界的是父容器的裁剪。 第一版断言只查了"是否落在底栏矩形内"，于是「计划」被裁时它照样通过。 判据改成「控件必须完整落在左组自己的矩形内」才抓得到。

4. 验证

jsdom 不做布局、不算 flex，「同一行」与「被截断」在 jsdom 里无法观测， 所以主体是真实浏览器几何脚本 docs/ai-composer-nowrap-20261007/check-composer.mjs（23 项全过）。

真实可达宽度：章节 AI 面板的拖拽下限是 UI_TEST_AI_MIN_WIDTH = 400 （src/lib/ui-test-layout.ts），大纲面板下限 320。所以 400 是必须过的硬线。

宽度底栏高同一行左组宽模型宽模型名截断
320（大纲下限）54px是155.944是
400（章节下限）54px是155.950.1是（可见 37px）
446（用户截图宽度）54px是15696是
520 及以上54px是156136.4（完整）否

修复前同一组测量：300–446px 全部 94px 两排，模型宽恒为 136.4、 从不截断；520px 起才是 54px 单排。也就是说用户截图里的宽度正落在缺陷区间内。

  • 单排高度基准取自最宽时的实测值（54px），阈值写成 < 54 × 1.4， 不写死魔数；两排是 94px，会被抓到。
  • 3 条负向对照，每条都复算与正式断言完全相同的判据： 恢复 flex-wrap:wrap → 重新变两排（94px）； 模型不可收窄 → 模型名不再截断； 整条底栏都不可收缩 → 出现 72px 水平溢出。
  • 模型宽度的单调性单独断言：44 → 50.1 → 96 → 136.4 随容器变宽而增， 证明是"跟着收窄"而不是某个固定值。

负向对照的第一版又是错的（本任务连续第三次踩同一个坑）： 我用「发送按钮被挤出底栏」来证明"模型框不可收窄"，但 nowrap 下发送按钮是 flex-shrink: 0，模型再宽也挤不掉它 —— 这条对照恒真，永远"抓不到"。 改成用「模型名是否被截断」判定才成立。教训一致： 负向对照必须复算与断言完全相同的判据，否则有效断言会看起来像空话。
