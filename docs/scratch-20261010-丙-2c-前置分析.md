## 1. 大纲面板的事件细纲链路**只有一个**触发点

逐行核对 `src/components/sources/outline-chat-panel.tsx`：

| 位置 | 内容 | 谁触发它 |
|---|---|---|
| `:78` | `import { EventOutlineWizardDialog } from "@/components/sources/event-outline-wizard-dialog";` | — |
| `:2221` | `const [eventOutlineWizardOpen, setEventOutlineWizardOpen] = useState(false)` | — |
| `:5542` | `handleSubmitEventOutlineWizard` | 仅被 `:6917` 的 dialog `onSubmit` 使用 |
| `:6635` | `<UiTestAiEmpty kind="outline" … onGenerateEventOutline={() => setEventOutlineWizardOpen(true)} …>` | **全文件唯一**调用 `setEventOutlineWizardOpen(true)` 的地方 |
| `:6914-6920` | `<EventOutlineWizardDialog … onSubmit={handleSubmitEventOutlineWizard} …>` | 仅由上面的 state 控制 |
| `:6705-6712` | `EventOutlineCard` 挂在助手气泡下方 | 见下 |

### 决定性事实
`EventOutlineCard`（`:6709`）拿到的 prop 是**只有两个**：

```tsx
<EventOutlineCard
  data={eventOutline}
  onWriteChapter={(prompt) => { … }}
/>
```

**没有**任何回调会去调用 `setEventOutlineWizardOpen(true)`。
（已 grep 确认：`setEventOutlineWizardOpen` 在 `outline-chat-panel.tsx` 里只出现在
`:2221` 的声明、`:6635` 的调用、`:6916` 的 `onOpenChange`。）

⇒ 删掉 `:6635` 的 `onGenerateEventOutline` 之后，下面四项**全部不可达**：
`EventOutlineWizardDialog` 的渲染（`:6914-6920`）、`eventOutlineWizardOpen` state（`:2221`）、
`handleSubmitEventOutlineWizard`（`:5542`）、以及 `:78` 的 import。

## 2. 必须显式二选一（不要让它成为偶然）

### (A) 推荐 —— 连带删掉这条死链
删：`import`、`state`、dialog 渲染、`handleSubmitEventOutlineWizard`。

**必须保留**：
1. **`EventOutlineCard` 的渲染**（`:6705-6712`）。
   它服务的是**已持久化的旧会话** —— `.qmai/outline-chats.json` 里已有的助手消息
   仍要能正常显示卡片。删掉会让老用户的会话凭空变样。
   ⚠️ 也就是说：**「不能从大纲面板新建事件细纲」≠「大纲面板不再渲染事件细纲卡片」**。
   这两件事必须分开，别一起删。
2. **共享库** `src/lib/novel/event-outline.ts` 与
   `src/lib/novel/event-outline-generation.ts` —— 章节区那条新链路正在用
   （`preview-panel.tsx` 的 `handleSubmitEventOutline` → `generateEventOutline`）。

**连带后果（必须一并处理）**：
`handleSubmitEventOutlineWizard` 身上挂着 丙-1/丙-2a **已验证**的
**requirement 确定性通道**（`e324d46` 的 FIX 4）：

```
向导里填的要求 → 可见用户消息（生成第 N 章事件细纲）→ outline-chat-store 持久化
              → extractEventOutlineData(msg, requirement) → event-outline.ts 的 withRequirement
```

以及 `outline-chat-panel.spec.tsx` 里为它写的那批用例（含
「向导里填的要求不靠模型回抄」等）。

⚠️ **特别注意一处陷阱**：实现者主动申报的第三项未完成
（`outline-chat-store.spec.ts` 的 `eventOutlineRequirement` 往返用例）
**正是为这条链写的**。选 (A) 时请**先确认章节区那条链是否也需要该字段的持久化往返**
—— 它**需要**，因为 丙-2b 要读 `task.request.requirement`。
⇒ 该用例应**保留**，继续钉住 store 的往返，只是产生者从大纲面板换成章节区。
**不要**因为「产生者没了」就顺手删掉 store 的校验 —— 那是 丙-2b 的输入。

### (B) 只删入口、保留死链
四位独立审查者会一致指出「保留不可达代码」。
若选这条，报告里必须写明理由，并**明确承认**它是死代码。

## 3. 有一条守卫测试**专为此写**，它会红 —— 要「反转」不要「绕过」

`src/components/layout/preview-panel.chapter-toolbar.spec.tsx:205-215`（丙-2a 加的）：

```ts
/*
 * 入口是**新增**，不是搬家 —— 本批之后大纲面板的空白态入口必须原样还在。
 * 删掉它是后续单独一步（要人确认章节区那条链路真的可用），
 * 这条守卫就是防止"顺手删掉"在没有验证的情况下发生。
 */
it("大纲面板的空白态入口在本批中保持不动", () => {
  const panel = readFileSync(resolve(__dirname, "../sources/outline-chat-panel.tsx"), "utf8")
  expect(panel).toContain("onGenerateEventOutline")
  expect(panel).toContain("setEventOutlineWizardOpen(true)")
  expect(panel).toContain("EventOutlineWizardDialog")
})
```

**丙-2c 就是这条注释所说的「后续单独一步」。**
它存在的意义就是让 丙-2c 成为一次**有意识**的动作，而不是「顺手删掉」。

**要求**：
- 按 (A) 实施后，这三条断言**全部**变红 —— 这是**预期行为，不是回归**。
- **反转**这条用例为「大纲面板已不再提供事件细纲入口」，
  并把注释改写为「前置条件（章节区链路已可用且已验证）已满足，故按约定删除」，
  写明这是有意识的删除。
- ⚠️ **不要**为了让测试变绿而保留一个空的 `EventOutlineWizardDialog` 引用
  —— 那是骗测试，比死代码更糟。
- 若选 (B)，则只需把首行断言改成 `not.toContain("onGenerateEventOutline")`、
  保留后两行；但那就等于承认死代码，须满足 §2(B) 的要求。

**⚠️ 另外两条同类断言也要一并核对**（它们断言的是「入口存在」，方向相反）：
- `preview-panel.chapter-toolbar.spec.tsx:212`：`expect(panel).toContain("onGenerateEventOutline")`
  —— 同上，属这条守卫。
- `preview-panel.chapter-toolbar.spec.tsx:186-203`：「生成章节细纲用灯泡图标」
  —— 断言的是**章节区**那枚按钮，丙-2c **不该**动它，应保持绿。
  别把两者搞混（一个在大纲面板、一个在章节工具栏）。
