同一世界，放在一起才经得起检查

以下是这次示例里可以直接核对的几个连接点。

连接问题去哪里看已落实的具体内容
这120个人住哪里、钱从哪来？组织势力第3、5、6区64人会舍、41人外租、15人常驻船；月收入5,400，支出4,100，结余分项。
地图上两点之间多久能到？地理第8区距离、速度、有效航行时间、税闸、补给和绕行代价分开。
罗盘为什么不能直接破案？金手指第3、7、9区只读最近转向，不含时间人物；来源核验与解释必须由角色完成。
第三章到底留下了什么？章节第13、14、16区一次额度、迟滞、红泥、铜铃原地、顾微起疑以及必须接住的盘问。
秘密是计划还是已经写过？伏笔第1、3、6区以第三章开场为设计基准，实际回收日志仍空，不把计划写成事实。
04

这轮请重点看这三件事

仍然由你的实际打开体验决定，不预先宣布已经满意。

信息密度

设定是否能回答你写正文时会问的问题？有没有只看起来详细、实际仍绕开机制的段落？

阅读秩序

目录、分区、图和表是否让你更快找到信息？是否仍有让你觉得拥挤、平淡或不协调的部分？

只改示例

具体到页面反馈

例如：“地理地图不错，但下面表格还太多”“人物想要更多经历和家庭细节”“组织喜欢收支结构，不喜欢标题风格”。可以只反馈一个最不满意的页面，我们再精准改它。

当前交付边界

本轮只生成第二版示例，不修改 src、软件技能模板、构建配置或安装包。全部情节与数字为虚构设计；地图是示意图，不是测绘成果。没有可用浏览器工具时，仅报告静态结构与图形检查，不把它说成完成了整页浏览器视觉验收。

本轮制作与验收计划
一、保留第一版并记录源码指纹。二、补完八类设定、卷纲100环节与章节17分区。三、建立常驻目录、互相参照和新版地理图。四、检查链接、文档结构、同世界关键数据与源码未变。五、交用户审阅，认可前不接入软件。
