# 缓存命中率优化·P5：「禁止违背」提权（零代价）

> 2026-10-25
> 这轮不是缓存优化，是 P2/P3 顺手暴露出来的**内容质量隐患**。
> 结论：只把「禁止违背」从优先级 17 提到 6.6，≤12k 预算行为完全不变，≥20k 能把硬规则救回来。

---

## 一、问题

`FIELD_PRIORITY` 决定"预算不够时留谁"。实测（12000 token 预算）发现：

```
## 禁止违背   ← 优先级 17，被整段裁掉
## 写作风格   ← 优先级 19，被整段裁掉
```

而「本节速记」（优先级 0）永远保留。也就是说：**模型可能拿不到硬性世界规则，却在按速记写正文**。
这是设定漂移的直接来源，而且用户完全不知情。

---

## 二、三种提权方案，只有一种零代价

用真实裁剪算法（按优先级累加，**遇到第一个装不下的就截止，其后全丢**）模拟。
字段体量按真实长中篇估（灵魂 2200、章纲 3800、摘要 4200、人物状态 5200、设定 6200、规则 3000、文风 1900…）。

### 方案 A：提到最前（4.6 / 5.7）— 否决

| 预算 | 后果 |
|---|---|
| 8000 | 故事框架绑定被挤掉 |
| 12000 | **本章章纲被挤掉**← 为了硬规则牺牲"本章要写什么"，不可接受 |
| 20000 | 人物状态、角色灵魂、人物Skill 全被挤掉 |

### 方案 B：提到章纲之后（6.6 + 文风 6.7）— 部分可行但有一次实质损失

| 预算 | 变化 |
|---|---|
| ≤12000 | 与现状完全相同 |
| 20000 | 规则 + 文风 都救回来，无额外损失 |
| 40000 | 文风救回来，但**核心设定（6200）被挤掉** ← 用大的换小的 |

### 方案 C：只提「禁止违背」到 6.6 — **采用**

| 预算 | 现状丢弃 | 提权后丢弃 | 规则存活 |
|---|---|---|---|
| 4000 | 灵魂/框架/章纲/…全部 | **完全相同** | 否 → 否 |
| 8000 | 章纲起全丢 | **完全相同** | 否 → 否 |
| 12000 | 摘要起全丢 | **完全相同** | 否 → 否 |
| 20000 | 人物状态起全丢（含规则） | 人物状态起全丢（**少一项规则**） | 否 → **是** |
| 40000 | 下章建议/文风/检索/图谱 | **完全相同** | 是 → 是 |

**零代价**：≤12k 截止点本来就在它之前，挪位置不影响任何字段；≥20k 白赚一条硬规则；40k 也不挤掉任何东西。

---

## 三、改动

`src/lib/novel/context-engine.ts`：`FIELD_PRIORITY.canonRules` 由 `17` 改为 `6.6`（紧跟 `chapterOutlineContext: 6.5`），并写明为什么不放到章纲之前。

输出顺序不受影响（`FIELD_EMIT_ORDER` 是另一张表，规则本来就排在稳定段里）。

### 护栏

`context-engine.spec.ts` 新增：

```
硬性世界规则排在每章可再取的辅助信息之前
  budget ∈ {6000, 8000, 12000, 20000, 30000}
  若 canonRules 被裁 → recentSummaries 与 characterStates 必须也已被裁
```

这条断言锁住的是"不能出现留下摘要却丢了硬规则"这个方向，不锁具体阈值，够稳。


## 五、还没解决的同类问题

「写作风格」仍是优先级 19。它在 40k 预算下会被裁掉，而方案 B 说明"救文风就得牺牲核心设定"。
文风影响的是**腔调一致性**（AI 味、节奏），不是事实正确性，所以这轮没动。

如果要救，正确做法不是提权，而是**把文风挪进 system**（主对话链路已经这么做了，见 P0）；
章节链路没有 system，得先补 system 才能免费拿到它——那是另一个独立改动。
