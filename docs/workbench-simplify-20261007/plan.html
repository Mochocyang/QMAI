6.2 几何验证：check-panel.mjs

单元 B 自述「没做真实浏览器几何验证」，因此这部分由我补做。检查 6 个视口/视图组合 （1280 卡片/列表、900、700 两列最紧断点、620、600 列表），断言：对象名+日期不被裁切、 长名不会把「待确认」徽标顶出卡片、日期保持单行、版本标题行不溢出、页脚 3 个按钮不溢出、 页面无横向溢出。

关于非空洞证明的一个诚实结论：实测表明真正承重的只有日期上的 white-space:nowrap —— 在 700px 的两列断点下卡片仅 315px，去掉它日期会折成 3 行 （内联盒高度 14 → 44，行高 20）。而 h3 上的 min-width:0 本次没能证明承重：h3 宽度与徽标位置在加/不加它时完全一致 （overflow-wrap:anywhere 已经让文本随时可换行）。所以脚本只对 nowrap 做 非空洞证明，没有假装 min-width:0 挡住了什么。

  1. 把 7 张卡片 × 3 个版本标题一起渲染 → 卡片数断言得到 21 而非 7；改为卡片只渲染一次。

  4. 证明③忘了把页面内容换回修好的 CSS，导致它在测变异体、必然失败。

7. 实施中发现并修正的设计错误

我最初的设计前提是错的，由实施子代理发现。 我原以为角色灵魂的 id 是确定性推导的 wb-${sha256(subject)}，因此「发布与删除可以用同一个函数算出同一个 id」。 实际不然：
  1. 那个推导值只赋给一个临时的 ExtractedCharacter.id （workbench-publish.ts:112），它传不进 aura （buildGeneratedAuraInputFromBookCharacter 与 GeneratedCharacterAuraSkillInput 都不读 id）—— 在发布路径上是死值。
  2. 真正落库的 id 由 createCustomCharacterAuraFromGeneratedSkill （character-aura.ts:432）生成：custom-${now}-${Math.random()}， 每次都不同。
  3. deleteCustomCharacterAura 按 aura.id 精确过滤， 查不到会静默返回、不抛错 —— 只按推导值删的结果是 「卡片消失了但灵魂还在库里」，属于最坏的一类 bug（看起来成功了）。
修正：删除改用与发布同源的判据 isSameBookAnalysisCharacterAura(a, bookTitle, subject) （发布路径 workbench-publish.ts 找 existing 用的就是它）， 并且删掉全部匹配项而不是只删第一条 —— 同一 (书名, 角色名) 在库里可能留下多条 （历史重复导入，或书名改过而旧备注仍在），只删一条会留下同名残留。
注意：原先这里写的理由是「新版发布与 legacy 导入是两套 id 体系」， 经独立审查证伪（两条路径共用同一个创建函数，且 aura-adapter.ts 有同源去重）， 故按实际情况改写。结论不变：仍然全删。
独立对抗审查后追加的三处修复（本轮，均有回归测试 + 变异验证）
  1. 删除判据的子串误伤（数据丢失）：isSameBookAnalysisCharacterAura 原用 text.includes(bookTitle) 裸子串。书名互为子串时（《测试》⊂《测试作品》）， 在《测试》里删同名角色会把《测试作品》的灵魂一起真删（不可撤销）；发布侧同理会去改写别书的条目。 修法：改为按 《书名》 边界匹配（与既有 aura-cleanup.ts 的 《\\s*title\\s*》 约定一致）。反例：把书名裸写进 sourceNote 的历史数据 会不再被认作同源；保留了 text.trim() === title 兜底。
  2. 活动跳转重复滚动（回归）：navigation 从不被消费，而跳转 effect 依赖 revisions，于是每次版本列表重载（自动入库后 reload、用户删一个对象…）都会把视口 再拉回那个旧版本。实测「跳转后 scrolls=1 → 删一个对象 → scrolls=2」。 修法：book-analysis-activity-store 新增 consumeNavigation()， 组件在确实找到目标版本后消费（找到之前不能消费，否则异步首轮空数组会把跳转吃掉）。
  3. 删除后的悬空引用与落盘契约：删除时一并回收 publishedIds 里已删的 id （否则它作为「本版在库条目」的语义会与库不一致）；并**明确承认**——删除懒落盘的 legacy 迁移条目 会把它落盘（不落盘的话 removedSubjects 存不下来，被删的旧版角色下次打开又会被重新造出来）。 两条都有回归测试。
顺带修复：全版本平铺后每个版本块各渲染一份卡片/列表开关（N 份互不相干）， 已把 view 提到结果区统一持有，视图切换只渲染一份并统管所有版本块。 同时发现 check-panel.mjs 的「非空洞证明」是假绿的： allCss 里同一条 .wb-card-date 规则出现两份（dist 产物 + 源文件）， 非全局 replace 只改掉第一份，剩下的仍带 white-space:nowrap， 于是变异体根本没被削弱。已改为全局替换并断言「无带 nowrap 的残留」。
