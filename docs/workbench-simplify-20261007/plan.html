2. 实施单元 B：组件（TDD）

改动要点
删 6 项 UI + 对应 stateselectedRevision、query、pendingOnly 三个 state 全删；confirm()、exportResult() 删除；Check/Download 从 import 移除（noUnusedLocals: true，留着必编译失败）
活动跳转改写原本靠 setSelectedRevision；改为切页签 + scrollIntoView 定位到该版本（用 data-revision-id）
自动入库 effect只处理 !confirmedAt && origin !== "legacy"；每个 id 每次挂载只尝试一次（useRef 记录），失败 toast.error 且不写标记、不重试（避免无限刷屏）；成功后 reloadRevisions()
全版本平铺渲染顺序按 createdAt 升序（旧在前）；不改 loadWorkbenchRevisions 的降序数组顺序（组件 :290 有注释警告）
版本标题行时间 · N章 · M个对象 ·（K项未采纳）；legacy 额外标「旧版导入」；非 legacy 且未入库标「尚未入库」
对象名后加日期取所属版本 createdAt，格式 M/D HH:mm
删除按钮 + 弹窗卡片底部第三个按钮（Trash2 已 import）；base-ui Dialog；文案按技能页三分支；确认后调 removeWorkbenchRevisionItem 并刷新
过滤已删除渲染时 items.filter(i => !removedSubjects.includes(i.subject))

3. 验证顺序

  1. 单元 A 的 spec 全绿 → 单元 B 的 spec 全绿（B 用 mock 隔离，可与 A 并行）
  2. npx tsc -p tsconfig.app.json --noEmit 必须 0（两个单元都落地后才有意义）
  3. 聚焦套件：affected specs 列表跑通并核对文件数与用例数（vitest 遇不存在路径会静默少跑）
  4. 变异验证：关键守卫逐条破坏 → 必须让具名测试失败，并附正向对照
  5. 全量套件与基线 A/B：新增失败文件必须为 0
  6. 独立对抗性审查（子代理），缺口逐条闭环
  7. 便携版重建 + 243 产物嵌入校验

4. 明确不在本次范围

  • 不做「覆盖已有条目时弹窗确认」（用户已接受静默覆盖；备份仍在 analysis/publication-history）
  • 不做删除撤销
  • 不改文风库/故事框架库的其它行为
  • 不动分析流水线、不改 loadWorkbenchRevisions 的排序

5. 风险登记

风险缓解
自动入库静默覆盖同 id 旧条目发布前照旧写 publication-history 备份快照；用户已知情接受
legacy 版本若被自动发布 → 重复角色灵魂明确排除 legacy，并写一条具名测试钉死「legacy 不自动发布」
失败后无限重试刷屏每 id 每次挂载只尝试一次；失败只报错一次
删掉 state 后遗漏引用 → 编译失败tsc --noEmit 作为硬门槛
旧版在前导致最新结果在最下面已向用户说明并确认；如日后不适可反向一行
