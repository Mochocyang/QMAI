把安装界面做成会动的

你想要的「WPS / 向日葵 / 360 那种大气磅礴」，本质不是一张会动的图，而是 去系统边框的自绘窗口 + 占满画面的大品牌主视觉 + 持续流动的光效 + 一键跑完的节奏。 下面先讲清楚在当前这套 Tauri + NSIS 打包链路上怎么做到、代价是什么，最后附一个可以直接看的动效 Demo。

当前形态：NSIS / MUI2 标准向导 侧栏图 164×314 · 页头图 150×57（静态 BMP） 打包链路：Tauri 2 → NSIS 版本：v4.3.7
01

结论：能做，但要分两层看

很多项目失败在这一步——把「动效」和「安装逻辑」搅在一起，结果动效做不出来，安装也不稳了。

判断

NSIS 原生做不到

NSIS 的界面只认 BMP 静态位图，不支持 GIF、APNG、视频。想「硬塞」动画只能靠定时器逐帧换图，帧率上限约 10fps，还会闪。

方向

拆成「动效壳 + 安装内核」

让 NSIS 只负责真正干活（解压、注册、提权、静默参数），视觉与交互交给一个能跑现代动效的壳。WPS、360 也是这个结构。

推荐

外层仍是原 NSIS exe

壳作为资源被 NSIS 释放并拉起来。这样签名对象、更新链路（Tauri Updater）、? 静默参数全部不变，回归面最小。

一句话方案：NSIS 保持"外壳与内核"双重身份，另加一个 QmaiSetupUI.exe 作为动效引导进程。用户先看到的是一个 960×600 的无边框动效窗口，点「开始安装」后，真正的安装段在后台静默执行，进度通过临时文件回传给动效界面。装完再回到动效界面显示完成页。

02

先拆解：它们为什么看起来大气

只做"会动的图"是达不到那个观感的。这四件事缺一件，都会掉档次。

要素 01

无边框自绘窗口

没有灰底系统标题栏、没有「下一步 / 上一步」的那排按钮。整个窗口就是一张画布，品牌独占。

要素 02

大尺寸主视觉

NSIS 侧栏只有 164×314，占画面不到两成，天然"小家子气"。改为 960×600 满版主视觉，气势立刻不同。

要素 03

持续的微动效

关键不是"播一段动画"，而是光一直在流、粒子一直在飘、logo 一直在呼吸。安静但不停，这是"高级"的来源。

要素 04

一键安装的节奏

不点「下一步」，进度自动跑完。少的是"向导感"，多的是"软件感"。这一条对体感的影响比动画本身更大。

03

现状诊断：这套安装器能做什么、不能做什么

基于 src-tauri/windows/_tauri-installer-template.nsi 与 tauri.windows.conf.json 的实际配置。

能力项当前状态说明
页面流程 7 页向导 欢迎 → 许可 → 重装判断 → 安装目录 → 开始菜单 → 安装进度 → 完成。步骤偏多，观感偏"传统软件"。
侧栏 / 页头图 静态 BMP 164×314 与 150×57。MUI2 只接受位图，且尺寸固定，不能放大。
GIF / APNG / 视频 不支持 NSIS 界面控件不支持任何多帧格式，这是引擎层面的限制。
定时器逐帧换图 可，但勉强 用 nsDialogs 自绘页 + Timer 反复换 BMP，或引入 Slideshow 类插件。10fps 左右、GDI 重绘易闪、体积膨胀。
进度条品牌化 有限 MUI 可以给进度条着色（colored），但形状、光效、百分比排版都改不了。
去掉系统边框 需换肤插件 要在 NSIS 里做无边框自绘窗口，得整套 Win32 自绘或换肤插件。在你现在这份已经定制的模板上动，稳定性风险高，不建议。
静默安装 /S 已具备 模板里已有 PassiveMode / SkipIfPassive 全套判断，这是"动效壳 + 静默内核"方案能落地的前提，你已经免费拥有。

关键结论：不要试图让 NSIS 自己变漂亮。它的界面层是 20 年前的 GDI 设计，投入产出比极低；而它的安装逻辑层非常可靠、且已支持静默。正确的做法是用它可靠的那一半，替掉它不好看的那一半。

三条可选路线

按投入从低到高排列。推荐 B，但 A 可以作为一周内就能看到的过渡版本。

过渡版

A · NSIS 内部帧动画

1–2 人日素材 12–24 帧体积 +1–2MB
  • 自绘欢迎页 + Timer 逐帧切换 BMP
  • 品牌色进度条 + 完成页动效
  • 不动打包链路，零新依赖
  • ≈10fps，肉眼可见顿
  • 重绘闪烁难彻底消除
  • 只能动首屏，进度页仍是原生
  • 达不到 WPS 级观感
推荐

B · 动效壳 + NSIS 静默内核

4–7 人日+1 个 exe体积 +5–10MB

06

动效规范（Demo 就是照这个做的）

写成规范是为了让素材、前端、打包三方对得齐，也为了以后换素材不用重写代码。

窗口与版式

  • 960×600（DPI 缩放由系统处理，按 1.5x 出素材）
  • 圆角 16px，1px 内描边 rgba(255,255,255,.10)
  • 外阴影 0 40px 90px -30px rgba(0,0,0,.85)
  • 无系统边框，标题栏只留品牌名 + 三个 20px 高的小按钮
  • 窗口居中，不可拉伸，不可最大化；Esc 触发取消确认

色彩

  • 深色底：#05161A → #0B2C30 斜向渐变
  • 品牌青：#35B7A6；高光薄荷：#6FE3CE
  • 正文：#EAF7F4；次级文字不透明度 40–65%
  • 浅色备选：纸底 #F3EEE3，墨青 #14251F，主色 #1E7A6C
  • 禁止在动效里出现第三种强调色（会和品牌青打架）

时序

② 安装 2.6–9.6s
③ 完成

元素缓动规则
窗口 / 幕切换cubic-bezier(.16,1,.3,1)淡入 + 上移 14px + 缩放 0.985→1，时长 550ms。绝不用弹跳。

性能预算：目标 60fps，只动 transform 与 opacity；大面积模糊用预渲染底图而不是实时 filter: blur()；粒子数按面积算，上限 60 个；整包动效素材 ≤1.5MB（Lottie 优先，帧序列只用于必不得已处）。

07

动效壳怎么和 NSIS 安装逻辑对接

这是方案 B 唯一有技术含量的部分，也是必须提前设计好的部分。

  1. 1用户双击 QMaiWrite_4.3.7_windows_X64.exe。此 exe 仍然是原 NSIS 安装包，签名、更新链路不变。
  2. 2NSIS .onInit 判断运行模式：只有"交互模式"才释放并启动 QmaiSetupUI.exe；带 /S、/passive、CI 环境一律走原生静默流程（零风险）。
  3. 3动效壳启动，显示第 1 幕欢迎页。此时还没有提权、还没写任何文件，用户看到的只是界面。
  4. 4用户点「开始安装」→ 壳通过命令行把控制权交回 NSIS（例如 Setup.exe /qm-ui-continue=<pid>），NSIS 提权并执行安装段，安装段本身不带任何页面。
  5. 5安装段每完成一个阶段，向 %TEMP%\qmai-setup-<pid>.progress 追加一行 18|正在解压核心文件。壳每 200ms 读一次。用临时文件而不是命名管道：零插件依赖，最稳。
  6. 6装完写 100|done，壳切到第 3 幕；点「立即体验」由壳 CreateProcess 拉起主程序。
  7. 7任何异常 → 写 err|<code>，壳显示错误页：错误码、日志路径、「重试」、「切回原生界面」三个出口。
  8. 8壳启动失败或 3 秒内没握手 → NSIS 放弃壳，直接显示原来的 MUI2 界面。这条回退是必须的。
为什么不换外层

签名与更新不能动

如果你的壳变成最外层的 exe，Tauri Updater 校验的签名对象就变了，更新链路要整体重做。让壳待在 NSIS 里面，是这次方案能"低成本"的根本原因。

为什么不实时流式

200ms 轮询足够

安装全程 40 秒左右，进度条 200ms 刷新一次肉眼已完全平滑。上管道要多一个 NSIS 插件，得不偿失。

必须想清楚

取消的语义

「取消」只在安装段开始前可用；安装段开始后按钮改为「中止」并走 Abort + 清理半成品。否则会留下坏掉的安装目录。

08

落地步骤

建议分两期，第一期就能让你看到东西，第二期再上完整观感。

第一期 · 1–2 人日

先让首屏"活"起来（路线 A）

  • 自绘欢迎页（Page custom），放 12 帧动效序列
  • 用本 Demo 的第 1 幕作为画面基准，导出 BMP 帧
  • 进度条改品牌色，完成页换成带勾的动效帧
  • 产出：一个能立刻发出去给人看的过渡版本

风险极低，不动打包链路，任何问题可以直接回退图片。

第二期 · 4–7 人日

上动效壳（路线 B）

  • 新建 src-installer/ 最小 Tauri 工程，只做三幕界面
  • NSIS 模板加：启动壳、静默段、进度回传、超时回退
  • 三条出口验证：正常装完 / 取消 / 断网或写入失败
  • 壳 exe 一起签名；补一条 CI 检查确保壳被打进资源
  • 保留开关：QMAI_SETUP_NATIVE=1 强制原生界面

这一期结束后，观感即与 WPS / 360 同级；后续换皮只改 CSS 与素材。

建议顺序：先做第一期拿到"能看的版本"，同时用它的素材给第二期定调。不要一上来就写壳——万一风格方向要改，壳的电全部白费；帧素材改起来只要几分钟。

09

风险与回退

安装器是用户第一次接触产品的地方，稳定性优先级永远高于好看。

风险概率对策
杀软误报中 新增的壳 exe 由签名安装包释放并执行，是典型启发式命中场景。对策：壳一并代码签名、向主流引擎提交白名单、壳体积尽量小、不写系统目录、不联网。
Updater 链路受影响低（方案 B） 外层 exe 仍是原 NSIS 包，签名对象不变。这也是把"壳当内层"而不是"壳当外层"的理由。
WebView2 缺失中 壳启动 3 秒内没握手即回退原生 MUI2 界面。安装包本身不额外带 Runtime（当前配置就是 skip）。
静默 / CI 被破坏低 壳只在交互模式启动，/S 与 /passive 完全走原路径，加一条测试锁死这个分支。
低配机 / 远程桌面卡顿中 跟随系统「减少动态效果」设置自动降级为静帧；壳内提供手动开关；粒子数按窗口面积动态缩减。
壳进程被用户强杀中 NSIS 侧监听壳句柄，壳消失且安装未完成 → 终止并清理，不能留半装状态。
多显示器 / 高 DPI 错位中 壳按 per-monitor DPI 感知声明，窗口在鼠标所在屏居中；1.25x / 1.5x / 2x 三档必须实测。
10

需要你拍板的四件事

这四条定了，我就能直接开工；不定的话做出来大概率要返工。

  • Q1
    第一期先做，还是直接上第二期？ 建议先做第一期（1–2 天），拿到能看的版本再决定要不要写壳。这样风格方向试错成本最低。
  • Q2
    风格选「青幕流光」还是「纸感留白」？ Demo 里两版都能点。深色更有"科技感/大气"，浅色更贴产品本身的书写气质。也可以做成跟随系统主题。
  • Q3
    要不要做成真正的"一键安装"？ 即：不再询问安装路径，默认装到当前用户目录，点一下自动跑完。这是 WPS / 360 体感的关键，但会牺牲"自定义安装"这一步。
  • Q4
    动效素材谁出？ 我可以直接用 CSS / Lottie 做出 Demo 里的效果（零额外成本）；如果你们有 AE 设计资源，给出规范后交接会更耐用。
