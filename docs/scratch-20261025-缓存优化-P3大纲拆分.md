# 缓存命中率优化·P3：作品大纲与章纲拆分（跨章 35.7% → 71.9%）

> 2026-10-25
> 前序：P0 主对话资料前移、P1 审稿复用前缀、P2 上下文输出顺序
> 本轮把「作品级大纲」和「卷纲+本章章纲」拆开，让作品大纲与稳定设定一起落在跨章公共前缀里。

---

## 一、问题

P2 之后，写作链路的 prompt 是：

```
# 【强制遵守】作品完整大纲
<mergedOutline = 作品大纲 + 卷纲 + 本章章纲>     ← 章纲随章变，断点就在这里
上下文：
## 项目灵魂 … ## 禁止违背 … ## 相关地点/组织/物品 … ## 写作风格
## 当前任务 / 写第N章 …
```

`mergedOutline` 把三段拼成一份放在**第 0 个字节**，而它末尾就是"本章章纲"。
于是每换一章，**后面那一整块稳定设定（灵魂/规则/设定/文风）全部够不着**。

---

## 二、改动（3 个文件）

| 文件 | 改动 |
|---|---|
| `src/lib/novel/deep-chapter-generation.ts` | `outlineText` 改为优先取 `contextPack.projectOutline`（作品级）；缺失时回退到原来的 `contextPack.outline`（保持旧行为） |
| `src/lib/novel/context-engine.ts` | ① 新增字段配置 `chapterOutlineContext`（标题 `## 本章章纲`）；② 裁剪优先级 `6.5`（紧跟 outline，确保紧预算下仍保留）；③ 输出顺序表里排在 `outline` 之后、`task` 之前；④ **去重规则**：不排除 outline 时（审稿等场景）章纲已在 mergedOutline 内，跳过该字段 |
| `src/i18n/zh.json` | 新增 `novel.contextPack.chapterOutline` |

为什么这样能生效：
- 作品大纲 → 放在 prompt 最前，整本书稳定；
- 灵魂/框架/正典/规则/设定/文风 → 由 P2 的输出顺序保证紧跟其后；
- 卷纲 + 本章章纲 → 落到 `chapterOutlineContext`，排在稳定字段**之后**；
- 于是跨章的公共前缀 = 作品大纲 + 全部稳定设定，断点正好落在「本章章纲」。

## 四、一个前提要说清楚

这套拆分依赖 `contextPack.projectOutline` 存在（即构建上下文包时算出了 outline 分层）。
**没有 outlineLayers 的项目会回退到旧的 mergedOutline**，跨章命中率仍是旧水平。
如果线上还有这类项目，需要确认 `buildContextPack` 是否总会产出 `projectOutline`。

## 六、下一步

1. **「禁止违背」与「写作风格」被裁**：优先级 17 / 19，预算紧时整段消失（12000 token 的实测里两者都不见了）。这是设定漂移风险，提权会改变"留谁"的行为，需要产品确认后再动。
2. **`stableFragments`（主对话稳定块）的顺序**：现在是 灵魂 → 框架 → 正典 → 规则 → 核心设定 → 文风 → 大纲，"核心设定"其实随章变，应下沉到大纲之后。属于同一类"顺序"问题，改动小、可测。
3. **资料章内冻结**（P0 遗留）。
4. **2k token 以下的碎调用**合并（低于缓存门槛等于白跑）。
