# 缓存命中率优化·执行计划（P0 批次）

> 2026-10-25 · 依据：真机实测报告（`scratch-20261025-缓存命中率-真机实测报告.md`）
> 目标：把主对话第二轮的未命中从 ~996 token 降到 ~100 量级（实测 A/B：85.8% → 98.7%）

---

## 一、本批只做四件事（P0）

| # | 改动 | 实测依据 | 影响文件 |
|---|---|---|---|
| A | 把「本轮参考资料（dynamicContext）」从 user 尾部前移到 system 之后、历史之前 | A/B 85.8% → 98.7%，未命中 996 → 94 | `context-hub/prompt-content.ts`、`chat/chat-panel.tsx` |
| B | 把「技能库 / QM-QUAI 技能」从"本轮动态要求"移到 system 稳定段 | 技能在 system：97.9%；在 user 正文：0% | 同上 |
| C | 任务契约改用**会话首条**用户目标，不再写本轮输入 | 契约在 system 末尾，每轮变 → 其后全部历史失效 | `agent/runner.ts`、`chat/chat-panel.tsx` |
| D | DeepSeek 补 `stream_options.include_usage`，UI 不再拿本地文件缓存率冒充 | 不开就收不到 `prompt_cache_hit_tokens`，改动无法验收 | `llm-providers.ts`、`common/context-hub-stats-summary.tsx` |

**不做**（下一批）：章节单会话化、审稿复用前缀、stableCore 固定配额、裁剪下界、工具集冻结。理由：它们要么改产线、要么改上下文构成，需要单独灰度；先把"只挪位置、不改语义"的两项落地并验证。

---

## 二、A+B 的落点设计

现状：
```
[system: 软件规则 + 稳定核心] [history] [user: 摘要 + 本轮资料 + 技能 + 要求 + 用户输入]
```

改后：
```
[system: 软件规则 + 稳定核心 + 技能库] [本轮资料(user)] [history] [user: 摘要 + 本轮要求 + 用户输入]
```

- `buildContextHubPromptParts` 的返回从 `{systemContent, taskContext}` 扩为 `{systemContent, chapterPrefix, taskContext}`；
- `systemContent` 追加 `stableRules`（技能类），并保持"最后一段带 cacheControl"的断点语义；
- `chapterPrefix` 只装 `dynamicContext`（人物状态/伏笔/检索/推演），**不装会话摘要**（摘要每轮重算，放前缀会立刻打断前缀）；
- `taskContext` 只留 `sessionSummary` + 本轮执行要求（taskDirective / goldenDirective / 大纲查找协议）；
- `chat-panel` 把 `chapterPrefix` 作为一条独立 user 消息插在 system 之后、history 之前。

## 三、C 的落点设计

```ts
// runner.ts：原来取"最后一条 user"（= 本轮输入），改为取"第一条 user"
const firstUser = messages.find((m) => m.role === "user")
```

同时 `chat-panel` 不再把 `taskGoal: plainText` 塞进 agentConfig——它语义上写的是"初始任务目标"，传本轮输入既错又不缓存。

## 四、验收

1. `tsc --noEmit` 干净；
2. `cache-prefix-diagnostic.spec.ts` 8 项仍绿（S2 的未命中应从 7114 明显下降）；
3. `prompt-content.spec.ts` 按新契约更新断言并通过；
4. `chat-panel` / `user-memory` / `runner` 相关 spec 通过；
5. 真机复跑 `cache_probe_ab.py`，确认第二轮命中 ≥ 98%。

## 五、回滚

四处改动都集中在函数返回结构与一处消息插入，回滚只需还原 `prompt-content.ts` 的返回字段与 `agentMessages` 的展开；不涉及数据结构、不涉及持久化格式。
