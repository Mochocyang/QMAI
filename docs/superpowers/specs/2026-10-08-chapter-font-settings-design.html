章节「字体设置」与正文字距 / 边距

待你审阅 —— 确认后我才进入实施计划
原始需求（用户原话，逐字保留）

现在软件当中有一个是界面字体，一个是正文字体。将正文字体放置在章节当中，也就是说写小说的过程当中，它的字体，章节当中显示的字体，是用正文字体是可以设置的。并且这个正文字体能够控制章节当中的字体。

另外，章节当中的当前的一键排版的图标与正文字体的图标，它两个不能设置为一样。当前一键排版的图标是字体的图标，你需要重新换一个。

还有当前在写作的过程当中，它的字体、它的行数总是显示在最后最底层，这个是有一些问题的，因为这样写的话总是眼睛看的都是最下面，让人很不习惯，所以说这里要调一个设置功能。这个设置功能呢，可以调一个底部的安全距离，这个底部的安全距离呢，也就是说是最后一行显示的字数是要在最后面去显示出来的。

另外，章节当中要有一个字间距的设置、行间距的设置、左右边距的设置以及底部安全间距的设置。另外字体的设置要有字号大小的设置，允许用户进行自定义的设置。

还有，关于智能排版的话，用换上一个浦发的一个智能排版的图标，你在里面去查找一下。所以说现在的话你要去进行重新的设置以及调整一下并且关于字体、间距等这些的设置，大纲当中也要有这个设置功能。

01

背景与实测根因

先说一个反直觉的结论：正文字体控制章节字体的链路本来就是通的，缺的是「写作现场能改」这个入口。贴底与间距不可调则各有明确的代码根因。

现象实测根因
写作现场改不了字体 正文字体链路已通：--serif 派生自 --qmai-body-font-family，章节正文 textarea 用 var(--serif)。但控件只在「设置 → 外观与界面」里。
最后一行贴在最底层 ui-test-editor.css:40  padding-bottom: 36px 写死，不可调；窄屏还有一条 28px 覆盖。
左右边距无法调 ui-test-editor.css:232  .immersive-scroll-container > div { padding: 0 } 把内层 px-8 py-10 清零；外层只有一条 clamp(20px, 4vw, 48px)。
行间距无法调 --qmai-body-line-height: 1.95 是字面量，同时 p 另写 1.95、li 写 1.9（共 3 处独立数字，改一处不会同步）。
字号只能选档 --qmai-body-font-size: calc(1.125rem * var(--qmai-body-font-scale, 1))，设置里只有 85/100/125/150% 四档百分比。
一键排版用字体图标 preview-panel.tsx:1520  一键排版用的是 lucide Type（T），与字体语义撞车。
关于你给的截图

截图里的「字间距 / 行间距 / 左右边距 / 底部安全距离」和「默认字体 / 15」在源码中零匹配，它们不是青幕现有界面。我按「你想要的目标样式」处理，滑块与数值的形态对齐该图。左侧那组绿色滑块只是配色巧合，容易让人误以为已实现。

需要你确认的一点

左右边距的默认语义：今天它是响应式的 clamp(20px, 4vw, 48px)，宽窗口 48px、窄窗口 20px。我打算这样处理 —— 你没动过这个滑块时，继续跟随窗口（行为完全不变）；一旦拖动过，就固定成你选的 px。这样既不惊吓现有用户，又能真正可调。如果你希望一上来就固定，请说。

05

贴底修复

这是你报的核心不适感。修法是把两条写死的值换成变量，并让「底部安全距离」在滚到底时留出真实空白。

位置现状改为
.ui-test-editor-scroll padding-bottom: 36px;
@media(max-width:640px){ padding-bottom: 28px }		 padding-bottom: var(--qmai-body-safe-bottom);
（删掉窄屏覆盖，统一走变量）
.ui-test-editor padding: 0 clamp(20px, 4vw, 48px); padding: 0 var(--qmai-body-margin-x);

效果：滚到底时最后一行下方固定留出 51px（可调）；打字时当前行不再贴在窗口最下沿。

06

入口与界面

控件只有一套归属：抽出一个共享组件，设置页与写作现场的浮层都复用它，避免两个入口读出两套值。

写作现场

  • 章节工具栏（preview-panel.tsx:1509-1521）：在「一键排版」之前插入 type 图标的按钮，aria-label="字体设置"。
  • 大纲工具栏（preview-panel.tsx:1522-1531）：在「查看记忆」之后插入同一个按钮。
  • 一键排版按钮的图标由 Type 改为 wand-sparkles（行为不变）。

浮层内容与顺序

  1. 正文字体（下拉，含推荐 + 本机中文字体）
  2. 正文字号（滑块 + 数值，px）
  3. 行间距（滑块 + 数值）
  4. 字间距（滑块 + 数值，px）
  5. 左右边距（滑块 + 数值，px）
  6. 底部安全距离（滑块 + 数值，px）

改动即时生效（写 CSS 变量 + 持久化），与设置页共用同一份值。设置页「外观与界面」里现有的「正文字体 / 正文字号」两项替换为这个共享组件。

我读过 verify-body-font-single-source.mjs：它把字号表达式钉成 1.125rem × 倍数（L158），把行高钉成固定字面量 1.95（L170-172，并注释「不随字号变化」）。按你的决定这两个字面量必须改，但我会保留它真正的不变量，并另外补守卫。

新增守卫（每条先证明「无修复必红」）

  1. 参数隔离：6 个参数各自单独改动时，只有对应元素的计算值变化（防止把字间距错接到行高上）。
  2. 迁移正确性：4 组 scale → px 映射 + 越界夹取。
  3. 贴底生效：滚到底时最后一行下方留有 --qmai-body-safe-bottom 的空白，且该值可调。
09

代价与影响面

  • 正文不再随「界面字号」缩放（你已确认接受）。此前 calc(1.125rem × 倍数) 会让正文跟着根字号一起变；改成 px 后改「界面字号」时正文纹丝不动。
  • 列表行高会被统一（待确认）：现在 p 是 1.95、li 是 1.9。要让「行间距」一处生效且可解释，我打算让列表与正文同高，列表会略增高约 2.6%。如果你要求保留这个差异，我会改成按比例派生。
  • 底部安全距离默认 51px：所有现有用户的写作区底部空白从 36px 变为 51px，这是你要求的变化。
  • 标题、表格、引用块、代码块的行高保持固定，不受行间距影响。
