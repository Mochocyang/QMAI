qmai.work 内置模型中转站 · 设计规格

日期 2026-10-30 · 状态 待评审 · 目标域名 relay.qmai.work · 代码仓库 新建私有仓库 qmai-gateway
一句话：在 Cloudflare 免费额度上搭一层只认票据的 OpenAI 兼容网关，把「Agent2API 的免费账号额度 + 硅基流动 + 现有 New API 站」合并成一组对外统一的模型名，只有登录过 QMai 账号且在白名单里的人能拉清单、能调用。

1. 目标

#目标验收信号
G1客户端登录后，无需填任何 API Key 即可列出并使用内置模型登录态 → 票据 → GET /v1/models 返回清单
G2模型来源可叠加：Agent2API（免费额度）、硅基流动、New API 站，对外名字统一换上游不需发客户端版本
G3某个上游失效/429/超时，自动换下一个来源，用户无感注入故障后请求仍成功
G4除白名单内账号外，任何人都拿不到模型清单也调不动无票 401、非白名单 403、白名单为空则全拒
G5全链路零新增服务器成本Cloudflare 免费额度内 + 自有 NAS 常开
G6每次调用留一行用量，可查成本与重度用户D1 usage_logs 有数据

2. 非目标（明确不做，避免范围膨胀）

  • 不做注册、支付、卡密兑换、套餐、推广返利——这些是 New API 类模板的价值所在，本场景用不到。
  • 不做 Web 管理后台。模型表、路由链、白名单全部用 wrangler d1 execute 与 vars 维护。
  • 不做多租户计费与扣费。只有"能不能用"，没有"还剩多少"。
  • 不改上游（Agent2API）源码；它按原样跑在 NAS 上。

3. 约束与既有事实

约束事实对设计的影响
没有服务器只有 Cloudflare + GitHub + 一台可常开的 NAS常驻进程（Agent2API）放 NAS；CF 只做前台网关
GitHub 不是运行时Actions runner 临时、无持久盘GitHub 只做代码源 + Workers Builds 自动部署
Agent2API 有状态Node 服务 + SQLite（/data 卷）+ 明文凭证不能上 Workers；Cloudflare Containers 是备选但需 $5/月
上游不稳定登录态会过期、会触发风控、签到会断降级必须是一等公民，不是补丁
Agent2API 许可证MIT + 附加声明：禁止商用、禁止二次分发牟利、禁止批量账号运营仅内部自用；不得把免费额度包成对外商品
Workers 免费额度约 10 万请求/天、单次 CPU 10ms；D1 约 10 万行写/天自用够；上量到千级活跃用户需升 Paid（$5/月，含 1000 万请求/月）

5. 组件与职责

组件位置只做明确不做
qmai-gatewayCloudflare Workers（新私有仓库）验票、白名单、清单聚合、路由降级、SSE 透传、记账不注册用户、不计费、不存上游凭证

cloudflared你的 NAS（容器）把 3065 暴露成 a2a.qmai.work不做鉴权

6. 数据模型

-- 一张表决定"对外叫什么、背后是谁、谁先谁后"
CREATE TABLE model_routes (
  public_name     TEXT    NOT NULL,   -- 对外名，如 qmai-standard
  upstream        TEXT    NOT NULL,   -- a2a | siliconflow | newapi
  upstream_model  TEXT    NOT NULL,   -- 上游真实模型 ID
  priority        INTEGER NOT NULL,   -- 越小越先用
  enabled         INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (public_name, upstream, upstream_model)
);
CREATE INDEX idx_routes_public ON model_routes (public_name, priority);

-- 一次上游调用写一行；按调用而非按 chunk，避免长文把写入额度吃光
CREATE TABLE usage_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id         INTEGER NOT NULL,
  public_name     TEXT    NOT NULL,
  upstream        TEXT    NOT NULL,
  status          INTEGER NOT NULL,
  prompt_tokens   INTEGER,
  completion_tokens INTEGER,
  created_at      INTEGER NOT NULL
);
CREATE INDEX idx_usage_created ON usage_logs (created_at DESC);
CREATE INDEX idx_usage_user    ON usage_logs (user_id, created_at DESC);

7. 接口契约

方法 路径鉴权行为
GET /health无{"ok":true}，仅探活，不泄露版本与配置
GET /v1/models票据 + 白名单只返回 model_routes 里 enabled=1 的去重 public_name，OpenAI 列表结构；不暴露上游名与真实模型 ID
POST /v1/chat/completions票据 + 白名单按 priority 依次尝试上游；stream:true 原样透传 SSE；成功后异步写一行 usage_logs
POST /v1/embeddings票据 + 白名单同转发逻辑，不做降级（向量模型不在免费额度里）
其它路径—404 接口不存在。

响应体一律 OpenAI 错误结构，中文文案，便于客户端直接展示：

{ "error": { "message": "登录状态已失效，请重新登录后再试。", "type": "invalid_request_error" } }

7.1 状态码约定

码含义客户端处理
401无票据 / 验签失败 / 已过期重新登录换票后重试一次
403账号不在白名单（含白名单为空）提示"当前账号无内置模型权限"
404模型不在路由表 / 路径不存在提示刷新模型列表
413请求体超上限（默认 8 MiB）提示内容过长，拒绝发送
429全部上游都限流提示稍后再试
502全部上游不可用提示"内置模型暂时不可用"

8. 安全模型

层机制失败时
票据Ed25519 验签，算法白名单只收 EdDSA（防 none/HS256 混淆）401
时效exp 30 分钟，客户端提前 120 秒续签401
名单ALLOWED_USER_IDS 逗号分隔；留空 = 全拒（失败关闭）403
上游凭证每个上游一条 Worker secret，永不进仓库、不进客户端该上游被判不可用，走下一跳
NAS 门a2a.qmai.work 只认 X-Relay-Secret（随机 32 字节，存 Worker secret）；不用 Cloudflare Access，避免席位概念与浏览器拦截403
CORS仅放行 tauri://localhost、https://tauri.localhost浏览器侧读不到响应
说明：Cloudflare Access 免费版 50 席位限制的是"能登录 Zero Trust 的人数"，与终端用户数无关。本方案不使用 Access，3000 用户也不受影响。

9. 路由与降级（伪码）

async function handleChat(request, env) {
  const auth = await authenticate(request, env)          // 票据 + 白名单
  if (!auth.ok) return auth.response

  const body = await readJsonCapped(request, 8 << 20)    // 超限 413
  const publicName = body?.model
  const chain = await routesFor(env, publicName)         // 按 priority 升序，60s 内存缓存
  if (chain.length === 0) return err404()

  for (const hop of chain) {
    const upstream = upstreams[hop.upstream]             // 各自 baseUrl + secret
    const res = await upstream.forward(body, hop.upstream_model)
    if (res.ok) { ctx.waitUntil(recordUsage(...)); return withCors(res) }
    if (!retryable(res.status)) return withCors(res)     // 400/401/403/404 原样回传，换源无意义
    // 429 / 5xx / 超时 → 试下一跳
  }
  return err502()
}

只对 429、5xx、网络超时降级；参数错误类 4xx 直接回传，避免把用户错误放大成多次计费调用。

10. 实施分期

阶段 0 · 密钥（不可回退，一次做对）

  1. 本地生成 Ed25519 密钥对：私钥 PKCS#8 base64 只进旧账号 secret RELAY_JWT_PRIVATE_KEY；公钥 base64url raw32 只进新网关 vars.RELAY_JWT_PUBLIC_KEY。
  2. 私钥落一份离线备份（密码管理器），丢失则所有存量票据作废（可重建，但需重签两端）。
  3. 给 account-worker 补 relay token 单测（签发 → 验签闭环），当前覆盖为零。

阶段 1 · 网关上线（纯 HTTP 上游，先不碰 NAS）

  1. 新建私有仓库 qmai-gateway，把 qmai-relay/ 的 auth.ts/forward.ts（20 个测试已验证）迁入并扩展为多上游。
  2. qmai.work NS 指向新 Cloudflare 账号 → Workers & Pages → Connect to Git → 选该私有仓库。
  3. 建 D1 qmai-gateway-db，执行 0001_init.sql，写入前两条路由（硅基流动 + New API）。
  4. 配 secret：UPSTREAM_SILICONFLOW_KEY、UPSTREAM_NEWAPI_BASE_URL、UPSTREAM_NEWAPI_KEY；配 vars：RELAY_JWT_PUBLIC_KEY、ALLOWED_USER_IDS、APP_ALLOWED_ORIGINS。
  5. workers_dev=false，只走 relay.qmai.work；验收：/health 200、无票 401、真票流式成功。

阶段 2 · NAS 接入 Agent2API

  1. NAS 上 docker run Agent2API（/data 卷持久化），面板注册管理员，建一把网关 Key。
  2. cloudflared 隧道 → a2a.qmai.work；NAS 侧用 X-Relay-Secret 校验（由隧道前置或面板反代实现）。
  3. 网关加 UPSTREAM_A2A_BASE_URL + UPSTREAM_A2A_KEY + UPSTREAM_A2A_SECRET，插入 a2a 路由并把 priority 设成 1。
  4. 验收：断开 NAS → 同一模型自动落到第二跳；恢复后回到第一跳。

阶段 3 · 客户端接线

  1. src/components/settings/llm-presets.ts 增 qmai-relay 预设（显示"内置模型"）。
  2. 把 src/lib/relay-gateway.ts 接入聊天链路（当前零调用点），模型清单走 relay 的 /v1/models。
  3. src/lib/has-usable-llm.ts 增加"已登录即可用"分支；未登录时给出登录引导。
  4. 验收：新装客户端 → 登录 → 直接写出一章 3000 字，全程不填 Key。

13. 风险与对策

风险后果对策
Agent2API 免费额度失效/封号第一跳不可用降级链 + 健康探测；免费额度只当省钱层，不作唯一来源
违反 Agent2API 附加声明法律与社区风险严格内部自用；不对外分发、不售卖、不批量养号
Workers 免费 10ms CPU长文流式被 1102 掐断先实测；必要时升 Paid（$5/月）
请求量超免费额度限流/超额千级活跃用户前升 Paid；D1 只写汇总行
NAS 掉线第一跳消失隧道自动重连 + 降级链 + /health 探活
凭证泄露上游被封凭证只在 secret；NAS 只暴露带共享密钥的网关端口，面板端口绑回环
