QMAI Design Spec · 2026-10-25

账号登录与注册
邮箱验证码注册 + 邮箱密码登录

为青幕AI写作补上一套独立、可选、可长期登录的账号身份。首版只解决「注册、登录、保持登录、退出、找回密码」，为后续会员权益留出稳定身份，不改变现有本地写作与模型配置。

状态：已确认，待实现 范围：客户端 + 独立账号 Worker 依赖：Cloudflare Workers / D1 / Resend

01背景与目标

现状：QMAI 是本地优先的写作桌面端，没有软件级账号；唯一的账号入口在「设置 → 内置模型」，那是 New API 网关的用户名/密码体系，与软件身份无关。

这次要补的是软件自己的账号，并且明确只先做登录/注册，为后续会员功能准备身份底座。模型是否可用、写作是否可用，都不由这个账号决定。

目标

  • 用户用邮箱完成注册，邮箱归属由验证码证明。
  • 注册后自动登录；日常登录用邮箱 + 密码，不反复发邮件。
  • 重启客户端仍保持登录；退出登录要能立即失效当前设备会话。
  • 不登录、账号服务不可用时，本地写作与现有模型配置完全不受影响。
  • 账号身份独立于模型网关，后续会员、云同步只依赖稳定的 users.id。

成功标准

  • 新用户 60 秒内完成「收码 → 注册 → 自动登录」。
  • 已登录用户重启应用后无需重新输入密码。
  • 验证码错误、过期、频繁发送、邮箱已注册、密码错误都有明确中文提示。
  • 账号服务宕机或断网时，书架、章节、模型设置照常打开。

02范围

首版做

  • 邮箱验证码注册（6 位，10 分钟有效）
  • 邮箱 + 密码登录（8–128 位）
  • JWT access + 轮换 refresh 的长期登录态
  • 启动静默续期、退出登录
  • 忘记密码 / 验证码重置密码
  • 顶栏账号入口、设置 → 账号页、登录/注册弹窗
  • 账号 Worker、D1 表结构、Resend 发信
  • 频率限制、验证码尝试上限、错误码映射

首版不做

  • 会员套餐、支付、权益判断（只留占位文案）
  • 用登录状态限制模型或写作功能
  • 账号与内置模型网关绑定 / 单点登录
  • 云同步身份、多端数据合并
  • 微信 / GitHub / 手机号登录
  • 登录设备管理页、邮箱换绑、注销账号
  • 用户协议 / 隐私政策页面（上线前单独补）
边界提醒：「忘记密码」虽然不在最初一句话需求里，但登录一旦上线就必须有找回路径；它与注册共用验证码表和发信逻辑，增量很小，因此纳入首版。

03关键决策

决策选择理由
账号定位统一账号，但不强制登录保留本地优先体验；会员功能上线后自然承接，不用改写作入口。
账号后端本仓库新建 Cloudflare Worker + D1与 analytics-worker 同一套部署方式；与 New API 网关解耦，身份可独立演进。
注册方式邮箱 + 验证码 + 设置密码验证码证明邮箱归属；密码让日常登录不依赖邮件送达。
登录方式邮箱 + 密码桌面软件高频登录，邮件成本与可达性风险都更低。
登录态JWT access（15 分钟）+ 轮换 refresh（90 天）日常请求不查库；refresh 可撤销、可检测重复使用。
客户入口顶栏账号图标 + 设置 → 账号登录可发现，但不占导航；未登录不打扰写作。
邮件通道Resend HTTP API接入最快；先适配 QQ / 163 实测，必要时换阿里云 DirectMail。
验证码存储只存哈希，不存明文数据库泄露时不能直接登录用户账号。

04总体架构

QMAI 客户端（React + Tauri）

  • lib/account/api.ts：纯 HTTP，不碰 UI
  • lib/account/session.ts：持久化登录态
  • stores/account-store.ts：全局状态与动作
  • AccountDialog / AccountSection / 顶栏按钮
→

Cloudflare Worker：account-worker

  • /v1/auth/*：发码、注册、登录、续期、退出、重置
  • D1：users / email_codes / sessions / rate_limits
  • Resend：发送验证码邮件
  • WebCrypto：PBKDF2 密码哈希、HS256 JWT

客户端通过 Tauri 的 plugin-http 发起请求（Rust 侧无浏览器 CORS 限制，但 Worker 仍会处理预检，便于浏览器开发模式联调）。账号服务与 qmai-builtin 模型网关完全独立，互不读写对方数据。

请求链路

1

客户端读本地会话；有 refresh token 就静默续期，没有就保持匿名。

2

登录/注册成功后保存 access + refresh + 用户信息，顶栏与设置页同步刷新。

3

需要账号数据的请求带 Authorization: Bearer <access>；401 时续期一次，仍失败则清会话。

4

所有写入 D1 的操作使用参数化 SQL；不拼接用户输入。

05数据模型

四张表覆盖首版全部状态。时间统一用 Unix 秒（INTEGER），邮箱统一小写存储。

users

列类型约束 / 说明
idINTEGER主键自增；对外只暴露这个稳定身份。
emailTEXTNOT NULL UNIQUE；写入前 trim + 小写。
display_nameTEXTNOT NULL；默认取邮箱 @ 前部分。
password_hashTEXT格式 pbkdf2$迭代数$盐$哈希。
statusTEXT默认 active；预留 disabled。
created_atINTEGER注册时间。
updated_atINTEGER资料更新时间。

email_codes

列类型约束 / 说明
idINTEGER主键自增。
emailTEXTNOT NULL。
purposeTEXTregister 或 reset。
code_hashTEXTSHA-256(pepper + email + purpose + code)。
created_at / expires_atINTEGER默认 10 分钟有效。
attemptsINTEGER默认 0；达到 5 次作废。
consumed_atINTEGER成功使用后写入；非空即不可再用。
request_ip_hashTEXT哈希后的请求 IP，仅用于审计/限流。

索引：(email, purpose, created_at DESC)，取最近一条有效码。

sessions

列类型约束 / 说明
idTEXTUUID 主键，代表一次设备登录。
user_idINTEGERNOT NULL，关联 users。
family_idTEXT轮换家族；检测到重复使用就整族撤销。
token_hashTEXTNOT NULL UNIQUE；当前 refresh token 的 SHA-256。
previous_token_hashTEXT上一次已轮换 token 的 SHA-256；用于识别「旧 token 被重复使用」。
device_labelTEXT可选，记录登录设备描述。
created_at / last_used_at / expires_atINTEGER90 天滑动有效期，刷新时顺延。
revoked_atINTEGER非空即失效。

索引：(user_id)、(family_id)、(previous_token_hash)。

为什么不是每轮换一次就插一行：access 15 分钟续一次，一天最多 96 次；若每次新行，一年单用户就会积累数万行。这里每个设备只保留一行：刷新时把当前 token_hash 挪到 previous_token_hash，再写入新值。这样既能识别「刚被轮换的旧 token 又出现」，又不会让会话表无限膨胀。

rate_limits

列类型约束 / 说明
bucketTEXT主键，例如 send:email:<hash>、send:ip:<hash>、login:<hash>。
window_startINTEGER当前窗口起点。
countINTEGER窗口内计数。
为什么邮箱验证码不存明文：6 位数字只有一百万种组合，若连同邮箱一起泄露，离线枚举几乎无成本。用服务端 pepper 做 SHA-256 后，攻击者还需要拿到 Worker secret 才能反查。

06接口契约

统一信封：成功 { "success": true, "data": ... }；失败 { "success": false, "code": "...", "message": "..." }。HTTP 状态码只用于语义分类，客户端按 code 映射文案。

POST /v1/auth/send-code

请求：{ "email": "a@b.com", "purpose": "register" | "reset" }
响应：{ "success": true, "data": { "cooldownSeconds": 60 } }
  • 邮箱格式非法 → VALIDATION。
  • 同邮箱 60 秒内重复请求 → RATE_LIMITED。
  • 无论邮箱是否已注册，成功响应一致；已注册的注册请求会改为发送「你已注册，请直接登录」通知，不写入验证码。
  • 开发模式（ENVIRONMENT=development 且 ALLOW_DEV_CODE=true）额外返回 devCode，生产环境绝不返回。

POST /v1/auth/register

请求：{ "email": "a@b.com", "code": "123456", "password": "至少8位", "displayName": "可选" }
响应：{
  "success": true,
  "data": {
    "user": { "id": 12, "email": "a@b.com", "displayName": "a", "createdAt": 1793000000 },
    "accessToken": "eyJ...",
    "accessExpiresAt": 1793000900,
    "refreshToken": "base64url...",
    "refreshExpiresAt": 1800776000
  }
}
  • 邮箱已存在 → EMAIL_TAKEN（HTTP 409）。
  • 验证码错误 / 过期 / 尝试过多 → CODE_INVALID / CODE_EXPIRED / CODE_ATTEMPTS。
  • 密码长度不在 8–128 → VALIDATION。
  • 成功后直接创建会话并返回登录态，客户端不再调用登录接口。

POST /v1/auth/login

请求：{ "email": "a@b.com", "password": "...", "deviceLabel": "Windows 桌面端" }
响应：与 register 相同的登录态结构
  • 邮箱不存在或密码错误统一 INVALID_CREDENTIALS，不暴露账号是否存在。
  • 用户不存在时也执行一次等价的 PBKDF2，避免用响应时间探测账号。
  • 账号 status != active → ACCOUNT_DISABLED。
  • 失败按邮箱 + IP 限流，超限 RATE_LIMITED。

POST /v1/auth/refresh

请求：{ "refreshToken": "base64url..." }
响应：新的登录态结构（access + 轮换后的 refresh）
  • refresh 不存在 / 已撤销 / 已过期 → INVALID_REFRESH。
  • 提交的哈希命中某设备的 previous_token_hash → 判定泄露，撤销该 family_id 下全部会话。
  • 每次成功刷新都生成新 refresh：当前 token_hash 挪到 previous_token_hash，再写入新哈希；同一设备仍只占一行。

POST /v1/auth/logout

请求：{ "refreshToken": "base64url..." }
响应：{ "success": true, "data": null }

幂等：token 不存在或已失效也返回成功，避免客户端反复重试。

GET /v1/auth/me

请求头：Authorization: Bearer <accessToken>
响应：{ "success": true, "data": { "user": { ... } } }

仅用于确认登录态与刷新资料；不做会员权益判断。

POST /v1/auth/password/reset

请求：{ "email": "a@b.com", "code": "123456", "password": "新密码" }
响应：{ "success": true, "data": null }

验证码 purpose 必须是 reset；成功后更新密码并撤销该用户全部会话，强制重新登录。

通用约束

项规则
请求体大小≤ 8 KB；超限 VALIDATION。
Content-Type只接受 application/json。
CORS只允许 tauri://localhost、https://tauri.localhost、http://localhost:1420、http://127.0.0.1:1420；预检 204。
缓存所有响应 Cache-Control: no-store。
日志不记录密码、验证码、token 明文；只记事件与错误码。

07注册流程

1

用户打开「注册」页签，填邮箱，点「获取验证码」。

2

客户端先本地校验邮箱格式，再调 send-code；按钮进入 60 秒倒计时。

3

Worker 做邮箱/IP 限流，生成 6 位码，存哈希，调用 Resend 发信。

4

用户填验证码和密码，点「注册并登录」。

5

Worker 校验码 → 检查邮箱唯一 → PBKDF2 哈希密码 → 插入用户 → 创建会话。

6

客户端保存登录态，关闭弹窗，顶栏头像与设置页立即变为已登录。

验证码规则

规则值说明
长度 / 字符集6 位数字用 crypto.getRandomValues，拒绝 Math.random。
有效期10 分钟过期后必须重新获取。
重发冷却60 秒客户端倒计时 + 服务端硬限制。
最多尝试5 次达到后该码作废，需重新获取。
同邮箱频率5 次 / 小时以首次请求为起点的固定窗口计数（rate_limits 只有三列）。
同 IP 频率20 次 / 小时IP 先加盐哈希再存。
新码生效旧码立即作废避免同时存在多个有效码。

密码规则

  • 长度 8–128；不做「必须含大小写/符号」的强制规则，避免弱可用性。
  • PBKDF2-SHA256，随机 16 字节盐，默认 210,000 次迭代；迭代数写进哈希串，后续可升级。
  • 密码只以哈希形式落库；接口和日志都不回显。
运行环境：210,000 次 PBKDF2 需要 Workers Paid（CPU 30 秒）；免费版 10 ms CPU 可能超限。若必须用免费版，把 PASSWORD_ITERATIONS 降到 100,000，并在文档里注明安全权衡。

08登录与续期

登录

1

用户输入邮箱 + 密码，点「登录」。

2

Worker 查用户；不存在也跑一次等价 PBKDF2，再返回统一错误。

3

校验密码 → 检查状态 → 新建 session（新 family）→ 返回 access + refresh。

4

客户端保存并关闭弹窗；失败时保留输入，仅在表单内提示。

续期与失效

  • 客户端启动：读本地 refresh；剩余有效期 > 0 就调 refresh，成功则更新，401 则清会话。
  • 网络失败：保留缓存用户，标记「登录状态待确认」，下次启动/打开账号页再试；不弹阻塞弹窗。
  • 业务请求 401：先续期一次，再重放原请求；仍 401 才退出登录。
  • access 过期前 60 秒主动续期，避免正常操作撞 401。
  • 退出登录：调 logout 撤销当前 refresh，再清本地会话；接口失败也清本地，避免退不出去。
  • 重置密码：撤销该用户全部 session，所有设备重新登录。

忘记密码 / 重置密码

1

登录页点「忘记密码？」，切到重置视图。

2

填邮箱，用 send-code（purpose=reset）获取验证码；已注册与未注册邮箱的成功响应一致。

3

填验证码和新密码，提交 password/reset。

4

成功后服务端撤销该用户全部会话；客户端清理本地会话，回到登录页并提示用新密码登录。

为什么不用「只发长期 JWT」

长期 JWT 无法在服务端撤销，用户点了退出、密码泄露、账号被盗都无法止损；而每次请求都查 D1 的不透明 token 又会把所有接口绑在数据库上。JWT + 轮换 refresh 是这两者之间成本与安全的平衡点。

界面入口

顶栏

  • 未登录：UserRound 图标，aria-label="账号"，悬停「登录 / 注册」。
  • 已登录：首字母圆形头像 + 邮箱提示。
  • 点击打开同一个账号弹窗；不新增导航项。

设置 → 账号

  • 分类放在第一位，图标 UserRound。
  • 未登录：说明 + 「登录 / 注册」按钮。
  • 已登录：邮箱、显示名、注册时间、会员状态「筹备中」、退出登录。
  • 服务不可用：仅在本页显示一条灰色提示，不影响其他设置。

弹窗结构

  • 标题：登录 / 注册两个页签；顶部一句「登录后可继承会员权益（筹备中），不影响本地写作」。
  • 登录：邮箱、密码、登录按钮、「忘记密码？」。
  • 注册：邮箱、验证码 + 获取按钮（60 秒倒计时）、密码（可切换显示）、「注册并登录」。
  • 重置密码：从「忘记密码？」进入，字段为邮箱、验证码 + 获取按钮、新密码、「重置密码」；成功后回到登录页并提示「密码已重置，请用新密码登录」。
  • 错误显示在提交按钮上方，使用 role="alert"；不用 window.alert。
  • 提交中禁用按钮并显示进度文案；回车提交；输入法组合期不误触发。
  • 成功：关闭弹窗 + toast「登录成功」/「注册成功，已自动登录」。

文案要点

场景文案
未登录说明登录青幕账号，会员权益与后续云服务会记在这个账号下。不登录也可以正常写作。
注册成功注册成功，已自动登录。
登录成功登录成功。
退出确认退出后这台设备需要重新登录；本地小说和模型配置不会被删除。

10安全与防刷

风险措施
验证码被爆破6 位码 + 5 次尝试上限 + 10 分钟过期 + 每邮箱/IP 频率限制；错误码不区分「不存在」与「已过期」之外的细节。
邮件接口被刷同邮箱 60 秒冷却、每小时 5 次；同 IP 每小时 20 次；后续可加 Turnstile。
账号枚举send-code 永远返回成功；登录失败统一文案；注册重复邮箱才明确提示。
密码拖库PBKDF2-SHA256 + 随机盐；不存明文；日志脱敏。
refresh 被盗只存哈希；轮换；重复使用撤销整个 family；90 天滑动过期，撤销后立即失效。首版只能检测紧邻的上一个 refresh token，更早 token 重放只失效、不撤族。
JWT 伪造HS256 + 强随机 secret；校验签名、exp、iss；secret 缺失时 Worker 启动即失败关闭。
SQL 注入全部使用 D1 prepared statement 参数绑定；动态 SQL 只拼固定表名/列名。
跨站请求CORS allowlist；非 allowlist 来源不返回 Access-Control-Allow-Origin。
敏感日志不打印密码、验证码、access/refresh；只打印事件名、用户 id、错误码。
本地 token 泄露沿用现有 localStorage 模式，依赖 CSP 限制外链脚本；后续可迁移 OS keychain。

Secrets 管理

  • AUTH_JWT_SECRET：至少 32 字节随机值。
  • AUTH_CODE_PEPPER：至少 16 字节随机值，用于验证码哈希。
  • RESEND_API_KEY：Resend 控制台生成，只放在 Worker secret。
  • 以上均不进仓库、不进客户端构建产物。

12测试与验收

Worker 单测

  • 邮箱/密码/验证码格式校验；密码哈希可验证、盐不同则哈希不同。
  • JWT 签发/校验：过期、签名错误、iss 不符均拒绝。
  • 验证码哈希：同输入稳定、不同 pepper 不匹配。
  • 错误码映射与 CORS 预检响应。

Worker 用例放在 account-worker/test，用该目录自己的 vitest.config.ts（node 环境）运行；根目录 test:mocks 需要排除 account-worker/**，避免 jsdom 环境误跑 Worker 用例。

客户端测试

  • api.spec.ts：请求路径、请求头、错误码 → 中文文案。
  • session.spec.ts：读写、损坏数据回空、清除。
  • account-store.spec.ts：登录成功、刷新轮换、401 清会话、退出幂等、网络失败保留缓存。
  • account-dialog.spec.tsx：空表单校验、验证码倒计时、提交中禁用、错误就近显示、忘记密码切换到重置视图。
  • account-section.spec.tsx：未登录/已登录两种卡片、退出确认。

人工验收

  • 新邮箱收码 → 注册 → 自动登录 → 重启客户端仍登录。
  • 同一邮箱重复注册 → 提示直接登录。
  • 错误验证码 5 次 → 提示重新获取；过期码 → 提示已过期。
  • 60 秒内重复点获取 → 按钮倒计时且接口拒绝。
  • 错误密码 → 表单内提示，不清空邮箱。
  • 退出登录 → 顶栏回到未登录；重启后仍是未登录。
  • 断网打开应用 → 书架正常；账号页只显示离线提示。
  • 重置密码 → 其他设备的旧会话失效。
