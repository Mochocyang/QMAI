# 内置模型改造：从 New API 后端切到自建 qmai.work 中转站

## 一、结论先行

这个分支（`work/independent-20261025`）里的「内置模型」已经**打通了整条 UI → provider 注入 → 写作链路**，
但它接的后端是 **自建 New API 网关**，需要：
- 用户在软件里**再注册一个账号**（`/api/user/register`）
- 网关**自动开一枚 sk- 令牌**（`/api/token/` + `/api/token/{id}/key`）
- 查询**额度与兑换码**（`/api/user/self`、`/api/user/topup`）

而我们现在的 qmai.work 中转站是**另一套模型**：
- 用户已经登录了软件自己的账号（`account.qmai.pro`）
- 不发行长期 sk- 令牌，而是**登录态换 30 分钟 Ed25519 票据**（`POST /v1/relay/token`）
- 没有额度、没有兑换码；**只判断"能不能用"**

所以**不能只改一个默认地址就完事**，要对 `gateway-api.ts` 这一层做"后端适配"。

## 二、现有实现的四个文件各干什么

| 文件 | 职责 | 改造结论 |
|---|---|---|
| `src/lib/builtin-models/gateway-api.ts` (525行) | 纯 HTTP 编排：登录/注册/开通令牌/拉模型/余额/兑换/探活 | **重写数据源**：New API 的 `/api/*` 全部换成我们自己的两个接口 |
| `src/lib/builtin-models/session.ts` (113行) | 本地会话（serverUrl + tokenKey + 额度快照），存 localStorage | **大幅简化**：只留 serverUrl，tokenKey 改成"票据缓存"，额度字段全部去掉 |
| `src/lib/builtin-models/provider-bridge.ts` (155行) | 把会话登记成 `qmai-builtin` provider 写入 llmConfig/默认模型 | **保持不动**（这是最值钱的部分，写作链路零改动） |
| `src/lib/builtin-models/catalog.ts` (195行) | 模型 id → 中文名/上下文/推荐位 | **调整**：按我们自己的对外模型名（`qmai-standard` 等）重写映射 |
| `src/components/settings/sections/builtin-model-section.tsx` (677行) | 设置页「内置模型」页签：登录表单 + 模型勾选 + 余额 | **改流程**：不需要账号密码，改成"用当前登录的 QMAI 账号一键启用" |

## 三、目标链路（改造后的样子）

```
用户在 QMAI 里登录（account.qmai.pro，已有能力）
        │  session.accessToken
        ▼
「内置模型」页签 → 点「启用内置模型」
        │  ① POST account.qmai.pro/v1/relay/token  { Authorization: Bearer <登录态> }
        │     → { token: <30 分钟 Ed25519 票据>, expiresAt }
        │  ② GET relay.qmai.work/v1/models   { Authorization: Bearer <票据> }
        │     → { data: [ { id: "qmai-standard" }, { id: "qmai-long" }, ... ] }
        ▼
applyBuiltinModels({ session: { serverUrl: "https://relay.qmai.work", tokenKey: <票据> }, modelIds })
        │  写入 providerConfigs["qmai-builtin"] / 默认模型 / 生效预设（provider-bridge 现有逻辑）
        ▼
写作请求 → https://relay.qmai.work/v1/chat/completions  (Bearer <票据>)
```

**关键点：票据 30 分钟就过期**，而现有 `provider-bridge` 把 `apiKey` 写死进 provider 配置。
所以必须加一层「**票据保鲜**」：请求前检查 `expiresAt`，快过期就重新换一张并回写配置。
现有 `src/lib/relay-gateway.ts`（main 分支上已有、但目前零调用点）正是干这个的——直接复用它。

## 四、接口对照表（New API → 我们的）

| 现有调用 | New API 路径 | 改造后 |
|---|---|---|
| `gatewayLogin` | `POST /api/user/login` | **删除**（用户用 QMAI 账号登录，不在这里登录） |
| `gatewayRegister` | `POST /api/user/register` | **删除** |
| `gatewayRefreshSession` | `POST /api/user/auth/refresh` | **删除** |
| `gatewayFetchSelf` | `GET /api/user/self` | **删除**（没有额度体系） |
| `ensureBuiltinToken` | `/api/token/*` | **换成** `POST account.qmai.pro/v1/relay/token` |
| `gatewayListModels` | `GET /v1/models`（Bearer sk-） | **保留**，只换 baseUrl + 令牌来源 |
| `gatewayProbeChat` | `POST /v1/chat/completions` | **保留**（验收用，可选） |
| `gatewayPublicStatus` | `GET /api/status` | **删除** |
| `gatewayRedeem` | `POST /api/user/topup` | **删除** |

改造后 `gateway-api.ts` 大约从 525 行缩到 150 行左右——因为我们的大多数能力本来就不需要。

## 五、`session.ts` 的目标形状

```ts
export interface BuiltinSession {
  serverUrl: string      // https://relay.qmai.work
  tokenKey: string       // 30 分钟票据（不是 sk-）
  expiresAt: number      // epoch 秒；快到期就换新的
  userId: number         // 来自登录态，用于白名单对齐
  updatedAt: number
}
```

删掉：`accessToken` / `accessExpiresAt` / `username` / `displayName` / `group` / `quota` / `usedQuota` / `quotaPerUnit` / `usdExchangeRate` / `tokenId`。

| 对外模型名 | 展示名 | 定位 | 上下文 | 输出上限 | 推荐 |
|---|---|---|---|---|---|
| `qmai-standard` | 青幕标准版 | 日常正文续写 | 204800 | 32768 | ✅ |

> 换供应商也不用发版——这是现有设计的核心价值，改造后保持不变。

## 八、风险与取舍

| 风险 | 说明 | 应对 |
|---|---|---|
| 票据只有 30 分钟 | 现有 provider 配置里存的 apiKey 会过期 | 请求前经 `relay-gateway.ts` 保鲜；过期即续 |
| 网关不可达 | 客户端所有写作请求都依赖它 | 保留 BYOK 逃生通道（现有「自定义模型」不受影响） |
| 白名单没配 | 网关侧 `ALLOWED_USER_IDS` 留空 = 全拒 | 上线前把真实 userId 填上 |
| 现有测试依赖 New API 形状 | 改造会大改 `gateway-api.spec.ts` | 先写新测试再改实现（TDD） |
