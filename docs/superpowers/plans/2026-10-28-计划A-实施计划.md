# 计划 A 实施计划 —— 插件平台 v3 · Phase 1 + 2

> 设计依据：`docs/superpowers/specs/2026-10-28-插件平台v3-设计.md`（决策 D1–D9）
> 基线：`9cb0a6c2`
> 目标：**装一个灵感包 → 点一个生成器 → 拿到结果并写回项目**，全程宿主渲染、不跑第三方代码。

---

## 0. 三条贯穿全程的硬约束

1. **Tier 1 插件不启动进程**（D1）。纯 `contentPacks`/`actions` 插件 `processState` 恒为 `"declarative"`。
2. **写项目只走枚举**（D2/D9）。不存在任何"写任意路径"的通道。
3. **`preview` 只用于展示**，调用真源仍是运行期（v2 的 D2 决策不破）。

## 1. 工作拆解与并行边界

| # | 工作 | 层 | 目录/文件 | 可与谁并行 |
|---|---|---|---|---|
| **A1** | 清单 schema 3 + 配置引擎 + 静态声明 | Rust | `plugins/manifest.rs`、`plugins/config.rs`(新)、`plugins/mod.rs` | 独立 |
| **A2** | 内容包解析与索引 | Rust | `plugins/content.rs`(新)、`plugins/mod.rs` | **依赖 A1** |
| **A3** | 项目读写补通 | Rust | `plugins/host_api.rs`、`plugins/mod.rs` | **依赖 A1**（同 mod.rs，串行） |
| **A4** | 修 4 个缺陷 | Rust | `plugins/mod.rs`、`plugins/providers.rs`、`plugins/supervisor.rs` | **依赖 A1**（同 mod.rs，串行） |
| **B1** | 声明式引擎（纯逻辑） | TS | `src/lib/plugins/declarative/*`（新目录） | 独立 |
| **C1** | 插槽注册表 + 6 个挂载点 + 对话框 | TS | `src/lib/plugins/slots.ts`、`src/components/plugins/*`（新） | 依赖 B1 接口（见 §3） |

**并行策略**：
- 第一批：**A1 ∥ B1**（一个 Rust 主干、一个纯 TS，零文件重叠）
- 第二批：**A2 → A3 → A4**（全部碰 `mod.rs`，必须串行）∥ **C1**
- 第三批：接线（前端调真实命令）+ 端到端验收

清单顶层新增：

```rust
pub struct PluginManifest {
    // ... 既有
    pub config_schema: Option<serde_json::Value>,   // JSON Schema 子集
    pub preview: Option<serde_json::Value>,         // 免执行发现
    pub slots: Vec<String>,                         // 声明要放的插槽
    pub requires_slot: HashMap<String, u32>,        // 插槽版本
}
```

`schema` 接受 **1 | 2 | 3**；`CURRENT_SCHEMA = 3`。`contentPacks`/`actions` 出现在 schema < 3 时 → `E_V3_REQUIRES_SCHEMA_3`。

### 2.2 校验（新增错误码）

| 检查 | 错误码 |
|---|---|
| schema < 3 却声明 contentPacks/actions/configSchema | `E_V3_REQUIRES_SCHEMA_3` |
| `contentPacks[].file` 不是相对路径 / 含 `..` / 绝对路径 | `E_CONTENT_FILE_INVALID` |
| `contentPacks[].id` 重复 / 不匹配 `^[a-z][a-z0-9-]{0,31}$` | `E_CONTENT_PACK_ID_INVALID` |
| `actions[].id` 同上规则、同插件内唯一 | `E_ACTION_ID_INVALID` |
| `actions[].slot` 不在允许清单 | `E_SLOT_UNKNOWN` |
| `prompt.system` / `prompt.user` 为空 | `E_PROMPT_EMPTY` |
| `slots[]` 或 `requiresSlot` 含未知插槽 | `E_SLOT_UNKNOWN` |
| 声明了 contentPacks 但包体积 > 5MB | `E_CONTENT_PACK_TOO_LARGE` |

**允许的插槽常量**（`SLOT_IDS`）：
`chapter-toolbar` `inspiration-browser` `editor-context-menu` `outline-toolbar` `analysis-toolbar` `plugin-center`

**插槽版本常量**（`SLOT_API_VERSIONS`）：当前全部 `1`。

### 2.3 配置引擎（`plugins/config.rs` 新文件）

职责：存、校验、注入。

```rust
/// 每个插件的配置（键值对，值已按 configSchema 校验）
pub struct PluginConfigStore { /* 落盘到 <插件根>/.configs.json */ }

impl PluginConfigStore {
    pub fn load(root: &Path) -> Result<Self, String>;
    pub fn get(&self, plugin_id: &str) -> serde_json::Value;      // 缺失返回 {}
    pub fn set(&mut self, plugin_id: &str, value: serde_json::Value,
               schema: &serde_json::Value) -> Result<(), String>;  // 校验后存
    pub fn save(&self, root: &Path) -> Result<(), String>;
}

/// 按 JSON Schema 子集校验：type / required / enum / minimum / maximum / minLength / maxLength / additionalProperties
pub fn validate_against_schema(value: &serde_json::Value, schema: &serde_json::Value)
    -> Result<(), String>;
```

**密钥处理**（对应设计 §6.3）：
- schema 里标 `"x-qmai-secret": true` 的字段，**不落盘**，存在内存 `Arc<Mutex<HashMap<(pluginId, field), String>>>`
- `<插件根>/.configs.json` 里该字段写 `"__secret__"` 占位
- 注入插件时用内存里的真值组装 `QMAI_CONFIG`

**注入**：`start_plugin` 里 `cmd.env("QMAI_CONFIG", serde_json::to_string(&merged)?)`。

### 3.3 `interpolate.ts`

```ts
export interface InterpolationScope {
  fields: Record<string, unknown>
  config?: Record<string, unknown>
  project?: { bookTitle?: string; bookTags?: string[]; bookIntro?: string; protagonist?: string; setting?: string }
  chapter?: { title?: string; text?: string }
  selection?: string
}

/** {{a.b}} 替换；未知变量替换为空串并记入 missing */
export function interpolate(
  template: string, scope: InterpolationScope
): { text: string; missing: string[] }

/** 抽出模板里引用的所有变量名，供校验器使用 */
export function collectVariables(template: string): string[]

/** 模板是否引用了项目上下文（决定是否需要 fs:project-read） */
export function requiresProjectAccess(template: string): boolean
```

规则：
- `{{name}}` → `fields[name]`
- `{{config.x}}` → `config.x`
- `{{project.x}}` / `{{chapter.x}}` / `{{selection}}` → 对应命名空间
- 数组值join 中文顿号；`undefined/null` → 空串
- 保留 `\{{` 作为字面量转义

### 3.4 `output.ts`

```ts
export type ParsedOutput =
  | { kind: "list"; items: string[]; degraded: false }
  | { kind: "text"; text: string; degraded?: false }
  | { kind: "degraded"; text: string; reason: string }

/** 按 mode 解析模型输出。永不抛错——解析失败降级成 degraded（D3） */
export function parseOutput(raw: string, output: ActionOutput): ParsedOutput
```

规则：
- `list`：按行切、去编号前缀、去空行、去多余引号；`maxItems` 截断；一条都没有 → degraded
- `json`：`JSON.parse` 成功且符合 `output.schema` 的顶层类型 → 转 list/text；失败 → degraded
- `text`：原样

### 3.5 `content-pack.ts`

```ts
/** 解析并校验内容包 JSON；错误带具体 item 索引 */
export function parseContentPack(raw: unknown, decl: { id: string; title: string; maxItems?: number }):
  { ok: true; pack: ContentPack } | { ok: false; errors: string[] }

/** 搜索 + 标签过滤（大小写不敏感，标题/正文/标签都参与） */
export function filterContentItems(items: ContentPackItem[], query: string, tags: string[]): ContentPackItem[]

/** 汇总所有标签及其计数，供筛选器渲染 */
export function collectTags(items: ContentPackItem[]): Array<{ tag: string; count: number }>
```

### 3.6 测试要求

每个文件配 `*.spec.ts`，至少覆盖：
- `normalizeForm`：未知 type 降级、缺 options 的 select、缺 key 的字段被丢弃
- `validateFormValues`：必填、number 的 min/max、maxLength、multiselect 的 maxSelected
- `interpolate`：三个命名空间、缺失变量进 `missing`、数组 join、转义 `\{{`
- `parseOutput`：list 带编号/引号/空行、json 合法与非法、空输出 → degraded
- `content-pack`：缺 id/title/body、重复 id、超 maxItems、filter 命中标题与标签
- `requiresProjectAccess`：含 `{{chapter.text}}` 为 true，纯表单为 false

## 4. C1 · 插槽与界面

### 4.1 插槽注册表（`src/lib/plugins/slots.ts`）

```ts
export const SLOT_IDS = [
  "chapter-toolbar", "inspiration-browser", "editor-context-menu",
  "outline-toolbar", "analysis-toolbar", "plugin-center",
] as const
export type SlotId = (typeof SLOT_IDS)[number]

export interface SlotActionEntry {
  pluginId: string; pluginName: string; action: DeclarativeAction
}
export interface SlotPackEntry {
  pluginId: string; pluginName: string; pack: ContentPack
}

/** 从 PluginSummary[] + 已加载内容包构建插槽内容 */
export function buildSlotIndex(plugins, packs): Record<SlotId, { actions: SlotActionEntry[]; packs: SlotPackEntry[] }>
```

数据来源：`plugins_list()` 的 `preview` + 新增命令 `plugins_actions()` / `plugins_content_packs()` / `plugins_content_pack_items(packId)`。

### 4.2 6 个挂载点

| 插槽 | 落点文件 | 形态 |
|---|---|---|
| `chapter-toolbar` | `src/components/editor/*`（章节编辑页工具栏） | 一排按钮，点击开 ActionDialog |
| `editor-context-menu` | 编辑器右键菜单 | 菜单项 |
| `outline-toolbar` | `src/components/sources/outline-*` | 一排按钮 |
| `analysis-toolbar` | 拆书库页工具栏 | 一排按钮 |
| `inspiration-browser` | 右侧栏/抽屉（新增面板） | 卡片列表 + 搜索 + 标签筛选 |
| `plugin-center` | `plugin-section.tsx` | 自述卡 + 灵感库入口 |

**渲染规则**：插槽内**只渲染宿主组件**（按钮开对话框、面板用宿主卡片），**不加载任何插件 HTML**。

### 4.3 核心组件（`src/components/plugins/`）

| 组件 | 职责 |
|---|---|
| `ActionButton.tsx` | 一个 action 按钮（图标 + 标题 + 来源插件小字） |
| `ActionDialog.tsx` | 表单 → 流式生成 → 结果（chips/markdown）→ targets 按钮 |
| `SchemaForm.tsx` | **通用字段渲染器**（action.form 与 configSchema **共用**） |
| `ContentPackBrowser.tsx` | 内容包浏览 + 搜索 + 标签 + 每条的 actions |
| `ConfigForm.tsx` | 插件配置（复用 SchemaForm），secret 字段特殊处理 |

### 4.4 ActionDialog 状态机

```
idle → (无表单) → running
idle → (有表单) → form → 校验通过 → running
running → 流式追加文本 → 可「停止」
running → done → 展示解析结果 + targets
running → error（超时/模型失败）→ 可重试
```

**targets 执行**：
- `project-field` 且 `confirm: true` → 二次确认
- `insert-at-cursor` → 需要有活跃编辑器，否则禁用并提示
- `clipboard` → 复制 + toast
