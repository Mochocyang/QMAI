WorkBuddy 账号登录（国内版首发）· 实施计划

规格：docs/superpowers/specs/2026-10-27-workbuddy-账号登录-design.md　·　分支：feature/model-settings

给执行者： 每个 Task 独立可验证、独立可提交。严格 TDD：先写失败测试 → 确认它因「未实现」而失败 → 写最小实现 → 跑绿 → 提交。不要一次写完再补测试。

Goal： 用户在「模型设置 → 添加账号」里用自己的 WorkBuddy 国内版账号登录一次，QMAI 就能直接用它名下的模型写作，不需要 API Key、不需要装 CLI。

Architecture： Rust 侧新建 src-tauri/src/workbuddy/ 模块：endpoints（两版常量）→ crypto + accounts（加密落盘）→ login / import / refresh（三条取凭证链路）→ models（/v3/config 目录）→ chat（私有头 + system 注入）→ gateway（进程内 axum，把 WorkBuddy 伪装成普通 OpenAI 供应方）。前端只做三件事：三栏入口 + 登录对话框 + 把登录结果写成一张普通模型卡片；聊天链路一行不改。

Tech Stack： Rust（axum 0.8 / reqwest stream / aes-gcm / tokio net）+ Tauri 2 命令；前端 React 19 + Zustand + vitest。

两条硬约束（违反即返工）： ① 凭证只在 Rust 侧流转，任何 IPC 返回值、日志、错误文案里都不得出现 accessToken / refreshToken 明文； ② 不整体复制 Agent2API 代码（许可冲突），只使用其协议事实（端点、头名、字段、握手顺序），实现自己写。
