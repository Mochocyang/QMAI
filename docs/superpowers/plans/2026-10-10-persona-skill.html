技能库「人物 Skill」实施计划

Goal

在技能库加第 4 个 tab「人物 Skill」：点「提取记忆」时，AI 顺带为本章出场的人物建档（说话方式、判断方式、在意什么……），同一个角色再次出场时继续完善它。用户能打开档案手改，也能用一个绿色复选框把某个角色手动标成「重要人物」——标了之后每章都会重点分析、并且是唯一会生成研究文件的一类角色。

Architecture

一套与「角色灵魂」（CharacterAura）完全隔离的轻量旁路：.qmai/persona-skills/ 下放一个 index.json（已建档人物的元数据，只有几十条）+ 一个 sightings.json（只装还没建档的人物的出场计数）+ 每人一份 <id>/SKILL.md（绿勾人物另有 references/research/）。学习挂在 ingestChapter() 末尾、后台 void 异步、整章所有人物合并成一次 LLM 调用；注入走 context-engine.ts，按档位裁剪后写入新加的独立可选字段 personaSkills（FIELD_PRIORITY = 10.5，排在 characterAuras 之后）。

动手前必须先知道的四件事
  1. 别碰 character-aura.ts。仓库里有三套都叫「角色 skill」的东西：拆书库角色 Skill（绑别人的角色）、写作 Skill 库的「角色」分类（没有人物维度）、角色灵魂 CharacterAura（绑本作人物）。本次一个字节都不改 CharacterAura——它是另一个功能，共用会互相污染。新体系只共享「buildCharacterSoulContext 已经打通注入」这个事实，不共享任何数据结构。
  2. 不额外加缓存层。CharacterAura 那条路的 hasCharacterProfile() 会去扫 3000 个实体正文，所以它有指纹缓存。我们这条路只读 index.json（几十条元数据）做名字匹配，命中后才读那一份 SKILL.md——不要照抄一套缓存，那是多余机制。
  3. 一次调用覆盖整章。D3 的硬指标是「每章 ≤ 1 次 LLM 调用，与出场人数无关」。所以阈值判定必须先在本地做完，把该处理的人物拼进同一条 prompt，绝不能一人一次调用。
  4. ingestChapter 的签名不能动。src/lib/novel/chapter-ingest.spec.ts 用源码字符串断言 export async function ingestChapter；签名一改那条测试就红。挂钩只能写在函数体里。

 *

export type PersonaSkillStatus = "active" | "dormant" | "archived"
export type PersonaSkillMode = "create" | "refine"

/** 定位 → 档位。定位取自 wiki/characters/角色-<定位>-<名>.md 的文件名。 */
export const PERSONA_MAJOR_ROLE_TYPES = ["主角", "男主", "女主", "反派", "导师"] as const

export const PERSONA_MINOR_FIRST_APPEARANCE = 2

 * 没有定位的名字不进档位表，用更保守的门槛：出场满 3 次才按 minor 处理。

/** 再次完善所需的累计出场次数。 */

export function isMajorRoleType(roleType: string): boolean {
  return (PERSONA_MAJOR_ROLE_TYPES as readonly string[]).includes(roleType.trim())
}

export function isMinorRoleType(roleType: string): boolean {
  return (PERSONA_MINOR_ROLE_TYPES as readonly string[]).includes(roleType.trim())
}

export function firstAppearanceThreshold(roleType: string): number {
  if (isMajorRoleType(roleType)) return PERSONA_MAJOR_FIRST_APPEARANCE
  if (isMinorRoleType(roleType)) return PERSONA_MINOR_FIRST_APPEARANCE
  return PERSONA_UNKNOWN_FIRST_APPEARANCE
}

export function refineAppearanceThreshold(roleType: string): number {
  return isMajorRoleType(roleType) ? PERSONA_MAJOR_REFINE_APPEARANCE : PERSONA_MINOR_REFINE_APPEARANCE
}

/** 绿勾一律按 major 注入；其余按定位分档。 */
export function resolvePersonaTier(roleType: string, pinned: boolean): PersonaSkillTier {
  if (pinned) return "major"
  return isMajorRoleType(roleType) ? "major" : "minor"
}

/** 连续多少章未出场决定状态；绿勾永远 active。 */
export function resolvePersonaStatus(
  lastChapter: number,
  currentChapter: number,
  pinned: boolean,
): PersonaSkillStatus {
  if (pinned) return "active"
  const gap = currentChapter - lastChapter
  if (gap >= PERSONA_ARCHIVED_GAP_CHAPTERS) return "archived"
  if (gap >= PERSONA_DORMANT_GAP_CHAPTERS) return "dormant"
  return "active"
}

/** 归一化人物名：去空白与标点、折叠大小写、NFKC。匹配只在归一化空间里做。 */
export function normalizePersonaName(value: string): string {
  return value.normalize("NFKC").toLowerCase().replace(/[\s\p{P}\p{S}]/gu, "")
}

  pinned: boolean
  appearanceCount: number
  mode: PersonaSkillMode
  /**
   * 本轮该「首次生成」研究文件：绿勾人物 + 还没有研究文件。
   * 已经有研究文件的一律不重写 —— 章节学习的提示词只看得到 SKILL.md，
   * 看不到那 6 份研究文件，重写等于用只有本章的素材覆盖掉累积内容。
   */
  withResearch: boolean
}

/**
 * 本轮该对哪些人物做什么，纯函数。
 *
 * 幂等：已建档的人物如果 lastLearnedChapter 已经等于当前章就跳过，重复摄取同一章不会二次烧模型。
 * 未建档的人物不受 lastLearnedChapter 约束 —— 那是有意的 fail-open：没有档案就该建档，
 * 万一有调用方给未建档条目填了 lastLearnedChapter，最坏也只是重复规划一次，不会永久静默跳过。
 *
 * 输入须已按 normalizePersonaName 去重（同名人物传两次会产出两条 plan）。
 */
export function planPersonaSkillRound(
  inputs: readonly PersonaSkillPlanInput[],
  currentChapter: number,
): PersonaSkillPlan[] {
  const plans: PersonaSkillPlan[] = []
  for (const input of inputs) {
    const tier = resolvePersonaTier(input.roleType, input.pinned)
    const withResearch = input.pinned && !input.hasResearch
    if (input.hasSkill) {
      if (input.lastLearnedChapter >= currentChapter) continue
      // 复用 major 首现门槛 = D6「绿勾一票升级为 major」，不是巧合。
      const threshold = input.pinned ? PERSONA_MAJOR_FIRST_APPEARANCE : refineAppearanceThreshold(input.roleType)
      if (input.appearanceCount < threshold) continue
      plans.push({
        characterName: input.characterName,
        aliases: [...input.aliases],
        roleType: input.roleType,
        tier,
        pinned: input.pinned,
        appearanceCount: input.appearanceCount,
        mode: "refine",
        withResearch,
      })
      continue
    }
    const threshold = input.pinned ? PERSONA_MAJOR_FIRST_APPEARANCE : firstAppearanceThreshold(input.roleType)
    if (input.appearanceCount < threshold) continue
    plans.push({
      characterName: input.characterName,
      aliases: [...input.aliases],
      roleType: input.roleType,
      tier,
      pinned: input.pinned,
      appearanceCount: input.appearanceCount,
      mode: "create",
      withResearch,
    })
  }
  return plans
}

读盘要分成两条路，这里是最容易写错的地方

注入路径用宽松读（loadPersonaSkillIndex）：文件不存在或坏 JSON 一律降级成空索引、永不抛。写作时读不出档案只是少一段提示词，绝不能因此弄挂生成。

写入路径用严格读（loadPersonaSkillIndexStrict，仅内部）：必须用 fileExists 区分「文件不存在」与「存在但读不出来」，后者 console.warn + 抛错、拒绝写入。

为什么必须这样分：如果写入路径也用宽松读，坏掉的 index.json 会被读成空索引，紧接着 updatePersonaSkillIndex 把那个空索引原样写回去——用户几十条人物档案的元数据一次性静默消失，全程没有任何警告。严格读的判别式要写成 StrictJsonResult { missing, value }：「文件不存在」与「解析出来是 null」必须分开，混成同一个 null 会让「索引结构不认识」误报在正常的首次创建上。

const UNSAFE_ID_CHARS = /[\\/:*?"<>|\s]/g

/** 全点号的名字：`.` / `..` 是目录引用，绝不能原样当路径的一段。 */
const DOTS_ONLY = /^\.+$/

/** 同步短哈希（FNV-1a）：只在名字含路径非法字符时用来消歧，不承担安全职责。 */
function shortHash(value: string): string {
  let hash = 0x811c9dc5
  for (let i = 0; i < value.length; i += 1) {
    hash ^= value.charCodeAt(i)
    hash = Math.imul(hash, 0x01000193) >>> 0
  }
  return hash.toString(16).padStart(8, "0")
}

/**
 * 有没有路径非法字符。刻意用 replace 而不是 test：
 * UNSAFE_ID_CHARS 带 /g，test 会推进 lastIndex，跨次调用状态泄漏。
 */
function containsUnsafeIdChars(value: string): boolean {
  return value.replace(UNSAFE_ID_CHARS, "") !== value
}

/** 人物名 → 目录名。合法名原样用（便于人肉打开文件夹排查）。 */
export function personaSkillIdFor(characterName: string): string {
  const trimmed = characterName.trim()
  const safe = trimmed.replace(UNSAFE_ID_CHARS, "")
  // 全点号（`.` / `..`）即使「没有非法字符」也必须走哈希分支，否则会穿越一层目录。
  if (safe.length > 0 && safe === trimmed && !DOTS_ONLY.test(trimmed)) return safe
  return `${safe || "persona"}-${shortHash(trimmed)}`
}

/**
 * 磁盘上的 id 一律不信任。index.json 可能被外部改过，id 会直接进路径拼接，
 * 所以任何形状不对的值（含 `..`、路径分隔符、非法字符）都回落到按人名重算的 id。
 */
function safeId(raw: unknown, characterName: string): string {
  const fallback = personaSkillIdFor(characterName)
  if (typeof raw !== "string") return fallback
  const trimmed = raw.trim()
  if (!trimmed) return fallback
  if (DOTS_ONLY.test(trimmed)) return fallback
  if (containsUnsafeIdChars(trimmed)) return fallback
  return trimmed
}

 * 宽松版：**注入路径**（章节生成时读索引）用它，索引损坏也绝不能让写作失败。

async function readJsonOrNull(path: string): Promise<unknown | null> {
  try {
    return JSON.parse(await readFile(path))
  } catch {
    return null
  }

/**
 * 严格读的结果。必须把「文件不存在」和「读出来了但是什么」分开表达：
 * 混成一个 null，调用方就再也分不清「真的没有索引」与「索引坏了」。
 */
interface StrictJsonResult {
  missing: boolean
  value: unknown
}

/**
 * 读 JSON，供**写入前**使用：文件不存在 → `{ missing: true }`；
 * 存在但读不出来 / 不是合法 JSON → console.warn 后抛。
 * 关键在 fileExists：把「没有文件」和「文件坏了」混成一个 null，就会让下一次保存
 * 拿空索引覆盖掉整库元数据。
 */
async function readJsonStrict(path: string): Promise<StrictJsonResult> {
  if (!(await fileExists(path))) return { missing: true, value: null }
  let text: string
  try {
    text = await readFile(path)
  } catch (error) {
    console.warn(`人物 Skill 索引读不出来，已停止写入以避免覆盖：${path}`, error)
    throw new Error(`人物 Skill 索引读不出来，已停止写入以避免覆盖：${path}`)
  }
  try {
    return { missing: false, value: JSON.parse(text) }
  } catch (error) {
    console.warn(`人物 Skill 索引损坏（JSON 解析失败），已停止写入以避免覆盖：${path}`, error)
    throw new Error(`人物 Skill 索引损坏（JSON 解析失败），已停止写入以避免覆盖：${path}`)
  }
}

function asRecord(value: unknown): Record<string, unknown> | null {
  if (!value || typeof value !== "object" || Array.isArray(value)) return null
  return value as Record<string, unknown>
}

function asStringArray(value: unknown): string[] {
  if (!Array.isArray(value)) return []
  return value.filter((item): item is string => typeof item === "string" && item.trim().length > 0)
}

function asNumber(value: unknown, fallback = 0): number {
  return typeof value === "number" && Number.isFinite(value) ? value : fallback
}

function sanitizeMeta(raw: unknown): PersonaSkillMeta | null {
  const record = asRecord(raw)
  if (!record) return null
  const characterName = typeof record.characterName === "string" ? record.characterName.trim() : ""
  if (!characterName) return null
  const roleType = typeof record.roleType === "string" ? record.roleType.trim() : ""
  const pinned = record.pinned === true
  return {
    id: safeId(record.id, characterName),
    characterName,
    aliases: asStringArray(record.aliases),
    roleType,
    // 档位按真源重算，不听磁盘上的值：拼错的 tier 会被静默「升级」成 major = 全字段注入。
    tier: resolvePersonaTier(roleType, pinned),
    pinned,
    status: record.status === "dormant" || record.status === "archived" ? record.status : "active",
    firstChapter: asNumber(record.firstChapter),
    lastChapter: asNumber(record.lastChapter),
    appearanceCount: asNumber(record.appearanceCount),
    createdChapter: asNumber(record.createdChapter),
    lastLearnedChapter: asNumber(record.lastLearnedChapter),
    skillRevision: asNumber(record.skillRevision),
    editedByUser: record.editedByUser === true,
    // 只认显式的 false：字段出现之前写下的老索引按「已有研究文件」处理，
    // 宁可漏生成一轮，也不能重写掉累积的研究内容（见 commit 44c1311）。
    hasResearch: record.hasResearch !== false,
    updatedAt: typeof record.updatedAt === "string" ? record.updatedAt : "",
  }
}

async function loadPersonaSkillIndexStrict(projectPath: string): Promise<PersonaSkillIndex | null> {
  const path = personaSkillIndexPath(projectPath)
  const read = await readJsonStrict(path)
  if (read.missing) return null
  const raw = asRecord(read.value)
  if (!raw || !Array.isArray(raw.skills)) {
    console.warn(`人物 Skill 索引结构不认识，已停止写入以避免覆盖：${path}`)
    throw new Error(`人物 Skill 索引结构不认识，已停止写入以避免覆盖：${path}`)
  }
  if (raw.version !== undefined && raw.version !== 1) {
    console.warn(`人物 Skill 索引版本不认识（version=${String(raw.version)}），已停止写入以避免覆盖：${path}`)
    throw new Error(
      `人物 Skill 索引版本不认识（version=${String(raw.version)}），已停止写入以避免覆盖：${path}`,
    )
  }
  const skills: PersonaSkillMeta[] = []
  for (const entry of raw.skills) {
    const meta = sanitizeMeta(entry)
    if (!meta) {
      console.warn(`人物 Skill 索引里有无法识别的条目，已停止写入以避免覆盖：${path}`)
      throw new Error(`人物 Skill 索引里有无法识别的条目，已停止写入以避免覆盖：${path}`)

  }

/**
 * 按 key 串行的互斥锁。同一章的两次并发摄取、或「学习」与「用户在 UI 上点绿勾」
 * 同时改 index.json 时，靠它保证读-改-写不互相覆盖。
 */
const locks = new Map<string, Promise<unknown>>()

export function withPersonaSkillLock<T>(key: string, task: () => Promise<T>): Promise<T> {
  const previous = locks.get(key) ?? Promise.resolve()
  // 上一个任务无论成功还是失败都要放行下一个（入链的是 catch 过的版本，所以锁不会泄漏），
  // 但绝不能把上一个任务的结果当实参传进来 —— task 声明为零参。
  const next = previous.then(
    () => task(),
    () => task(),
  )
  locks.set(
    key,
    next.catch(() => undefined),
  )
  return next
}

export function __resetPersonaSkillLocksForTesting(): void {
  locks.clear()
}

/**
 * 锁键必须对「指向同一目录的不同写法」等价：`C:/p`、`C:/p/`、`c:/p` 是同一个项目，
 * 各拿一把锁就等于没有锁（并发读-改-写互相覆盖）。Windows 盘符大小写不敏感，一并折平。
 */
export function personaSkillLockKey(projectPath: string): string {
  const normalized = normalizeComparablePath(projectPath)
  return /^[a-zA-Z]:/.test(normalized) ? normalized.toLowerCase() : normalized
}

/** 读-改-写索引。mutate 返回 undefined 表示「没变化」，此时不落盘。 */
export async function updatePersonaSkillIndex(
  projectPath: string,
  mutate: (index: PersonaSkillIndex) => PersonaSkillIndex | void,
): Promise<PersonaSkillIndex> {
  return withPersonaSkillLock(personaSkillLockKey(projectPath), async () => {
    // 读用严格版：索引损坏时这一轮直接失败，而不是拿空索引把整库抹掉。
    const index = (await loadPersonaSkillIndexStrict(projectPath)) ?? { version: 1, skills: [] }
    const next = mutate(index)
    if (!next) return index
    await savePersonaSkillIndex(projectPath, next)
    return next
  })
}

/**
 * 读-改-写候选池。mutate 返回 undefined 表示「没变化」，此时不落盘。
 * 与索引共用同一把锁（见 updatePersonaSkillState 的说明）。
 */
export async function updatePersonaSightings(
  projectPath: string,
  mutate: (sightings: PersonaSkillSightings) => PersonaSkillSightings | void,
): Promise<PersonaSkillSightings> {
  return withPersonaSkillLock(personaSkillLockKey(projectPath), async () => {
    const sightings = await loadPersonaSightings(projectPath)
    const next = mutate(sightings)
    if (!next) return sightings
    await savePersonaSightings(projectPath, next)
    return next
  })
}

export interface PersonaSkillState {
  index: PersonaSkillIndex
  sightings: PersonaSkillSightings
}

/**
 * 在**同一把锁**内一次读两份文件、调 mutate、再只落盘它返回的那几部分。
 *
 * 索引与候选池之间有跨文件不变量（「一旦建档就把它从 sightings 移走」），
 * 两把独立的锁无法保证它 —— 两次并发学习会各自基于同一份计数判定达标。
 * 所以这里与 updatePersonaSkillIndex / updatePersonaSightings 共用同一把锁。
 *
 * mutate 返回 undefined 或空对象表示什么都不写；只返回 { sightings } 时就只写候选池
 * （每章都会变的只有它，没必要连带重写没变化的索引）。返回的是合并后的完整 state。
 * 索引那份的读用严格版：损坏就抛，不许把丢过字段的结果写回去。
 */
export async function updatePersonaSkillState(
  projectPath: string,
  mutate: (state: PersonaSkillState) => Partial<PersonaSkillState> | void,
): Promise<PersonaSkillState> {
  return withPersonaSkillLock(personaSkillLockKey(projectPath), async () => {
    const index = (await loadPersonaSkillIndexStrict(projectPath)) ?? { version: 1, skills: [] }
    const sightings = await loadPersonaSightings(projectPath)
    const patch = mutate({ index, sightings })
    if (!patch) return { index, sightings }
    if (patch.index) await savePersonaSkillIndex(projectPath, patch.index)
    if (patch.sightings) await savePersonaSightings(projectPath, patch.sightings)
    return {
      index: patch.index ?? index,
      sightings: patch.sightings ?? sightings,
    }
  })

export function uniqueNames(values: readonly string[]): string[] {
  const seen = new Set<string>()
  const result: string[] = []
  for (const value of values) {
    const trimmed = value.trim()
    const key = normalizePersonaName(trimmed)
    if (!trimmed || !key || seen.has(key)) continue
    seen.add(key)
    result.push(trimmed)
  }
  return result
}

/**
 * 一次目录列举，从 wiki/characters/角色-<定位>-<名>.md 的文件名读定位。
 * 只解析文件名、不读正文，所以零额外 LLM 成本（D2）。
 */
export async function loadCharacterRoleTypes(projectPath: string): Promise<Record<string, string>> {
  const result: Record<string, string> = {}
  let nodes
  try {
    nodes = await listDirectory(`${normalizePath(projectPath)}/wiki/characters`)
  } catch {
    return result
  }
  for (const node of nodes) {
    if (node.is_dir) continue
    const parsed = parseCharacterRoleFileName(node.name)
    if (!parsed) continue
    // 键必须归一化：文件名里的名字已被 buildCharacterFileName 净化过
    // （sanitizeOutlineFileNamePart 去空白、把 \ / : * ? " < > | 换成 -），
    // 而快照里的 characters 是 LLM 抽出的原始规范名。不归一化的话，
    // 一个叫「Lin Chen」的主角会因为文件里存成「LinChen」而查不到定位 → 静默降成次要档。
    result[normalizePersonaName(parsed.name)] = parsed.role
  }
  return result
}

 */

    const names = [meta.characterName, ...meta.aliases].map(normalizePersonaName)
    return names.some((name) => wanted.has(name))
  })
}

function findSighting(
  sightings: PersonaSkillSightings,
  characterName: string,
  aliases: readonly string[],
): PersonaSkillSighting | undefined {
  const wanted = new Set([characterName, ...aliases].map(normalizePersonaName).filter(Boolean))
  return sightings.sightings.find((item) =>
    [item.characterName, ...item.aliases].some((candidate) => wanted.has(normalizePersonaName(candidate))),
  )
}

/**
 * 把本章出场并进候选池，并汇总出每个人物的累计状态。
 * 已建档的人走 index（不在候选池里），未建档的人走候选池。
 */
export function collectChapterAppearances(
  index: PersonaSkillIndex,
  sightings: PersonaSkillSightings,
  chapter: PersonaChapterInput,
  roleTypes: Record<string, string>,
): { appearances: PersonaChapterAppearance[]; sightings: PersonaSkillSightings } {
  const nextSightings: PersonaSkillSightings = {
    version: 1,
    sightings: sightings.sightings.map((item) => ({
      ...item,
      aliases: [...item.aliases],
      chapters: [...item.chapters],
    })),
  }
  const appearances = new Map<string, PersonaChapterAppearance>()

  const put = (appearance: PersonaChapterAppearance) => {
    const key = normalizePersonaName(appearance.characterName)
    const current = appearances.get(key)
    if (!current) {
      appearances.set(key, appearance)
      return
    }
    appearances.set(key, {
      ...current,
      aliases: uniqueNames([...current.aliases, ...appearance.aliases, appearance.characterName]),
      appearanceCount: Math.max(current.appearanceCount, appearance.appearanceCount),
      firstChapter: Math.min(current.firstChapter, appearance.firstChapter),
      roleType: current.roleType || appearance.roleType,
      hasSkill: current.hasSkill || appearance.hasSkill,
      hasResearch: current.hasResearch || appearance.hasResearch,
      pinned: current.pinned || appearance.pinned,
      lastLearnedChapter: Math.max(current.lastLearnedChapter, appearance.lastLearnedChapter),
    })
  }

  for (const rawName of chapter.characters) {
    const name = rawName.trim()
    if (!name) continue
    const aliases = uniqueNames(chapter.characterAliases?.[name] ?? [])
    const meta = findPersonaSkillMeta(index, name, aliases)
    if (meta) {
      // 同一章重复摄取时 lastChapter 已经是本章，不重复加一
      const alreadyCounted = meta.lastChapter === chapter.chapterNumber
      put({
        characterName: meta.characterName,
        aliases: uniqueNames([...meta.aliases, ...aliases, name]),
        roleType: meta.roleType || lookupRoleType(roleTypes, name) || "",
        appearanceCount: meta.appearanceCount + (alreadyCounted ? 0 : 1),
        firstChapter: meta.firstChapter || chapter.chapterNumber,
        hasSkill: true,
        hasResearch: meta.hasResearch,
        pinned: meta.pinned,
        lastLearnedChapter: meta.lastLearnedChapter,
      })
      continue
    }

    const sighting = findSighting(nextSightings, name, aliases)
    if (sighting) {
      if (!sighting.chapters.includes(chapter.chapterNumber)) {
        sighting.appearanceCount += 1
        sighting.chapters.push(chapter.chapterNumber)
      }
      sighting.firstChapter = sighting.firstChapter || chapter.chapterNumber
      sighting.lastChapter = Math.max(sighting.lastChapter, chapter.chapterNumber)
      sighting.aliases = uniqueNames([...sighting.aliases, ...aliases])
      sighting.roleType = sighting.roleType || lookupRoleType(roleTypes, name) || ""
      put({
        characterName: sighting.characterName,
        aliases: sighting.aliases,
        roleType: sighting.roleType,
        appearanceCount: sighting.appearanceCount,
        firstChapter: sighting.firstChapter,
        hasSkill: false,
        hasResearch: false,
        pinned: false,
        lastLearnedChapter: 0,
      })
      continue
    }

    const created: PersonaSkillSighting = {
      characterName: name,
      aliases,
      roleType: lookupRoleType(roleTypes, name),
      appearanceCount: 1,
      firstChapter: chapter.chapterNumber,
      lastChapter: chapter.chapterNumber,
      chapters: [chapter.chapterNumber],
    }
    nextSightings.sightings.push(created)
    put({
      characterName: name,
      aliases: created.aliases,
      roleType: created.roleType,
      appearanceCount: 1,
      firstChapter: created.firstChapter,
      hasSkill: false,
      hasResearch: false,
      pinned: false,
      lastLearnedChapter: 0,
    })
  }

  return { appearances: [...appearances.values()], sightings: nextSightings }
}

function normalizeStringRecord(value: unknown): Record<string, string> {
  if (!value || typeof value !== "object" || Array.isArray(value)) return {}
  const result: Record<string, string> = {}
  for (const [key, entry] of Object.entries(value as Record<string, unknown>)) {
    if (typeof entry === "string") result[key.trim()] = entry.trim()
  }
  return result
}

/** 解析模型返回的多人 JSON。根对象不可解析 / 没有 skills 数组时返回 null（整轮跳过）。 */
export function parsePersonaSkillDrafts(
  raw: string,
  plans: readonly PersonaSkillPlan[],
): PersonaSkillDraft[] | null {
  const parsed = parseLlmJsonObject(raw)
  if (!parsed || !Array.isArray(parsed.skills)) return null
  const byName = new Map<string, PersonaSkillPlan>()
  for (const plan of plans) {
    byName.set(normalizePersonaName(plan.characterName), plan)
    for (const alias of plan.aliases) byName.set(normalizePersonaName(alias), plan)
  }
  const drafts: PersonaSkillDraft[] = []
  for (const entry of parsed.skills) {
    if (!entry || typeof entry !== "object" || Array.isArray(entry)) continue
    const record = entry as Record<string, unknown>
    const plan = byName.get(normalizePersonaName(typeof record.name === "string" ? record.name : ""))
    if (!plan) continue
    drafts.push({
      characterName: plan.characterName,
      fields: normalizeStringRecord(record.fields),
      research: normalizeStringRecord(record.research),
    })
  }
  return drafts
}

function stripFrontmatter(markdown: string): string {
  const match = markdown.match(/^---\r?\n[\s\S]*?\r?\n---\r?\n?/)
  return match ? markdown.slice(match[0].length) : markdown
}

function stripDocumentPreamble(markdown: string): string {
  return stripFrontmatter(markdown).replace(/^\s*#\s+.*\r?\n/, "").trim()
}

function renderFieldSections(fields: Record<string, string>, order: readonly string[]): string {
  const blocks: string[] = []
  for (const name of order) {
    const value = (fields[name] ?? "").trim()
    if (!value) continue
    blocks.push(`## ${name}`, "", value, "")
  }
  return blocks.join("\n").trimEnd()
}

/** 把草稿落到 SKILL.md / 研究文件 / index，并把已建档的人从候选池移走。返回真正写入的人数。 */
export async function applyPersonaSkillDrafts(input: ApplyPersonaSkillInput): Promise<number> {
  const appearanceByName = new Map(
    input.appearances.map((item) => [normalizePersonaName(item.characterName), item]),
  )
  const updatedAt = new Date().toISOString()
  const upserts: PersonaSkillMeta[] = []

  for (const plan of input.plans) {
    const draft = input.drafts.find(
      (item) => normalizePersonaName(item.characterName) === normalizePersonaName(plan.characterName),
    )
    if (!draft) continue
    if (Object.values(draft.fields).every((value) => !value.trim())) continue

    const existing = findPersonaSkillMeta(input.index, plan.characterName, plan.aliases)
    const id = existing?.id ?? personaSkillIdFor(plan.characterName)
    const appearance = appearanceByName.get(normalizePersonaName(plan.characterName))
    const previousDocument = existing ? await readPersonaSkillDocument(input.projectPath, id) : ""

    await writePersonaSkillDocument(
      input.projectPath,
      id,
      renderPersonaSkillDocument({
        characterName: plan.characterName,
        aliases: existing ? uniqueNames([...existing.aliases, ...plan.aliases]) : plan.aliases,
        roleType: plan.roleType || existing?.roleType || "",
        tier: plan.tier,
        pinned: plan.pinned,
        appearanceCount: Math.max(plan.appearanceCount, existing?.appearanceCount ?? 0),
        firstChapter: existing?.firstChapter || appearance?.firstChapter || input.chapterNumber,
        lastChapter: input.chapterNumber,
        chapterNumber: input.chapterNumber,
        fields: draft.fields,
        existing: previousDocument,
        editedByUser: existing?.editedByUser ?? false,
      }),
    )

    let hasResearch = existing?.hasResearch ?? false
    if (plan.withResearch && Object.keys(draft.research).length > 0) {
      const written = await writePersonaSkillResearch(input.projectPath, id, draft.research)
      if (written.length > 0) hasResearch = true
    }

    upserts.push({
      id,
      characterName: plan.characterName,
      aliases: uniqueNames([...(existing?.aliases ?? []), ...plan.aliases]),
      roleType: plan.roleType || existing?.roleType || "",
      tier: plan.tier,
      pinned: plan.pinned,
      status: "active",
      firstChapter: existing?.firstChapter || appearance?.firstChapter || input.chapterNumber,
      lastChapter: input.chapterNumber,
      appearanceCount: Math.max(plan.appearanceCount, existing?.appearanceCount ?? 0),
      createdChapter: existing?.createdChapter || input.chapterNumber,
      lastLearnedChapter: input.chapterNumber,
      skillRevision: (existing?.skillRevision ?? 0) + 1,
      editedByUser: existing?.editedByUser ?? false,
      hasResearch,
      updatedAt,
    })
  }

  if (upserts.length === 0) return 0

  // 「插进 index」与「从候选池移走」必须原子：分两次写的话，中间崩溃会让人物
  // 同时留在两个文件里，违反 D7「sightings 只记还没建档的人」。所以走一个入口。
  await updatePersonaSkillState(input.projectPath, (state) => {
    const skills = [...state.index.skills]
    for (const meta of upserts) {
      const position = skills.findIndex((item) => item.id === meta.id)
      if (position >= 0) skills[position] = { ...skills[position], ...meta }
      else skills.push(meta)
    }

    const createdIds = new Set(upserts.map((meta) => normalizePersonaName(meta.characterName)))
    const sightings = state.sightings.sightings.filter(
      (item) => !createdIds.has(normalizePersonaName(item.characterName)),
    )

    return {
      index: { version: 1, skills },
      sightings:
        sightings.length === state.sightings.sightings.length
          ? state.sightings
          : { version: 1, sightings },
    }
  })

  return upserts.length
}

/**
 * 章节摄取后的后台学习入口。永不抛：外层兜住一切，只 warn。
 * 只处理「本章出场、且达到门槛」的人物，整轮只发一次 LLM 请求。
 */
export async function learnPersonaSkillsFromChapter(options: LearnPersonaSkillsOptions): Promise<void> {
  const pp = normalizePath(options.projectPath)
  const { chapter, llmConfig, signal } = options
  if (chapter.characters.length === 0) return

  const roundKey = `${pp}#${chapter.chapterNumber}`
  if (inFlightRounds.has(roundKey)) return
  inFlightRounds.add(roundKey)

  try {
    const roleTypes = await loadCharacterRoleTypes(pp)
    // 候选池是纯计数，先落盘：即使后面模型失败，下场也还能接着数。
    // 走 updatePersonaSkillState：读两份 + 计数 + 只写 sightings 全在同一把锁内，
    // 这样并发的另一次学习不会把这里的计数覆盖掉。
    // index 顺手从同一次锁内快照里捞出来，供后面查「这个人是否已建档」——
    // 权威写入在 applyPersonaSkillDrafts 里会于锁内重读，这里只用于按名字找 id。
    let appearances: PersonaChapterAppearance[] = []
    let index: PersonaSkillIndex = { version: 1, skills: [] }
    await updatePersonaSkillState(pp, (state) => {
      // 注意：mutate 必须是同步的，别在这里 await（会拖住候选池落盘）。
      index = state.index
      const collected = collectChapterAppearances(state.index, state.sightings, chapter, roleTypes)
      appearances = collected.appearances
      return { sightings: collected.sightings }
    })

    const plans = planPersonaSkillRoundForChapter(appearances, chapter.chapterNumber)
    if (plans.length === 0) {
      await refreshPersonaSkillStatuses(pp, chapter.chapterNumber)
      return
    }

    if (!hasUsableLlm(llmConfig, useWikiStore.getState().providerConfigs)) {
      console.warn("[Persona Skill] 提取模型不可用，跳过本轮人物 Skill 学习")
      return
    }

    const existing = new Map<string, string>()
    for (const plan of plans) {
      const meta = findPersonaSkillMeta(index, plan.characterName, plan.aliases)
      if (!meta) continue
      existing.set(plan.characterName, await readPersonaSkillDocument(pp, meta.id))
    }

    const drafts = await requestPersonaSkillDrafts({
      llmConfig,
      chapterNumber: chapter.chapterNumber,
      chapterBody: chapter.chapterBody,
      plans,
      existing,
      signal,
    })
    if (!drafts) {
      console.warn("[Persona Skill] 模型没有返回可解析的 JSON，本轮跳过（不推进 lastLearnedChapter）")
      return
    }

    const written = await applyPersonaSkillDrafts({
      projectPath: pp,
      index,
      appearances,
      plans,
      drafts,
      chapterNumber: chapter.chapterNumber,
    })
    if (written > 0) console.log(`[Persona Skill] 第 ${chapter.chapterNumber} 章更新 ${written} 个人物 Skill`)

    await refreshPersonaSkillStatuses(pp, chapter.chapterNumber)
  } catch (err) {
    console.warn("[Persona Skill] 人物 Skill 学习失败:", err instanceof Error ? err.message : err)
  } finally {
    inFlightRounds.delete(roundKey)
  }
}

为什么这是一个「整理」而不是「再提取」

D6 规定：研究文件在建档那一次调用里顺带产出，所以点绿勾不会增加每章调用次数。但绿勾的典型场景恰恰是「设定很重、前期一直没出场」——这种人物第一次出场时可能素材很薄。所以给 UI 一个手动的「重新整理」按钮，素材取他自己现有的 SKILL.md：只把已有信息拆细、补齐六个文件的骨架，禁止引入档案里没有的新事实。这样既不幻觉，也不需要去读章节快照。

/**
 * 重新整理某人的研究文件。素材只有「他自己现有的档案」——
 * 不读章节快照、不引入新事实，所以这是一次「整理」而不是「再提取」。
 * 永不抛：失败返回 false，由 UI 提示。
 */
export async function regeneratePersonaSkillResearch(options: {
  projectPath: string
  characterName: string
  llmConfig: LlmConfig
  signal?: AbortSignal
}): Promise<boolean> {
  const pp = normalizePath(options.projectPath)
  try {
    const index = await loadPersonaSkillIndex(pp)
    const meta = findPersonaSkillMeta(index, options.characterName)
    if (!meta) return false
    const document = await readPersonaSkillDocument(pp, meta.id)
    if (!document.trim()) return false

    let result = ""
    let streamError: Error | null = null
    await streamChat(
      options.llmConfig,
      buildPersonaSkillResearchMessages({
        characterName: meta.characterName,
        roleType: meta.roleType,
        document,
      }),
      {
        onToken: (token: string) => {
          result += token
        },
        onDone: () => {},
        onError: (error: Error) => {
          streamError = error
        },
      },
      options.signal,
      PERSONA_SKILL_REQUEST_OVERRIDES,
    )
    if (streamError) throw streamError

    const parsed = parseLlmJsonObject(result)
    const research = parsed ? normalizeStringRecord(parsed.research) : {}
    const written = await writePersonaSkillResearch(pp, meta.id, research)
    if (written.length === 0) return false

    await updatePersonaSkillIndex(pp, (current) => ({
      version: 1,
      skills: current.skills.map((item) =>
        item.id === meta.id
          ? { ...item, hasResearch: true, updatedAt: new Date().toISOString() }
          : item,
      ),
    }))
    return true
  } catch (err) {
    console.warn("[Persona Skill] 研究文件重新整理失败:", err instanceof Error ? err.message : err)
    return false
  }
}

import { normalizePath } from "@/lib/path-utils"
import { loadPersonaSkillIndex, readPersonaSkillDocument } from "./persona-skill-store"
import {
  PERSONA_INJECT_CHAR_BUDGET,
  PERSONA_INJECT_FIELD_CHARS,
  PERSONA_INJECT_MAX_SKILLS,
  PERSONA_MAJOR_FIELDS,
  PERSONA_MINOR_FIELDS,
  PERSONA_MIN_SUBSTRING_MATCH_CHARS,
  PERSONA_SUPPLEMENT_HEADING,
  normalizePersonaName,
  type PersonaSkillIndex,
  type PersonaSkillMeta,
  type PersonaSkillTier,
} from "./persona-skill-types"

const TIER_RANK: Record<PersonaSkillTier, number> = { major: 0, minor: 1 }

/** 注入顺序：绿勾 → 主要 → 次要 → 出场次数多的优先（D5）。 */
export function comparePersonaSkillMeta(a: PersonaSkillMeta, b: PersonaSkillMeta): number {
  if (a.pinned !== b.pinned) return a.pinned ? -1 : 1
  if (TIER_RANK[a.tier] !== TIER_RANK[b.tier]) return TIER_RANK[a.tier] - TIER_RANK[b.tier]
  if (a.appearanceCount !== b.appearanceCount) return b.appearanceCount - a.appearanceCount
  return a.characterName.localeCompare(b.characterName, "zh-Hans-CN")
}

/**
 * 名字匹配：精确相等 / 别名命中 / 双向包含。
 * 包含匹配要求两边都 ≥ 2 个字，否则单姓（「林」）会把全库都匹配上。
 * 故意不做拼音与繁简归一：那会把 pinyin-pro / opencc-js 拖过 bundle 边界。
 */
export function matchesPersonaName(normalizedQuery: string, names: readonly string[]): boolean {
  for (const name of names) {
    const normalized = normalizePersonaName(name)
    if (!normalized) continue
    if (normalizedQuery === normalized) return true
    if (normalizedQuery.length < PERSONA_MIN_SUBSTRING_MATCH_CHARS) continue
    if (normalized.length < PERSONA_MIN_SUBSTRING_MATCH_CHARS) continue
    if (normalizedQuery.includes(normalized) || normalized.includes(normalizedQuery)) return true
  }
  return false
}

/** 从 index 里挑出本次该注入的候选：潜伏 / 归档不注入，绿勾例外。 */
export function selectPersonaSkillCandidates(
  index: PersonaSkillIndex,
  matchingText: string,
): PersonaSkillMeta[] {
  const query = normalizePersonaName(matchingText)
  if (!query) return []
  return index.skills
    .filter((meta) => meta.pinned || meta.status === "active")
    .filter((meta) => matchesPersonaName(query, [meta.characterName, ...meta.aliases]))
    .sort(comparePersonaSkillMeta)
    .slice(0, PERSONA_INJECT_MAX_SKILLS)
}

/**
 * 把 SKILL.md 拆成「## 标题 → 正文」。
 * 同名标题会拼接：用户手改过的档案每轮都会追加一个「补充（第 N 章）」段。
 */
export function extractPersonaSkillSections(markdown: string): Map<string, string> {
  const sections = new Map<string, string>()
  let current: string | null = null
  let buffer: string[] = []
  const flush = () => {
    if (current == null) return
    const value = buffer.join("\n").trim()
    if (!value) return
    const previous = sections.get(current)
    sections.set(current, previous ? `${previous}\n${value}` : value)
  }
  for (const line of markdown.replace(/\r\n/g, "\n").split("\n")) {
    const heading = line.match(/^##\s+(.+?)\s*$/)
    if (heading) {
      flush()
      current = heading[1].trim()
      buffer = []
      continue
    }
    if (/^#\s/.test(line)) {
      flush()
      current = null
      buffer = []
      continue
    }
    if (current != null) buffer.push(line)
  }
  flush()
  return sections
}

function truncate(value: string, max: number): string {
  return value.length <= max ? value : `${value.slice(0, max)}…`
}

/** 按档位渲染一条注入块：主要人物 7 段，次要人物只留 2 段。 */
export function renderPersonaSkillBlock(meta: PersonaSkillMeta, document: string): string {
  const sections = extractPersonaSkillSections(document)
  const order = meta.tier === "major" ? PERSONA_MAJOR_FIELDS : PERSONA_MINOR_FIELDS
  const parts: string[] = []
  for (const field of order) {
    const value = (sections.get(field) ?? "").replace(/\s*\n\s*/g, " ").trim()
    if (!value) continue
    parts.push(`${field}：${truncate(value, PERSONA_INJECT_FIELD_CHARS)}`)
  }
  const supplements = [...sections.entries()]
    .filter(([heading]) => heading.startsWith(PERSONA_SUPPLEMENT_HEADING))
    .map(([, value]) => value.replace(/\s*\n\s*/g, " ").trim())
    .filter(Boolean)
  if (supplements.length > 0) {
    const joined = truncate(supplements.join(" "), PERSONA_INJECT_FIELD_CHARS)
    parts.push(`${PERSONA_SUPPLEMENT_HEADING}：${joined}`)
  }
  if (parts.length === 0) return ""
  const tags = [
    meta.tier === "major" ? "主要人物" : "次要人物",
    meta.pinned ? "★重点" : "",
    `出场 ${meta.appearanceCount} 次`,
  ].filter(Boolean)
  return `- 【人物 Skill · ${meta.characterName}（${tags.join(" / ")}）】${parts.join(" ")}`
}

/**
 * 写作上下文用的「人物 Skill」段；没有命中时返回空串。
 * 先只用 index 元数据做名字匹配（几十条，很便宜），命中后才读那一份 SKILL.md。
 */
export async function buildPersonaSkillContext(
  projectPath: string,
  matchingText: string,
): Promise<string> {
  const pp = normalizePath(projectPath)
  if (!matchingText.trim()) return ""

  let index: PersonaSkillIndex
  try {
    index = await loadPersonaSkillIndex(pp)
  } catch {
    return ""
  }
  if (index.skills.length === 0) return ""

  const candidates = selectPersonaSkillCandidates(index, matchingText)
  if (candidates.length === 0) return ""

  const blocks: string[] = []
  let used = 0
  for (const meta of candidates) {
    const document = await readPersonaSkillDocument(pp, meta.id)
    if (!document.trim()) continue
    const block = renderPersonaSkillBlock(meta, document)
    if (!block) continue
    if (used + block.length > PERSONA_INJECT_CHAR_BUDGET) break
    blocks.push(block)
    used += block.length
  }
  if (blocks.length === 0) return ""
  return `【人物 Skill】\n${blocks.join("\n")}`
}

/** 列表顺序：绿勾 → 出场次数多的 → 名字。注入用的顺序在 persona-skill-context.ts，两处口径不同是故意的。 */
function sortMeta(a: PersonaSkillMeta, b: PersonaSkillMeta): number {
  if (a.pinned !== b.pinned) return a.pinned ? -1 : 1
  if (a.appearanceCount !== b.appearanceCount) return b.appearanceCount - a.appearanceCount
  return a.characterName.localeCompare(b.characterName, "zh-Hans-CN")
}

  projectPath: string,
  id: string,
  content: string,
): Promise<PersonaSkillIndex> {
  return withPersonaSkillLock(personaSkillLockKey(projectPath), async () => {
    const index = (await loadPersonaSkillIndexStrict(projectPath)) ?? { version: 1, skills: [] }
    await writePersonaSkillDocument(projectPath, id, content)

      version: 1,
      skills: index.skills.map((item) =>
        item.id === id

          : item,
      ),
    }
    await savePersonaSkillIndex(projectPath, next)
    return next

残余风险与后续

风险本计划里的处置后续可选动作
同名人物共用一个 skill。两个人叫「小二」，会算成同一个人。 v1 接受。collectChapterAppearances 用归一化名字做 key，同名必然合并。 加「按章节共现歧义消解」或让用户在 UI 上手动拆分（指定两个 id）。
自动分档判错。定位来源是文件名，作者可能把重要角色标成「配角」。 绿勾（D6）就是为这个盲点设计的兜底：一次手动点击即可一票升级，并且此后每章重点分析。 让 UI 支持手动改 roleType / tier（当前只读展示）。
后台学习比下一章慢。用户点完「提取记忆」立刻写下一章，可能还读不到刚学到的 skill。 接受。注入端对「档案不存在」是降级而不是报错（空串），不会影响写作。 不需要动：这是一次 LLM 的固有延迟，同步等待反而会让按钮变慢。
模型返回坏 JSON。 整轮 warn 后跳过，不推进 lastLearnedChapter，下次出场自动重试；候选池计数照常落盘，不会白数。 若线上偏多，可把「多人一次」按 N 分批（仍 ≤ 1 次/章的前提下拆成 2 批）。
注入预算被撑满。12 人 × 每段 260 字会顶到 4000 字上限，排在后面的主角可能被截。 排序把绿勾与主要人物排在前面，被截的是次要人物；没有命中就完全不注入。 可给 PERSONA_INJECT_* 开成项目配置项。
用户手改后档案越滚越长。每轮追加一个「补充（第 N 章）」段。 注入端对「补充」做了 260 字截断，且总预算 4000 兜底。 UI 加「合并补充段」（让 AI 把补充内容并进正式字段，仍经用户确认）。
