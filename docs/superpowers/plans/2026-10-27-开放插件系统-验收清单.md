## 1. 准备一个示例插件仓库

在任意目录新建这三份文件，推到你的公开 GitHub 仓库（下面以 `你的账号/hello-plugin` 为例）。
**这个插件故意不依赖任何 SDK**，只用手写 30 行协议，用来证明最小插件可以零依赖。

`plugin.json`
```json
{
  "schema": 1,
  "id": "hello-plugin",
  "name": "Hello 插件",
  "version": "1.0.0",
  "description": "验收用的最小插件：一个工具，返回固定文本",
  "author": { "name": "你的名字", "url": "https://github.com/你的账号" },
  "license": "MIT",
  "runtime": {
    "type": "node",
    "entry": "index.js",
    "args": ["--stdio"],
    "keepAlive": true,
    "startTimeoutMs": 10000
  },
  "inject": ["host.logger"],
  "contributes": {
    "tools": [
      {
        "name": "say_hello",
        "description": "返回一句问候，用于验证插件链路",
        "parameters": {
          "who": { "type": "string", "description": "问候对象", "required": false }
        }
      }
    ]
  },
  "permissions": [],
  "autoStart": true
}
```

`index.js`
```js
#!/usr/bin/env node
// 最小 MCP 服务端：只实现 initialize / tools/list / tools/call。
// 约定：stdout 只写协议帧，日志一律走 stderr（宿主会把 stderr 排空并保留尾部）。
let buffer = ""

function reply(id, result) {
  process.stdout.write(JSON.stringify({ jsonrpc: "2.0", id, result }) + "\n")
}

process.stdin.on("data", (chunk) => {
  buffer += chunk.toString("utf8")
  let nl
  while ((nl = buffer.indexOf("\n")) >= 0) {
    const line = buffer.slice(0, nl).trim()
    buffer = buffer.slice(nl + 1)
    if (!line) continue
    let msg
    try { msg = JSON.parse(line) } catch { continue }

    if (msg.method === "initialize") {
      reply(msg.id, {
        protocolVersion: "2024-11-05",
        serverInfo: { name: "hello-plugin", version: "1.0.0" },
        capabilities: { tools: {} },
      })
    } else if (msg.method === "tools/list") {
      reply(msg.id, {
        tools: [{
          name: "say_hello",
          description: "返回一句问候，用于验证插件链路",
          inputSchema: {
            type: "object",
            properties: { who: { type: "string", description: "问候对象" } },
            required: [],
          },
        }],
      })
    } else if (msg.method === "tools/call") {
      const who = msg.params?.arguments?.who ?? "世界"
      reply(msg.id, { content: [{ type: "text", text: `你好，${who}！` }] })
    } else if (msg.id !== undefined) {
      reply(msg.id, { content: [{ type: "text", text: `未知方法：${msg.method}` }] })
    }
  }
})

process.stderr.write("hello-plugin 已启动\n")
```

`package.json`（GitHub 只是存文件，占位即可，但建议有）
```json
{ "name": "hello-plugin", "version": "1.0.0", "private": true }
```

**先本地自检协议**（不需要装 QMAI）：
```powershell
cd <你放这三个文件的目录>
'{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"say_hello","arguments":{"who":"QMAI"}}}' | node index.js
```
预期输出：`{"jsonrpc":"2.0","id":1,"result":{"content":[{"type":"text","text":"你好，QMAI！"}]}}`

## 3. 已知限制（第一期有意为之，验收时不必当失败）

1. **`source.commit` 存的是 ref 不是 commit SHA**
   GitHub 的 archive zip 顶层目录名是 `repo-ref`，不含 SHA；拿真 SHA 要再打一次 GitHub API，第一期不做。
   责任归属仍可追溯：`repo + ref + zip 的 sha256` 都记在 `.registry.json` 里。

2. **启动失败时界面显示「已停止」而不是「启动失败」**
   `PluginsState` 目前没有「失败态」的存储槽，错误通过「启用」命令的返回值直接报给用户。
   要做到状态列显示 `failed`，需要再加一个 pluginId → 错误 的缓存。

3. **权限只在启用时一次性授予，且第一期固定传空权限数组**
   即「无额外权限」：不能读项目文件、不能联网、不能调 LLM。界面确认层已明确写出这一点。
   逐项勾选需要后端先提供「该插件申请了哪些权限」的接口，属第二期。

4. **停用再启用会清空历史授权**（因为固定传空数组）。第一期没有「部分授权」的概念，影响很小。

5. **插件互相 `inject` 未实现**：`inject` 只认宿主服务（`host.qmai.tools` / `host.logger`）。

6. **`contributes.stages` 只解析不执行**：阶段钩子（在生成前/后插入处理）属第二期。

7. **界面插件（iframe 面板）未实现**：`contributes.panels` 会被解析但不渲染。

8. **`requires.qmai` 不校验**：无 `semver` 依赖，装到不兼容宿主上会在启动阶段失败并显示错误。

9. **同一插件的调用是串行的**：`running` 用整表互斥，一个插件调用最坏 30 秒会阻塞其它插件的列表/启停。
   不会串台（每个插件另有 io 锁），只是吞吐受限。要按插件并行需把 map value 改成 `Arc<AsyncMutex<LaunchHandle>>`。

10. **插件市场索引未做**：第一期只有「粘贴 GitHub 地址安装」。等真实供给出现后再建索引仓库。

# 第二部分：v2.0 —— Provider 插件验收

> **这部分验的是「插件给软件加模型」**，也就是你要的"插件中心能带模型"。
>
> 素材是一个**零依赖的假 provider 插件**，仓库里就有，**不需要推 GitHub**。
> 它不连任何上游，只回固定文本，所以**生成内容是假的**——验的是链路，不是模型质量。
> 预期输出固定为三段：「你好，」「我是假 provider 插件，」「这是一段流式回复。」

## 6. 准备（建议用隔离目录，不碰你的真实数据）

### 6.1 设置隔离的插件目录

```powershell
# 便携版 exe 不读这个变量之外的任何特殊配置；设了它，插件目录就与正式数据隔离
$env:QMAI_PLUGIN_HOME = "$env:TEMP\qmai-plugin-acceptance\plugins"
```

> 不设也可以，那就用真实目录 `%APPDATA%\com.qingmuai.writer\plugins`（§4 有全平台路径）。
> **建议设**，因为下面要手工写 `.registry.json`，隔离目录测坏了直接删掉即可。

### 6.2 放入假插件

```powershell
# <仓库> 换成你实际的仓库路径
$repo = "C:\QMAI_C\worktrees\QMAI-plugins"
$root = $env:QMAI_PLUGIN_HOME
New-Item -ItemType Directory -Force -Path "$root\fake-provider" | Out-Null
Copy-Item "$repo\src-tauri\tests\fixtures\plugins\fake-provider\*" "$root\fake-provider\" -Force
```

### 6.3 手工登记（让它启动时自动拉起）

新建 `$root\.registry.json`，内容：

```json
{
  "version": 1,
  "plugins": {
    "fake-provider": {
      "id": "fake-provider",
      "version": "1.0.0",
      "enabled": true,
      "granted_permissions": ["net:listen"],
      "source": {
        "repo": "local",
        "ref": "local",
        "commit": "local",
        "zip_sha256": "local",
        "installed_at": "2026-10-28T00:00:00Z"
      }
    }
  }
}
```

> **为什么手工写而不是用安装框**：安装器只接受 GitHub 地址，而这个 fixture 在本地。
> 这也**顺带验证了 `autostart_all`**——启动时它会把这个已启用的插件拉起来。
>
> `granted_permissions: ["net:listen"]` 是必需的：provider 要开本机端口。
> 想从"未启用"开始测也行，把 `enabled` 改 `false`，再在界面上点启用。

## 7. 验收条目（v2.0）

### 7.1 自动启动与登记

- [ ] 启动应用 → **设置 → 插件**：列表里有「假 Provider 插件 v1.0.0」，状态是**「运行中」**
- [ ] 任务管理器里能看到一个 `node.exe` 子进程（这是插件本体）

### 7.2 模型出现在设置页与选择器

- [ ] **设置 → 模型设置**：多出一张「假 Provider」卡片，小字标注**「来自插件 fake-provider」**，并且排在**内置 provider 之后**
- [ ] 卡片上有两个按钮：`刷新模型`、`登录/设置`
- [ ] 点 `登录/设置` → 提示**「该插件不需要登录」**（因为这个 fixture 的 `authKind` 是 `none`，不应该出现伪造的登录框）
- [ ] 模型选择器里出现 **2 个**模型：**「好模型」**、**「小窗口模型」**
- [ ] **「缺窗口模型」不出现** —— 它故意没声明上下文窗口，宿主按设计丢弃它（这是**预期行为**，不是 bug）

### 7.3 真的能用来生成

- [ ] 选「好模型」，随便发一句话（比如让它写一段）
- [ ] 输出能出来，且**分三段流式**出现（不是一次性蹦出整段）
- [ ] 生成过程中点**停止** → 立即停下

> **注意**：内容是假插件写死的三段文本，与你的输入无关。这是 fixture 的用途。

### 7.4 停用即摘除

- [ ] 设置 → 插件 → 点**停用** → 状态变「已停止」，`node.exe` 子进程消失
- [ ] 回到模型设置：卡片变为**灰显 + 「未就绪」**（或消失，两种都算通过，记录实际是哪种）
- [ ] 模型选择器里**不再有**「假 Provider」的模型

### 7.5 token 不落盘（安全项）

这一步验的是「插件凭证绝不进磁盘」——v2.0 的硬约束之一。

- [ ] 在隔离目录里全局搜索 provider 的 token：

```powershell
# 先把插件跑起来（7.1 之后），再执行；token 是 uuid 形式
Get-ChildItem -Recurse -File $env:QMAI_PLUGIN_HOME |
  Select-String -Pattern '[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}' |
  Where-Object { $_.Path -notmatch 'fake-provider' }
```

- [ ] **没有输出**（`.registry.json` 里也不该有）
- [ ] 同样搜一下真实数据目录（若你没用隔离目录）：`%APPDATA%\com.qingmuai.writer` 下的设置文件里也不该有

> 说明：`fake-provider` 自己的文件里不含 token（它是从环境变量读的），所以排除该目录。

### 7.6 重启自恢复

- [ ] 完全退出应用再打开 → 插件**自动变回「运行中」**，模型再次出现（不需要你手动启用）

### 7.7 高危确认文案（单独测一次）

- [ ] 把 `.registry.json` 的 `enabled` 改回 `false`，重启
- [ ] 在**设置 → 插件**里点该插件的**启用**
- [ ] 确认层出现的是**红色**的 provider 高危文案，内容是：
  > 该插件会成为你的模型供应商：你对 AI 说的每一句话、以及软件送给 AI 的全部上下文
  > （包括你这本书的设定、剧情和已写正文）都会经过它。它还可能把这些内容发往它自己的上游服务。
  > 请只安装你信任来源的 provider 插件。
- [ ] 同时列出声明的 provider id（`fake-provider`）

## 8. v2.0 的已知限制（不要当失败）

| 限制 | 说明 |
|---|---|
| ~~**没有登录窗口**~~ **已过时（v2.1 已交付）** | 这条限制写于 v2.0：当时 `authKind = browser-login / paste-token / import-file` 的插件**还写不出来**，界面上点「登录/设置」只会提示「登录界面将在后续版本提供」。**现在四种 `authKind` 全部可用**：`none` 无登录入口；`browser-login` 打开受控登录窗口（`65637f2a`，`authDomains` 白名单限域）；`paste-token` 是卡片上的密码框 + 「保存」，`import-file` 是「选择文件」（`fbd89eb4`，≤1MB）。这也是"真正的 WorkBuddy / Qoder / Trae / 小浣熊 插件"最后一块地基——验收见**第五部分**（§19 受控登录窗口 / §19.5 粘贴令牌与导入文件） |
| 凭据型插件不会"记住"你填过的令牌 | 宿主只做一次内存中转：不回填、不落盘、重启后也不会自动带令牌（它真的没存这个值）。要"已登录"体验请同时声明 `settingsPagePath`，在自己页面里展示状态；要持久化，就写到 `/host/status` 返回的 `dataRoot`（即 `<插件根>/<id>.data/`）。详见 §19.5 |
| ~~没有余额 / 签到展示~~ **已过时** | 这条写于 v2.0：当时 `capabilities` 里的 `balance.query` / `checkin` 只在契约里预留、端点未接。**现已接通**（第五部分 §20）：卡片上有「余额」与「每日签到」按钮，宿主把请求代理到插件的 `/v1/_qmai/balance` / `/v1/_qmai/checkin`；能力位没声明就不渲染按钮 |
| 窗口小于 204800 的模型 | 已修（`8c8b26ff` / `69706d44`）：插件声明多少就用多少，不再被用户输入下限抬高。7.2 里「小窗口模型」就是用来验这条的 |

## 16. 钩子（Phase 3）

### 16.1 准备

在任意目录建 `hook-demo/plugin.json`：

```jsonc
{
  "schema": 3,
  "id": "hook-demo",

    ]

  "permissions": []

```

### 16.2 验收条目

**请求前钩子**
- [ ] 换成 `"on": "beforeLlmRequest"` 的钩子（模板里用 `{{text}}` 追加一句风格约束）→ 主聊天发一句话 → 回答确实带上了该约束
- [ ] 停用插件后行为**立刻**回到原样（不需要重启）

**响应后钩子**
- [ ] 上面那个 `afterLlmResponse` 示例：收到回复后**界面上的句号变成了感叹号**
- [ ] 只在**主聊天路径**生效（章节生成等内部调用不生效，见 16.3）

**超时与失败**
- [ ] 把 `timeoutMs` 改成 `1` → 主聊天**仍正常收到回复**（fail-open），日志有超时警告
- [ ] 模板引用不存在的变量 → 仍正常回复

**gate（门禁）**
- [ ] 给钩子加 `"gate": true` 且 `timeoutMs: 1` → 主聊天**报错**（fail-closed）。测完删掉该插件

**工作流钩子**
- [ ] 换成 `"on": "afterChapterDraft"` 的钩子（模板给正文末尾加一行）→ 生成一章 → 最终正文末尾确实有这一行

**观测钩子**
- [ ] `onLlmUsage` 钩子（impl=process + 一个打日志的 tool）→ 聊天后触发，且**不拖慢回复**
- [ ] 观测钩子返回 patch 会被忽略（日志里有警告）

### 16.3 钩子的已知边界（不要当失败）

| 边界 | 说明 |
|---|---|
| `afterLlmResponse` 只在主聊天生效 | 其他调用点把 token 增量追加进自己的累加器，改写无处安放；硬接会正文重复。当前用显式 opt-in，只开了主聊天 |
| 本地 CLI provider（claude-code 等） | `beforeLlmRequest` 生效、`afterLlmResponse` 不生效 |
| 工作流 gate 被阻断 | **中止整个阶段**（管线没有"只中止一段再继续"的语义） |
| `afterLlmResponse` 的 gate 被忽略 | 正文已流到界面，此时阻断只会让用户丢掉已看到的回复 |
| 同 priority 多钩子 | 按 pluginId 字典序，顺序确定 |
| 并发请求 | 重入保护是模块级计数器（WebView 无 AsyncLocalStorage），钩子执行期间的并发请求也会跳过钩子链 |

# 第五部分：Tier 2 收尾验收（Phase 5）

> 本部分把「**要登录的**模型渠道插件」打通——也就是 WorkBuddy / Qoder / Trae / 小浣熊 这类插件的最后一块地基。

## 19. 受控登录窗口

### 19.1 准备一个 provider 插件

用仓库里的假 provider 改造：在它的 `plugin.json` 的 `providers[0]` 里加三项：

```jsonc
"authKind": "browser-login",
"settingsPagePath": "/login",
"authDomains": ["example.com"]
```

并在 `index.js` 里加一个 `GET /login` 返回一小段 HTML（随便写「这是设置页」即可）。

> 这个 fixture 的 `/login` 目前不存在——所以**第一轮测应该先看到「窗口打开但页面 404」**，这本身就是在验证窗口真的打开了。

### 19.2 验收条目

**打开窗口**
- [ ] 模型设置里「登录/设置」按钮**可点**（此前这里只会得到一句"以后再说"的占位提示，现在真的会开窗口）
- [ ] 点击 → 弹出一个独立窗口，标题含插件名，加载的是 `127.0.0.1:<端口>/login`
- [ ] **窗口数据是隔离的**：新开一次登录，上一步的 Cookie 不会带过去（这是"加第二个账号"能用的前提）
- [ ] 登录期间按钮显示「打开中…」，不能重复点

**白名单（最关键的安全项）**
- [ ] 在窗口里手动导航到**清单未声明**的域名（比如 `https://bing.com`）→ **被拦住**
- [ ] 导航到 `authDomains` 里声明的域名或其子域 → 放行
- [ ] 访问 `127.0.0.1` 上的**其它端口**（不是宿主分配的那个）→ 被拦住

**关窗后自动刷新**
- [ ] 关掉登录窗口 → 模型列表**自动刷新**（不需要手动点「刷新模型」）
- [ ] 若插件在登录后新增了模型，关闭窗口后能出现在列表里

## 19.5 粘贴令牌 / 导入文件（paste-token / import-file）

> `browser-login` 靠**受控窗口**（§19）让用户在插件自己的页面里完成登录；另外两种 `authKind`
> 靠**卡片上的一次性输入**把一段文本直接交给插件：`paste-token` 是密码框，`import-file` 是选文件。
> 两者的插件侧契约完全相同——固定端点 `POST /login/credential`，清单里不用声明路径（设计 §5.3）。

### 准备

把 fixture 的 `providers[0].authKind` 改成 `paste-token`（或 `import-file`），并在它的 `index.js` 里加：

```text
POST /login/credential
  → 校验 Authorization: Bearer <QMAI_PROVIDER_TOKEN>
  → 读 body 的 {kind, value, filename}
  → 回 {"ok": true, "message": "登录成功"}
```

> 失败要回非 2xx：QMAI 把「状态码 + 响应体前 200 字」原样显示在卡片上，
> 所以 401（令牌不对）与 404（端点没实现）在用户眼里是两件不同的事。

> 用 SDK（`serveProvider`）写的插件**不用手写这个端点**：给 `onCredential({ kind, value, filename })`
> 一个回调就行，401/404/405/400 都由 SDK 统一处理（`f4668a43`）。这一节用 fixture 手写，是为了不依赖 SDK。

> **先别声明 `settingsPagePath`**：凭据型 `authKind` 一旦同时声明了设置页，卡片上仍会多一个
> 「登录/设置」按钮（那是给"既要收令牌、又要有说明页"的插件准备的）——下面的第一条就不成立了。
> §19.1 里为了测窗口加过它，测这一节时把它删掉，或者换一份 fixture。

### 验收条目

- [ ] `authKind = paste-token` 时，卡片上出现**密码框 + 「保存」**，**不出现**「登录/设置」按钮
- [ ] 输入一段文字点保存 → 显示插件返回的 message
- [ ] **保存后输入框被清空**（凭证不该留在界面上）
- [ ] 重新打开设置页 → 输入框是**空的**（宿主不回填：它真的没存这个值）
- [ ] 空输入时「保存」按钮是禁用的
- [ ] `authKind = import-file` 时，卡片上是**「选择文件」**按钮
- [ ] 选一个 >1MB 的文件 → **直接报错，不会卡住**（宿主先查大小再读内容）
- [ ] 选一个 `.txt` 文件 → 内容被提交，插件收到 `filename` 是真文件名（**不是完整磁盘路径**）
- [ ] 让插件端点返回 401 → 卡片显示插件的错误原文（含状态码）
- [ ] 提交成功后模型列表**自动刷新**（和登录窗口一样，关窗/提交后后端会重抓）

### 已知边界

| 边界 | 说明 |
|---|---|
| 宿主不回填已提交的令牌 | 它真没存。要"已登录"体验请同时声明 `settingsPagePath`，在自己页面里展示状态 |
| 重启后不会自动带令牌 | 要么用户重填，要么插件自己把令牌持久化到 `/host/status` 返回的 `dataRoot`（即 `<插件根>/<id>.data/`） |
| 扩展名不限制 | `.txt/.json/.toml/.yaml/.yml/.conf/.ini` 之外的扩展名会提示一句、**照样提交**，格式校验由插件自己做 |

> **`dataRoot` 就是"插件自己的数据目录"**：`/host/status` 现在会返回 `dataRoot`（绝对路径，
> 值即 `<插件根>/<id>.data/`，宿主在建立会话时就保证目录存在）——这是本轮修复新增的字段。
> 插件是子进程，**不要**用 cwd 或 `../<id>.data` 去猜这个路径：插件根可以被 `QMAI_PLUGIN_HOME` 改掉，
> 猜错轻则下次启动读不到，重则根本写不进去（安装目录可能只读）。
> 「宿主不回填」与它是同一件事的两面——宿主手里没有令牌可回填，插件的令牌只该活在你自己的 `dataRoot` 里。

## 20. 余额 / 签到（由 `capabilities` 驱动）

在 `plugin.json` 的 `providers[0].capabilities` 里加 `"balance.query"` 和 `"checkin"`，并让 fixture 实现：

- `POST /v1/_qmai/balance` → `{"items":[{"label":"积分","value":"1,234"}]}`
- `POST /v1/_qmai/checkin` → `{"ok":true,"message":"已签到"}`

### 20.1 验收条目

- [ ] 卡片上出现「余额」按钮 → 点击显示 `积分 1,234`
- [ ] 出现「每日签到」按钮 → 点击显示「已签到」
- [ ] **把 `capabilities` 里的 `balance.query` 删掉重启 → 余额按钮消失**（不渲染灰按钮）
- [ ] 让 `/v1/_qmai/balance` 返回畸形结构（如 `{"items":"不是数组"}`）→ 显示「无法识别」而不是崩

## 21. 模型成本与模态

在 fixture 的 `/v1/models` 里给某个模型加：

```jsonc
"_qmai": { "maxInputTokens": 204800, "maxOutputTokens": 8192,
           "cost": { "input": 2, "output": 8 }, "inputModalities": ["text","image"] }
```

- [ ] 该模型后面显示成本小字（形如 `2/8 /1M tokens`，**单位是每百万 token**）
- [ ] 显示「支持图片」标记
- [ ] 没声明 `cost` 的模型 → **什么都不显示**（不占位）
- [ ] `inputModalities` 含 `image` 的模型，在选择器里被视为支持图片

## 22. 「刷新模型」的门控（一条刻意的决定）

- [ ] 即使 `capabilities` 里**没有** `models.refresh`，「刷新模型」按钮**仍然显示**
- [ ] 理由：`/v1/models` 是 provider 契约的**必需端点**（设计 §3.1），刷新是宿主自己的能力；`models.refresh` 这个能力位仅为向后兼容保留，**不驱动任何 UI**

## 23. Phase 5 的已知边界

| 边界 | 说明 |
|---|---|
| 白名单被拦时用户**能看到提示** | 已实现：宿主收到 `plugin-provider-navigation-blocked` 事件后弹**全局 toast**（`toast.info`，portal 到 body，设置页没打开也看得见），文案说明"这是安全拦截、不是坏了"，并指出需要插件作者在 `authDomains` 里声明。同一 host 3 秒内只提示一次 |
| 想恢复 Google / GitHub 登录入口 | 需要在清单 `authDomains` 里显式声明 `accounts.google.com` 等身份域——这是有意的（白名单必须来自清单） |
| 余额/签到的返回结构 | 宿主只做展示、不理解语义；结构不符就显示"无法识别" |
| `cost` 的货币单位 | 由插件自己定义，宿主不换算、不参与计费 |
| 登录窗口的数据目录 | 每次登录新建、关窗删除 → **登录态不会在窗口之间共享**（这是正确的隔离，但意味着"多账号"要每次重新登录） |
| 关窗后 500ms 才重探活 | 若插件落盘凭证更慢，可能拿到一次失败并写进 `last_error`（日志与事件里可见，不打扰用户；仍可手动点「刷新模型」） |
