## 1. 准备一个示例插件仓库

在任意目录新建这三份文件，推到你的公开 GitHub 仓库（下面以 `你的账号/hello-plugin` 为例）。
**这个插件故意不依赖任何 SDK**，只用手写 30 行协议，用来证明最小插件可以零依赖。

`plugin.json`
```json
{
  "schema": 1,
  "id": "hello-plugin",
  "name": "Hello 插件",
  "version": "1.0.0",
  "description": "验收用的最小插件：一个工具，返回固定文本",
  "author": { "name": "你的名字", "url": "https://github.com/你的账号" },
  "license": "MIT",
  "runtime": {
    "type": "node",
    "entry": "index.js",
    "args": ["--stdio"],
    "keepAlive": true,
    "startTimeoutMs": 10000
  },
  "inject": ["host.logger"],
  "contributes": {
    "tools": [
      {
        "name": "say_hello",
        "description": "返回一句问候，用于验证插件链路",
        "parameters": {
          "who": { "type": "string", "description": "问候对象", "required": false }
        }
      }
    ]
  },
  "permissions": [],
  "autoStart": true
}
```

`index.js`
```js
#!/usr/bin/env node
// 最小 MCP 服务端：只实现 initialize / tools/list / tools/call。
// 约定：stdout 只写协议帧，日志一律走 stderr（宿主会把 stderr 排空并保留尾部）。
let buffer = ""

function reply(id, result) {
  process.stdout.write(JSON.stringify({ jsonrpc: "2.0", id, result }) + "\n")
}

process.stdin.on("data", (chunk) => {
  buffer += chunk.toString("utf8")
  let nl
  while ((nl = buffer.indexOf("\n")) >= 0) {
    const line = buffer.slice(0, nl).trim()
    buffer = buffer.slice(nl + 1)
    if (!line) continue
    let msg
    try { msg = JSON.parse(line) } catch { continue }

    if (msg.method === "initialize") {
      reply(msg.id, {
        protocolVersion: "2024-11-05",
        serverInfo: { name: "hello-plugin", version: "1.0.0" },
        capabilities: { tools: {} },
      })
    } else if (msg.method === "tools/list") {
      reply(msg.id, {
        tools: [{
          name: "say_hello",
          description: "返回一句问候，用于验证插件链路",
          inputSchema: {
            type: "object",
            properties: { who: { type: "string", description: "问候对象" } },
            required: [],
          },
        }],
      })
    } else if (msg.method === "tools/call") {
      const who = msg.params?.arguments?.who ?? "世界"
      reply(msg.id, { content: [{ type: "text", text: `你好，${who}！` }] })
    } else if (msg.id !== undefined) {
      reply(msg.id, { content: [{ type: "text", text: `未知方法：${msg.method}` }] })
    }
  }
})

process.stderr.write("hello-plugin 已启动\n")
```

`package.json`（GitHub 只是存文件，占位即可，但建议有）
```json
{ "name": "hello-plugin", "version": "1.0.0", "private": true }
```

**先本地自检协议**（不需要装 QMAI）：
```powershell
cd <你放这三个文件的目录>
'{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"say_hello","arguments":{"who":"QMAI"}}}' | node index.js
```
预期输出：`{"jsonrpc":"2.0","id":1,"result":{"content":[{"type":"text","text":"你好，QMAI！"}]}}`

## 2. 六条验收 + 常驻四检

### ① 安装（设计 §14.2-1）

1. 打开 **设置 → 插件**
2. 输入框粘贴 `https://github.com/你的账号/hello-plugin`，点安装

**通过判据**
- [ ] 列表出现 `Hello 插件 v1.0.0`
- [ ] 状态显示「已停止」（安装不自动启用，这是刻意的）
- [ ] 来源显示 `你的账号/hello-plugin @<7位>`（当前 `commit` 字段实际存的是 ref，见「已知限制」1）

---

### ② 启用并调用工具（设计 §14.2-2）

1. 点「启用」，阅读确认层文案后确认
2. 到对话页，让模型调 `say_hello`（例如输入「用 say_hello 工具跟 QMAI 打个招呼」）

**通过判据**
- [ ] 插件状态变「运行中」
- [ ] 模型的可用工具列表里出现 `hello_plugin__say_hello`（注意 `-` 变 `_`、双下划线）
- [ ] 调用返回「你好，…」
- [ ] 出现**工具确认弹窗**（插件工具默认 `permission: "confirm"`）

> 若模型不支持工具调用（如 `deepseek-reasoner`、`claude-code` 等），工具会被整体禁用——换一个支持 function calling 的模型再试。

---

### ③ 停用（设计 §14.2-3）

点「停用」，再发一条消息。

- [ ] 状态变「已停止」
- [ ] `hello_plugin__say_hello` 从模型工具列表里消失

---

### ④ 断网安装（设计 §14.2-4）

断开网络，再装另一个插件（或用同一个地址重装到一个新 id 的仓库）。

- [ ] 给出可读错误，包含最后一次失败的原因（不是卡死、不是空白）
- [ ] 界面不崩，可以继续操作

---

### ⑤ 坏清单被拒（设计 §14.2-5）

把 `plugin.json` 的 `version` 改成 `1.2`（非法 SemVer），推到另一个仓库，尝试安装。

- [ ] 拒绝安装
- [ ] 错误信息点名具体错误码 `E_VERSION_INVALID`（在界面的错误条里）

再试这几个，确认错误码对得上：

| 改动 | 预期错误码 |
|---|---|
| 把 `"permissions"` 拼成 `"permissionss"` | `E_JSON_INVALID`（并提示候选字段名） |
| `runtime.entry` 改成 `"../../evil.js"` | `E_ENTRY_INVALID` |
| `runtime.type` 改成 `"ruby"` | `E_RUNTIME_INVALID` |
| 两个工具都用 `say_hello` | `E_TOOL_NAME_INVALID`（提示 duplicate） |

---

### ⑥ 卸载保留数据（设计 §14.2-6）

先让插件写过一次数据（若你没有实现 data 端点，可跳过前一步），再卸载。

- [ ] 插件目录 `<插件根>/hello-plugin/` 被删除
- [ ] 注册表 `<插件根>/.registry.json` 里该条目消失
- [ ] `<插件根>/hello-plugin.data/`（若存在）**被保留**
- [ ] 进程列表里没有残留的 node 子进程

---

### 常驻四检（任务 12）

- [ ] **启用即启动**：启用后任务管理器出现 node 子进程，状态「运行中」
- [ ] **崩溃隔离**：手动结束那个 node 进程 → 主程序不受影响；插件状态变「异常退出」（⚠ 见「已知限制」2）
- [ ] **停用即停止**：停用后 node 子进程消失
- [ ] **重启自启**：启用状态下完全退出应用再打开 → 插件自动变「运行中」，无需手动再启用

## 3. 已知限制（第一期有意为之，验收时不必当失败）

1. **`source.commit` 存的是 ref 不是 commit SHA**
   GitHub 的 archive zip 顶层目录名是 `repo-ref`，不含 SHA；拿真 SHA 要再打一次 GitHub API，第一期不做。
   责任归属仍可追溯：`repo + ref + zip 的 sha256` 都记在 `.registry.json` 里。

2. **启动失败时界面显示「已停止」而不是「启动失败」**
   `PluginsState` 目前没有「失败态」的存储槽，错误通过「启用」命令的返回值直接报给用户。
   要做到状态列显示 `failed`，需要再加一个 pluginId → 错误 的缓存。

3. **权限只在启用时一次性授予，且第一期固定传空权限数组**
   即「无额外权限」：不能读项目文件、不能联网、不能调 LLM。界面确认层已明确写出这一点。
   逐项勾选需要后端先提供「该插件申请了哪些权限」的接口，属第二期。

4. **停用再启用会清空历史授权**（因为固定传空数组）。第一期没有「部分授权」的概念，影响很小。

5. **插件互相 `inject` 未实现**：`inject` 只认宿主服务（`host.qmai.tools` / `host.logger`）。

6. **`contributes.stages` 只解析不执行**：阶段钩子（在生成前/后插入处理）属第二期。

7. **界面插件（iframe 面板）未实现**：`contributes.panels` 会被解析但不渲染。

8. **`requires.qmai` 不校验**：无 `semver` 依赖，装到不兼容宿主上会在启动阶段失败并显示错误。

9. **同一插件的调用是串行的**：`running` 用整表互斥，一个插件调用最坏 30 秒会阻塞其它插件的列表/启停。
   不会串台（每个插件另有 io 锁），只是吞吐受限。要按插件并行需把 map value 改成 `Arc<AsyncMutex<LaunchHandle>>`。

10. **插件市场索引未做**：第一期只有「粘贴 GitHub 地址安装」。等真实供给出现后再建索引仓库。

## 4. 发现问题时请记录这些

报问题时请一并给出（缺了很难定位）：

```
Desktop 版本 / 平台：
插件仓库地址与 ref：
现象（截图或文字）：
界面上的错误文案原文：
错误码（E_XXX）：
<插件根>/.registry.json 里该插件的条目：
应用日志里含 [plugins] 的行（stderr 的尾部 64KB 会打在这里）：
```

`.registry.json` 的位置：
- Windows：`%APPDATA%\com.qingmuai.writer\plugins\.registry.json`
- macOS：`~/Library/Application Support/com.qingmuai.writer/plugins/.registry.json`
- Linux：`${XDG_DATA_HOME:-~/.local/share}/com.qingmuai.writer/plugins/.registry.json`

## 5. 全部通过之后

若六条 + 四检全绿，插件系统第一期即可视为可用。下一步（第二期）的优先级建议：

1. **逐项权限授权**（需要后端补「申请了哪些权限」的接口）——这是能力边界的关键一环
2. **插件更新流程**（不原地覆盖，走「新目录 + 切指针」）
3. **阶段钩子**（`contributes.stages` 真正执行）+ **插件互相 inject**
4. **市场索引**（`awesome-qmai-plugin`，一个插件一个 YAML，沿用 DSH 的投稿模型）
5. **界面插件**（iframe 沙箱 + slot 契约）
