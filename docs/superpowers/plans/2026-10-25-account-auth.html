账号登录与注册 · 实施计划

目标：在 QMAI 中交付可选登录的邮箱账号体系：验证码注册、邮箱密码登录、长期登录态、退出与找回密码；账号服务独立部署，不影响本地写作与现有模型。

架构：Cloudflare Worker + D1 提供 /v1/auth/*；客户端新增纯 HTTP 层、会话持久化、zustand store、账号弹窗与设置页。

技术栈：TypeScript、Cloudflare Workers/D1、WebCrypto、Resend、React 19、Zustand、Vitest、Tauri plugin-http。

规格：docs/superpowers/specs/2026-10-25-account-auth-design.html · 计划日期：2026-10-25

执行方式

本计划按「服务端 → 客户端纯逻辑 → UI → 集成验证」顺序执行。每个任务先写测试，再实现，再跑测试并提交。

外部依赖：Resend 的 RESEND_API_KEY 与已验证发信域名由你提供。代码先支持开发模式（devCode）联调；生产密钥未配置时不得对外发布。

Task 4：八个认证路由 服务端

Create: account-worker/src/auth.ts
Modify: account-worker/src/index.ts（路由、CORS、错误兜底）
  1. send-code：校验邮箱/purpose → 邮箱 60s + IP/邮箱小时限流 → 已注册的 register 发通知不发码 → 生成码、存哈希、发信 → 返回 {cooldownSeconds:60}；开发模式附 devCode。
  2. register：查重 → 取最近未消费码 → 过期/尝试/哈希校验 → 插用户 → 建 session → 返回 bundle。失败码按规格 §11。
  3. login：查用户；不存在也跑一次 PBKDF2；校验密码；status 检查；建新 family session。
  4. refresh：先按当前哈希查；命中则轮换（previous_token_hash = 旧，写入新哈希，expires_at 顺延）；若命中 previous 哈希 → revokeFamily 并返回 INVALID_REFRESH；否则 401。
  5. logout：按 refresh 哈希撤销；幂等返回成功。
  6. me：Bearer 解析 + JWT 校验 + 查用户。
  7. password/reset：purpose=reset 校验 → 更新哈希 → 撤销全部 session。
  8. CORS/路由：OPTIONS 204；只允许 allowlist；未知路由 404；捕获异常返回 SERVER_ERROR，不泄露堆栈。
  9. 本地冒烟：npx wrangler dev --local --port 8787，用 curl 走「发码（开发模式看码）→ 注册 → me → refresh → logout」；记录结果。
  10. 提交：git commit -m "feat(账号): 注册、登录、续期与找回密码路由"
