角色灵魂：可迁移人格实施说明

2026-10-04 · 功能分支：feature/portable-character-soul · 未提交、未合并

角色档案记录“这个人是谁”；角色灵魂描述“在什么情况下，倾向怎样判断、表达和行动”。两者分开保存，不把原型经历改写到用户人物小传中。

当前结论：基础链路已实现，仍是测试版。绑定读取与职业隔离已有实测；模型自动核验有漏判，人工复核仍发现规则泛化和正文过度推断，尚未达到“百分之百严格遵守 Skill”的验收标准。

本轮实施范围

  1. 保留原有角色档案、旧灵魂和上一轮界面调整，不自动迁移或覆盖。
  2. 新生成角色 Skill 改为可迁移人格：按姓名和别名定位上下文，跨章节取样，再仅提炼性格明显的行动、取舍、表达及反例。
  3. 原文证据由程序编号，模型每条规则只选1至2个关键编号；程序回填引文，不让模型改写引文。保存前另做迁移与证据关联核验。格式、证据或迁移核验不合格最多修正一次，仍失败不保存成品。
  4. 文档、预览、编辑和运行时人格来自同一份结构化规则。修改后的原始证据不冒充用户修订规则的证明。
  5. 生成前检查规则是否完整进入上下文及是否与小传冲突；生成后逐条核验。人格专项最多返修一次，不通过不调用最终正文回调。
  6. 运行源码页面、回归和真实模型测试，完成后生成独立便携包。

哪些内容不迁移

原作信息可以提炼的性格倾向不可继承
前世是警察有行为证据时：资料不足先核验，不把猜测当成事实穿越经历、警察身份、刑侦和法医知识
用特殊武技救人紧迫底线下先尝试制止，再承担代价武技、战力、原作胜负结果和原事件
给原作妹妹送礼口头打趣与实际照顾并存原作亲属、亲缘关系、具体礼物和台词

不把单一场景扩大成绝对人格。新人物是账房、普通人或其他职业，不算性格冲突；但“资料不足也必须直接定罪”与“先核验再判断”才可能构成直接冲突。

数据和流程

原文章节 → 人物相关片段 → 原文证据编号 → 条件化人格规则 → Skill / 灵魂字段 → 绑定目标人物 → 完整性与冲突前检 → 正文 → 逐条核验 → 最多一次返修与复检 → 最终正文

规则包含编号、维度、触发条件、行为倾向、例外与边界、证据编号。人格摘要和规则进入写作请求；原作姓名、原文证据、职业和生平不经新灵魂自动注入。

证据、范围和结构化规则嵌入同一个 Skill 文件，重启加载无需额外同步旁路数据。重复生成前保留旧文件到该作品的 skills/history，新内容验证成功后再更新。

五个维度仍沿用软件现有的表达特征、心智模型、决策启发式、价值观反模式、诚实边界。没有证据的维度不强行生成内容。

与对话生成的关系

本轮先建立对话未来调用的可靠底层，不新增聊天窗口。后续对话将把用户需求整理为“目标人物、章节范围、关注的性格问题、预期用途”，调用同一提炼器并形成草稿，而不是直接修改最终灵魂。

建议按三步继续：专题需求输入；带证据的多轮修订；版本确认和替换绑定。每步应单独验收，旧版灵魂与已有小传始终由用户决定是否替换。

对话不应直接把聊天记录注入正文。每次修订应产出规则差异：保留、修改、删除及对应证据，用户确认后再更新绑定版本。优先解决证据可信与误判，再增加聊天界面。

真实试验结果

使用 D:\E\大奉打更人.txt，以 GB18030 解码，选取第1、2、5、6、14、22、28、31、48、102、103章，共38,413字符。生成器再按人物窗口取样，最多18个片段。提炼/独立核验使用当前配置的 deepseek-flash，章节写作使用 gemini-3.8-flash-high；未修改用户持久化模型设置。

检查项实测结果
原文 → 新 Skill → 灵魂 → 绑定“陆衡”链路通过，陆衡仍为无武功、非穿越的账房学徒；原型证据不经新灵魂路径注入写作上下文。
故意混入前世警察、刑侦和法医知识独立核验检出违规。不同职业本身没有被当成人格冲突。
初次完整写作模型判通过，但人工发现凭空新增墨色、钥匙、印章等关键证据。这是漏判，不算内容验收成功。
加强证据边界后复验原失败稿已识别新增事实；调用真实章节恢复流程，触发一次返修并复检，最终回调一次。
返修稿人工复核仍有“练过三年以上行楷”等无依据的确定判断，写作也仍过分贴近查案场景。自动判通过不能代表完全合格，样本保留待后续改进。
规则质量精确引文可核对，但个别摘要与例外仍泛化过度，例如“帮人从不白帮”“无人可倚仗时一定先走”。不应把这份自动样本作为最终人格定论。

实测文件： 自动生成的原始 Skill · 职业迁移反例 · 新增证据漏判复验 · 返修稿（仍需人工复核） · 恢复流程结果。

下一步建议把规则证据进一步拆成“原文观察、有限推断、未知边界”，用固定的反例集检查“冒险程度被改写”“新职业获得专业知识”“用新增事实伪装验证”。优先降低误判和漏判，再开放需求对话。

验收与限制

  • 确定性检查覆盖结构恢复、原文回填、字段一致性、绑定读取、低预算拦截、快速模式前检、返修次数和最终正文回调。
  • 真实样本、模型请求和实际输出保存在本地 许七安新样本；完整快速流程结果单独记录是否通过，失败不算成功。
  • 当前是有上限的代表性取样，不是全书穷尽分析。未包含在片段中的显著行为仍可能遗漏，后续专题检索可进一步改进。
  • 现有“简单提取/六维分析”的前置角色档案流程保留。本轮改变最终角色 Skill 的生成内容，不表示整个拆书流程已经不做前置分析，也不宣称整体费用一定降低；新核验会增加模型调用。
  • 模型仍可能误判人格或证据与规则之间的关联。程序能保证引文来自输入及检查失败不自动完成，不能保证大模型永不偏离。
  • 用户手动改写后的规则明确标记为用户修订，不声称已获得原文证明。
  • 硬检查适用于此次新生成并绑定的可迁移人格，以及软件的章节写作流程；旧版灵魂、普通问答和外部手动写入不因此自动获得同等校验。
  • 当前角色导入仍保留原有同书同角色去重。已经加入灵魂库的旧角色不自动升级，本轮也不默默替换旧绑定。
