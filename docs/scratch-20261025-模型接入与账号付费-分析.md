# QMai 增加「模型选择 + 账号登录 + 付费使用」完整分析

> 面向对象：不熟悉 API、token、网关的读者。
> 结论先行：**你现在已经有模型选择功能了，缺的是「账号 + 收钱 + 你自己的一条模型通道」。**
> 本文只做分析与实施说明，不含代码改动。

## 一、先看清现状：你手里已经有什么

把相关代码读了一遍，事实如下。

| 能力 | 现状 | 位置 |
| --- | --- | --- |
| 选择模型 | **已有**，20 多个内置提供方 | `src/components/settings/llm-presets.ts` |
| 内置了哪些 | DeepSeek、智谱 GLM、Kimi（国内/国际/Coding Plan）、MiniMax、阿里百炼、火山方舟、小米 MiMo、OpenAI、Anthropic、Gemini、Azure、Groq、xAI、NVIDIA、Atlas Cloud、Ollama、各家 CLI | 同上 |
| 自定义接口 | **已有**（中转站、内网、本地都能接） | 同上 + `src/lib/llm-providers.ts` |
| 拉取模型列表 | **已有**（用 Key 向厂商请求 `/v1/models`） | `src/lib/settings-model-list.ts` |
| 模型连通性测试 | **已有** | `src/lib/settings-model-test.ts` |
| 每个功能单独选模型 | **已有**（对话、大纲、拆书、去 AI 味…） | `src/stores/wiki-store.ts` |
| 新手引导（教用户拿 Key） | **已有** | `src/lib/guide/guide-steps.ts` |
| 用户账号体系 | **没有**（只有百度网盘/WebDAV 授权，不是你的账号） | `src/lib/cloud-sync/` |
| 付费 / 额度 / 套餐 | **没有** | — |
| 你自己的服务端 | 只有一个 Cloudflare Worker 收统计 | `src/lib/analytics.ts`、`analytics-worker/` |

**所以：**

```
现在：用户 → 填自己申请的 Key → 直连厂商 → 钱付给厂商
你要：用户 → 登录你的账号 → 买额度 → 你的网关（你持有厂商 Key）→ 上游模型
```

这不是「加几个模型」，这是**多出一套服务端系统**。模型选择那一层，反而是里面最简单、你已经做完的部分。

## 二、四个概念，用自来水打比方

### 1. API Key（密钥）= 水卡

厂商（DeepSeek、智谱）是自来水厂。你去开户、充钱，它给你一张「水卡」（一串 `sk-` 开头的字符）。软件拿着这张卡去取水。

- 卡是谁的，水费就记在谁头上
- 卡泄露 = 别人拿你的卡免费用水，账单还是你的
- 卡可以随时作废重发

### 2. token = 用水量（计价单位）

模型不是按「次」收费，是按 token 收费。token 是模型眼里的「字」。

- 中文大约 **1 个汉字 ≈ 0.6～1 个 token**（各家分词器不同，别记死）
- 你让模型读的内容叫**输入 token**，模型写出来的叫**输出 token**
- 输出通常比输入贵 2～4 倍

一次「写一章 3000 字」的请求，大致是输入 1～3 万 token + 输出 6 千～1 万 token。

### 3. 网关（中转）= 楼下的二次供水 + 水表

水厂不直接给每家每户装表。中间有个泵房：统一从水厂买水，再分给住户，每户装表计费。

你的网关就是这个泵房：

- 对上游：用**你的一张卡**批量买水
- 对用户：每人一个**小水表**（额度），用完就停
- 对账：谁用了多少、成本多少、卖了多少，都在这层能看到

**没有网关，你就没法收钱**——因为用户用的是他自己的卡，钱根本不经过你。

### 4. 卡密（兑换码）= 充值卡

一张写着 `QM-XXXX-XXXX` 的码，用户在你的软件里输入，额度就加到账上。

好处：不需要营业执照、不需要微信商户号、不需要对接支付接口，一天就能上线。适合第一阶段。

## 三、模型到底从哪来（最详细的一节）

**模型不是下载安装的。** 你向厂商申请一个 API Key，充钱，然后通过网络调用它的接口。你卖的是「调用额度」，不是软件。

### 3.1 路线一：官方直连（推荐做主线）

| 平台 | 申请地址 | 注册要什么 | 充值方式 | 特点 |
| --- | --- | --- | --- | --- |
| DeepSeek | `platform.deepseek.com/api_keys` | 手机号，个人可 | 支付宝/微信 | 便宜、中文强，写作主力 |
| 智谱 GLM | `open.bigmodel.cn/usercenter/apikeys` | 手机号，个人可 | 支付宝/微信 | 中文文风好，有免费额度 |
| Kimi（月之暗面） | `platform.moonshot.cn/console/api-keys` | 手机号，个人可 | 支付宝/微信 | 长上下文，适合长文 |
| 阿里百炼 | `bailian.console.aliyun.com` | 阿里云账号 + 实名 | 支付宝 | 模型多，企业采购方便 |
| 火山方舟 | `console.volcengine.com/ark` | 火山账号 + 实名 | 对公/支付宝 | 豆包系列，部分模型要企业资质 |
| MiniMax | `platform.minimaxi.com` | 手机号 | 支付宝/微信 | 有性价比型号 |
| 硅基流动 | `cloud.siliconflow.cn` | 手机号 | 支付宝/微信 | **聚合平台**，一个 Key 多家模型 |

> 以上入口与资质要求以各家官网当前页面为准，平台规则会变。

**通用申请步骤（各家几乎一样）：**

1. 打开官网，手机号注册
2. 完成实名认证（个人身份证即可，多数平台强制）
3. 进「充值 / 费用中心」，充最小金额试水（¥10～50 足够测）
4. 左侧菜单找「API Keys / 密钥管理」
5. 点「创建 API Key」，名字随便起
6. **立刻复制**（多数平台只显示一次），存到密码管理器
7. 回到 QMai：`设置 → 大语言模型 → 添加提供方 → 选对应厂商 → 粘贴 Key → 拉取模型 → 测试`

**关键提醒：**

- Key 不要发微信群、不要截图、不要提交到 GitHub
- 一个平台可以建多个 Key，**给网关单独建一个**，方便日后只吊销它
- 充值前先看「计费说明」，确认输入/输出单价和是否有免费额度

### 3.2 路线二：聚合平台（起步省事）

一个 Key 调几十家模型，自带用量面板。典型：硅基流动、OpenRouter。

- 优点：省去逐个平台开户，模型切换快
- 缺点：加价、稳定性受制于人、**部分上游条款不允许二次转售**、出问题只能等对方
- 建议：**内测期用，正式运营换成官方直连做主通道**

### 3.3 路线三：不要碰的

- 淘宝/群里卖的「共享 Key」「无限量 Key」
- 「逆向接口」「网页版转 API」
- 代充、代开企业账号

风险：随时封号跑路、你的用户数据被第三方看到、上游封禁客户端特征、出了事你承担全部责任。你现在软件里已经有一条提示「当前中转站限制了客户端来源」（`src/lib/settings-model-test.ts`），就是这类渠道的典型症状。

### 3.4 拿到 Key 后怎么验证能用

在 QMai 里（不用写代码）：

```
设置 → 大语言模型 → 添加提供方 → 选厂商 → 填 API Key
→ 点「拉取模型」→ 从列表里点一个模型名 → 点「测试」
```

测试失败时，看错误含义：

| 现象 | 含义 | 怎么办 |
| --- | --- | --- |
| 401 / Unauthorized | Key 错、过期、复制少了字符 | 重新复制，注意前后空格 |
| 402 / 余额不足 | 账户没钱 | 充值 |
| 404 / model not found | 模型名不对 | 用「拉取模型」选，别手打 |
| 429 / rate limit | 请求太频繁 | 等一会；免费额度通常限流严 |
| 超时 / Load failed | 网络不通 | 换网络；国内厂商一般不用代理 |

### 3.5 做写作软件，先选哪几个模型

别一上来上十个。先两个：

- **主力**：DeepSeek —— 便宜、中文好、写长文稳定，适合 90% 的章节生成
- **备选**：智谱 GLM 或 Kimi —— 文风更「人味」，适合精修正文

**硬指标**：上下文 ≥ 128K（要能塞进设定+大纲+前文），最大输出 ≥ 8K（一章 3000 字约 6K token）。低于这个的模型，写长篇会不断截断。

### 3.6 你提到的「mini」「K3」怎么处理

这类名字通常是**产品命名**，不是上游真实模型名。做法是维护一张映射表：

| 你展示给用户的名字 | 上游真实模型 ID | 上游厂商 |
| --- | --- | --- |
| QMai 写作标准版 | `deepseek-chat` | DeepSeek |
| QMai 写作增强版 | `glm-4.6` | 智谱 |
| QMai 长文版（K3） | `kimi-k2-...` | Kimi |
| QMai 轻量版（mini） | 某个便宜小模型 | 硅基流动 |

好处：换模型、调价、上新，**都不用发新版本客户端**。这张表放在网关里，是整个方案最值钱的设计。

## 四、为什么不能直接把 Key 发给用户

这是新手最容易犯的错。五个理由：

1. **Key 打进客户端 = 公开**。桌面软件能被拆包，Key 十有八九当天就出现在各种「免费 API」群里。
2. **一个 Key 多人用会被厂商限流甚至封号**，你的所有用户一起挂。
3. **无法计量**。你不知道谁用了多少，就没法定价、没法防薅。
4. **无法收费**。用户直接用你的 Key，钱不经过你。
5. **无法换模型/降级**。想让某个用户用便宜模型、或者临时切备用通道，做不到。

网关解决的就是这五件事。

### 六个部件各自要干什么

| 部件 | 职责 | 一句话 |
| --- | --- | --- |
| 网关 | 鉴权、扣额度、路由、透传、记账、限流 | 唯一收钱的地方 |
| 账号服务 | 注册、登录、令牌刷新、找回密码 | 知道「你是谁」 |
| 订单/卡密 | 生成卡、兑换、绑定、过期 | 知道「你付了多少」 |
| 额度账本 | 每次变动都记账，可对账 | 知道「你还剩多少」 |
| 管理后台 | 加渠道、看用量、封号、补额度 | 你自己用的 |
| 客户端 | 登录页、模型列表、余额显示 | 用户看到的 |

### 三条技术选型

| | A. 现成开源网关 | B. 云函数自建 | C. 全自研 |
| --- | --- | --- | --- |
| 用什么 | `new-api` / `one-api`（Docker 部署） | Cloudflare Workers + D1 | Node/NestJS + Postgres + Redis |
| 账号/额度/兑换码 | **全都有** | 要自己写 | 要自己写 |
| 工作量 | 最小，1～3 天能跑 | 中，1～2 周 | 大，1～2 个月 |
| 可控性 | 中 | 高 | 最高 |
| 风险 | 开源项目漏洞、被扫描 | 支付/账号要自建 | 工期长 |
| 适合 | **第一阶段** | 你已有 Worker 经验 | 日活上千后 |

**推荐路径：A → C。** 先用开源网关验证有没有人付钱；等业务成立、开源项目开始拖后腿，再自研替换网关（客户端协议不变，替换成本可控）。

## 六、阶段 0：一周开卖（不改客户端一行代码）

目的只有一个：**验证有没有人愿意为你的额度付钱。**

### 6.1 买服务器

- 2 核 4G、40G 硬盘足够，国内厂商约 ¥60～100/月
- 系统选 Ubuntu 22.04 / 24.04
- 地域：主要用户在境内 → 选境内（需域名备案）；想跳过备案 → 香港/新加坡（延迟略高）

### 6.2 装 Docker

SSH 登录服务器后，按 Docker 官方文档装 Docker Engine。国内服务器拉镜像慢的话，配一个镜像加速地址。

### 6.3 部署 new-api

按项目官方 README 的 Docker 方式启动（镜像名、端口、数据卷以 README 为准）。要点：

- 数据卷挂到 `/opt/new-api/data`，别丢
- 先只监听本机或内网，**不要**直接把 3000 端口开到公网
- 外面用 Nginx/Caddy 反代到 443，配 HTTPS 证书

### 6.4 首次登录，立刻改密码

默认管理员账号密码是公开的，**不改等于把后台送人**。改完再关掉「允许新用户注册」——第一阶段只由你手工建号。

### 6.5 加渠道（把上游 Key 填进去）

后台「渠道 → 新建」：

| 字段 | 填什么 |
| --- | --- |
| 类型 | DeepSeek / 智谱 / Moonshot 等 |
| Base URL | 用默认；自建代理才改 |
| 密钥 | 你在 3.1 申请的那把 Key |
| 模型 | 这个渠道支持哪些模型（可留空自动） |

建完点「测试」，通了再启用。

### 6.6 配模型与展示名

后台「模型」里把上游模型 ID 挂上，再决定对外叫法（见 3.6 的映射表）。第一阶段可以先不改名，直接用真实模型名，减少出错。

### 6.7 建用户、发令牌

1. 后台建一个用户（用户名+密码，或直接给他一个令牌）
2. 给这个用户生成令牌（`sk-` 开头）
3. 设置初始额度

### 6.8 用户在客户端怎么填（照着念给他）

```
打开 QMai → 设置 → 大语言模型 → 添加自定义模型
  接口地址：https://api.你的域名/v1
  线路协议：OpenAI（chat_completions）
  API Key：sk-你发给他的令牌
  模型：点「拉取模型」，选一个
  → 点「测试」，通过 → 设为默认模型
```

这就是为什么**阶段 0 不用改代码**：客户端里的「自定义模型」本来就是为标准 OpenAI 协议准备的，你的网关只要兼容它。

### 6.9 收钱、加额度

微信/支付宝转账 → 你在后台给他加额度 → 微信告他用完了再充。

丑，但一周就能验证需求。**别在这一步做自动化。**

### 6.10 每天看三个数

- 调用次数、输入/输出 token 总量 → 算真实成本
- 每个用户用了多少 → 看谁是重度用户
- 哪些模型被用得最多 → 决定正式版主推哪个

### 阶段 0 验收标准

- [ ] 至少 5 个真实用户跑通「填地址+令牌→测试通过→写出一章」
- [ ] 连续跑 3 天不宕机
- [ ] 你能算出「一个用户一个月大概烧多少钱」
- [ ] 至少 1 个人真的付了钱

达不到就别做阶段 1。

## 七、阶段 1：卡密 + 客户端登录（设计草案）

### 7.1 数据表

```sql
users       用户：id、账号、密码哈希、状态、创建时间
cards       卡密：code、面额(点数)、有效期、状态、绑定用户、兑换时间
ledger      额度账本：user_id、变动值、原因(兑换/扣费/赠送)、余额快照、时间
usage_logs  调用流水：user_id、模型、输入/输出 token、成本、请求时间
```

### 7.2 三条硬规则（少一条就被薅）

1. **一码只能用一次** —— 用数据库唯一约束兜底，不能只靠代码 `if`
2. **首次兑换即绑定账号** —— 之后不能转赠
3. **卡密有有效期** —— 过期作废，避免长期挂账

### 7.3 兑换流程

```
用户买卡（发卡平台 / 微信转账）
  → 客户端「账号与套餐」输入卡密
  → POST /qmai/redeem
  → 校验：存在 + 未使用 + 未过期
  → 绑定当前账号 + 加额度 + 写账本
  → 客户端刷新余额
```

### 7.4 客户端要改的文件

| 文件 | 改动 |
| --- | --- |
| `src/stores/wiki-store.ts` | `LlmConfig.provider` 联合类型加 `"qmai"` |
| `src/lib/llm-providers.ts` | 加分支：地址固定、Key 用登录令牌，请求体与 openai 相同 |
| `src/lib/has-usable-llm.ts` | 加「已登录即可用」，不再要求用户填 Key |
| `src/components/settings/llm-presets.ts` | 加「QMai 官方通道」预设；模型 chips 改为服务端下发 |
| `src/lib/settings-model-list.ts` | 复用现有 `/v1/models` 拉取，指向你的网关 |
| 新增 `src/lib/account/` | 登录、令牌刷新、余额、兑换 |
| 设置页 | 新增「账号 / 套餐 / 用量」区块 |
| 错误提示 | 401 未登录、402 额度不足、429 限流，全中文 |

### 7.5 三条安全底线

- 用户令牌存**系统钥匙串**，不要明文进 `localStorage`
- 厂商 Key **只存服务器环境变量**，不进客户端、不进 git
- 后台只允许你的 IP 或加二次验证

## 八、成本与定价

### 8.1 成本公式

```
单次成本 = 输入 token × 输入单价 + 输出 token × 输出单价
月成本   = Σ 所有用户所有调用
毛利     = 收入 - 月成本 - 服务器/带宽/支付通道费
```

### 8.2 一个示例（数字是假设，实际以官网为准）

假设某模型：输入 ¥2/百万 token，输出 ¥8/百万 token。

| 场景 | 输入 | 输出 | 单次成本 |
| --- | --- | --- | --- |
| 生成一章 3000 字 | 20,000 | 6,000 | ¥0.04 + ¥0.048 ≈ **¥0.09** |
| 拆解一本 30 万字书 | 400,000 | 60,000 | ¥0.8 + ¥0.48 ≈ **¥1.28** |
| 全天重度（20 章 + 2 次拆书） | — | — | ≈ **¥4.4/天 ≈ ¥130/月** |

### 8.3 所以不要做「会员无限用」

重度用户能把你的成本跑到售价的 3～5 倍。正确做法：

- **积分/点数制**：充 ¥30 得 3000 点，按实际 token 扣
- 或 **限量套餐**：¥39/月含 50 万字生成额度，超出按量
- 或 **分层**：基础版用小模型，高级版才给旗舰模型

### 8.4 盈亏平衡

```
保本用户数 = 固定成本 ÷ (客单价 - 平均单用户成本)
```

先把「平均单用户月成本」测出来（阶段 0 就是在测这个），再定价。

## 九、风险清单

### 9.1 合规（最容易被忽略）

- 境内服务器对外提供 80/443 服务，域名需要 **ICP 备案**
- 面向境内公众提供生成式 AI 服务，涉及**生成式人工智能服务备案/安全评估**（据公开规定，具体以主管部门要求为准，建议咨询专业人士）
- 转售厂商 API 要看**上游服务条款**是否允许；多数允许正常调用，禁止「转售原始接口」
- 收费涉及**发票与税务**

**降低风险的做法**：第一阶段只做小范围内测、不公开宣传、不做「无限量」承诺；模式验证后再走正规备案与合同。

### 9.2 安全

- 后台默认口令、3000 端口裸奔，是这类开源网关最常见的被入侵方式
- 必须：强口令、只开 443、前面挂 Cloudflare、关闭公开注册
- 定期看后台日志里有没有陌生 IP 大量调用

### 9.3 稳定性

- 单一上游挂了，全部用户都不能写 → 至少配一条备用渠道
- 网关要能「某个模型失败自动切备用模型」，否则用户会以为软件坏了

### 9.4 商业

- 用户充值后你跑路 = 纠纷；建议明确「额度有效期」「不支持退款」并写进购买页
- 卡密被盗刷：一次性 + 绑定 + 有效期
- 竞品价格战：你的差异应该是「写作场景调好的模型+提示词」，不是单纯卖 token

## 十一、常见问题

**Q：我能直接把 DeepSeek 的 Key 打包进软件吗？**
不能。会被拆包，等于公开送人。

**Q：不建账号，只卖卡密行不行？**
不行。卡密必须绑到一个账号上，否则一张卡可以被无限次「兑换」。

**Q：一定要备案吗？**
境内服务器对外提供服务需要 ICP 备案；生成式 AI 服务另有备案要求。先用香港服务器可以缓一缓，但正式运营要补。

**Q：能不能不自己搭，直接接别人的中转站再卖？**
技术上可以（客户端「自定义模型」填对方地址），但你成了二道贩子：上游一跑路你全挂，且加价空间很薄。

**Q：new-api / one-api 会不会被黑？**
会。默认配置直接暴露公网，历史上被扫是常态。按 9.2 加固，或干脆先只对固定 IP 开放。

**Q：现在软件里已经有二十多个模型，为什么还要做网关？**
因为那些是「用户自己的钥匙」。你要收钱，就必须让请求经过你。

**Q：做完这些，软件里原来「填自己的 Key」的功能要删吗？**
不要删。保留它，是给专业用户的逃生通道，也是你的差异化（很多同类软件强制只能用官方通道，用户很反感）。
