# 缓存命中率优化·P0 落地报告

> 2026-10-25 · 计划见 `scratch-20261025-缓存优化-执行计划.md`
> 结论：主对话第二轮命中率 **72.8% → 99.6%**（真实 API 复核，未命中 1865 → 29 token）

---

## 一、改了什么（4 处代码 + 3 处测试）

| 文件 | 改动 | 目的 |
|---|---|---|
| `src/lib/context-hub/prompt-content.ts` | `buildContextHubPromptParts` 由"两段"改为"三段"：`systemContent` / `chapterPrefix` / `taskContext`；新增第 4 个参数 `stableRules` | 把稳定的技能库塞进 system；把本轮资料从尾部前移到 system 之后 |
| `src/components/chat/chat-panel.tsx` | ① QM-QUAI 技能、选中写作技能、会话技能从"本轮动态要求"改走 `stableRules`；② 把 `chapterPrefix` 作为一条独立 user 消息插在 system 之后、历史之前；③ 不再传 `taskGoal: plainText` | 同上 + 修任务契约污染头部 |
| `src/lib/agent/runner.ts` | `taskGoal` 从"最后一条 user"（=本轮输入）改为"第一条 user"（=会话初始目标） | 契约在 system 末尾，每轮变会让其后全部历史失去缓存 |
| `src/lib/context-hub/prompt-content.spec.ts` | 按新契约更新断言，新增"稳定技能进 system 且不进本轮要求"用例 | 防止回退 |
| `src/lib/__tests__/cache-prefix-diagnostic.spec.ts` | 新增 S2b：用真实函数构造新布局，断言第二轮可完整命中 | 本地护栏 |
| `src/lib/cache-hit.real-llm.test.ts` | "现状"分支改为显式复刻旧布局，"修后"分支改用 `chapterPrefix` | 保持真机 A/B 可复跑 |

### 改后的请求结构

```
[system : 软件规则 + 稳定核心 + 技能库]   ← 逐字节不变
[user   : 本轮参考资料（人物/伏笔/检索/推演）] ← 一章内不变，可命中
[history: 只追加]
[user   : 会话摘要 + 本轮执行要求 + 用户输入]  ← 唯一随时间变的部分
```

### 没做什么（有意为之）

- **没改请求体**：原计划要给 DeepSeek 补 `stream_options.include_usage`，实测发现**硅基流动在流式下默认就返回 usage（含 `cached_tokens`）**，加了反而给其它网关带来 400 风险。撤。
- **没改 UI 指标**：原计划去掉"供应商没报就回落成本地文件缓存率"。但 `context-trace-panel.spec.tsx` 有 4 条用例明确把"本地资料复用率"当成「缓存命中」展示（本地 4/5=80%），是既定产品口径。与本次优化无关，撤。建议后续单独讨论改名。

## 三、风险与已知残留

| 风险 | 说明 | 处理 |
|---|---|---|
| 资料未做"章内冻结" | 若本章资料在中途被工具改写（伏笔台账更新等），`chapterPrefix` 会变一次 → 该次 miss | 可接受（一次 miss vs 每轮 miss）；后续按 `会话+章节+依赖指纹` 冻结 |
| 多了一条前导 user 消息 | system 之后紧跟 user（资料），模型看到的顺序变了，注意力分配可能变化 | 需试读 1~2 章确认"人物状态/伏笔"仍被采纳 |
| 技能库进 system 后 system 变长 | 技能大的会话 system 可能到 6~8k token | 正是想缓存的部分；但要注意别挤占上下文预算 |
| 会话摘要仍在尾部 | 每轮重算，不能命中 | 下一批：摘要改成"增量追加" |
| `chapterPrefix` 未计入上下文用量环 | 预算口径没变（dynamicTokens 已含该内容） | 观察即可 |

## 四、下一批（P1）建议顺序

1. **试读验证**：真实写 1~2 章，确认资料前移没有降低"人物状态/伏笔"的采纳率。
2. **章节产线单会话化**：实测未命中 6772 → ~3900（−42%）。
3. **审稿复用写作前缀**：审稿现在从 `pack.task` 起头，与写作前缀异构 → 0%。
4. **stableCore 固定配额**：避免"一段变、后面截断位全移"（实测只剩 43.9% 公共前缀）。
5. **合并 2k token 以下的小调用**：低于门槛直接不缓存，白跑。
