拆书库：旧版结果并入新版页签

设计说明 · 2026-10-06 · 青幕AI写作 v4.1.0

1. 背景与目标

拆书库目前有两代界面共存：新版单页工作台 book-analysis-workbench.tsx，以及被当作一个整体块挂在页面最下方的旧版页面 LegacyBookAnalysisView。

现状有两个问题：

  • 旧版块把「用量分析／正在识别角色／待分析／区块进度」这类过程性脚手架也一并露出，这些内容不该出现在结果区。
  • 旧版结果被堆在底部，与新版三个页签（角色 Skill／故事 Skill／文风 Skill）割裂；同一个技能的结果分散在两处。

目标：旧版结果按技能并入对应新版页签，去掉底部独立旧版块；页签内只呈现结果，不出现旧版的操作按钮与过程脚手架。

已确认的决策（用户逐项确认）：
  • 用户口语里的「决策 skill」= 新版「角色 Skill」页签（新版只有 角色／故事／文风 三个页签）。
  • 只搬结果，不搬旧版操作按钮（重新提取／启用文风／删除／生成角色 Skill／选择角色生成）。
  • 导入作品时即使勾了分析项，也不自动建任务；保持新版行为（选中作品＋滚到分析设置，由用户点「开始分析」）。
  • 实施走「就地内嵌＋迁移副作用」；旧版组件本次只停止挂载，暂不删除。

丢弃的内容

丢弃 用量分析、正在识别角色、待分析、区块进度、旧版全部操作按钮，以及旧版「证据」页签（新版 WorkbenchResult 内部已渲染 revision.evidence）。

为什么不需要数据迁移

三个旧版面板都是纯 props 展示组件；BookWorkspace 已经持有 book（含全部旧版数据）和 activeSkill，插入点就在新版结果区渲染 WorkbenchResult 之后。旧版数据形状（personalityProfile、styleProfile.layers、故事导图 HTML）与 WorkbenchRevision 差异较大，不做结构转换，直接并排渲染两套结果。

故事页签的重叠是刻意的：新版结果只渲染当前这一份故事导图，旧版块提供的是历史列表（多份、可逐个展开预览）。两者维度不同，因此都保留；旧版块标题明确写「历史导图」，避免看起来像重复渲染。

3. 组件设计

给三个既有组件增加一个 variant 模式，避免复制展示逻辑（复制会让两处慢慢不一致）：

组件新增embedded 模式下的行为
BookAnalysisCharacterPanelvariant?: "full" | "embedded"隐藏标题与说明（:72-97，其中包含两个操作按钮，它们属于这个重复标题块）；保留角色列表的选中按钮、已生成／未生成标记、右侧详情。外层去掉边框与圆角。逐角色的删除按钮不由 variant 控制，而是由 onDeleteCharacter 是否存在决定（详见下面「控件是否渲染只看回调」）。
BookAnalysisStyleCard同上只去掉卡片自身的边框、背景与内边距（:84）；标题「作品文风 · Writing DNA」与「已启用」标记保留、六层蒸馏、指标面板与可展开详情保留。三个工具条按钮（启用此文风／提取文风／删除文风，:103-119）不由 variant 控制，而是各自由对应回调是否存在决定。
StoryMapContent不加 variant只隐藏「删除」（:180-188），做法是把删除按钮门控在 onDeleteStoryMap 上（未传则不渲染）；保留「查看全部／收起」——它是查看预览的开关，不是管理操作。它没有需要剥离的外壳（根节点是 space-y-4，每张卡片自己的边框属于内容），所以不需要 variant，见 legacy-panel-variant.ts 的注释。

控件是否渲染只看回调

实施中由评审定下、并已写进 legacy-panel-variant.ts 注释的约定：variant 只描述外壳（重复标题、卡片自身的内边距/边框/背景）；某个管理类控件是否渲染，只由它自己的回调是否存在决定（{onX && <Button/>}）。

这样漏传回调只会少一个按钮，而不会留下点了没反应的死按钮——原来的写法（回调可选、控件无条件渲染）正是这个坑，StoryMapContent 的删除按钮在本次修改前就处于这个状态。

嵌入模式下的 props 契约

被隐藏的控件对应的回调（onOpenSkillSelection、onAddSelectedSkillsToSoul、onDeleteCharacter、addingToSoul、onExtractStyle、onToggleStyle、onDeleteStyle、onDeleteStoryMap）在 embedded 下变为可选，无回调时对应控件直接不渲染。

BookAnalysisCharacterPanel 的 selectedCharacterId／onSelectCharacter 仍保持受控：由新增的 LegacySkillResults 持有选中状态并向下传递。组件内部不引入隐式自管状态，避免同一个组件出现两种行为模式。选中 id 为空或已失效时组件本就会回退到第一个角色，因此初始值传 null 即可。

原因：页签本身已经叫「角色 Skill」，面板内部再出现一次同名标题会重复；旧版面板自带卡片边框，嵌进页签后会出现「框里套框」。embedded 同时解决这两点。full（默认值）保持旧版页面原有行为，因此既有测试不受影响。

新增一个薄封装组件 LegacySkillResults，按 activeSkill 选择渲染哪一个，负责「旧版资料」小标题；空状态由各面板自己负责（暂无角色数据。／尚未提取故事导图。…／尚未蒸馏 Writing DNA…），封装层不重复这套判断。

实施中修订：空状态归属。本节原先写封装层「统一负责空状态」，实现时改为由面板各自负责，原因：三个面板本来就有各自的空状态文案，而故事页签的空状态只能靠 listStoryMapHistory 的结果判断，封装层要自己判断就得把这次读取重复一遍。 因此封装层对当前技能无条件渲染容器与「旧版资料」标签，空状态由面板给出——已被 legacy-skill-results.spec.tsx 的空作品用例钉住。

4. 副作用迁移（本设计的真正工作量）

旧版页面不只是一堆展示，停止挂载它会同时带走 4 个看不见的副作用。逐条核实结果：

#副作用位置处置
1导入完成 → 自动建分析任务book-analysis-view.tsx:360-373按已确认决策不迁移：保持新版「选中作品＋滚到分析设置」行为。这是一处有意的行为变化。
2任务完成 → 重载作品库、刷新故事导图:375-429必须迁移。并入的角色／文风结果来自作品库，不刷新会一直显示旧数据。
3侧边栏「刷新」→ 重载作品库:446-448必须迁移，理由同上。
4侧边栏「现在处理」→ 重建旧版选角色面板:470-492旧版面板随卸载消失，改为滚到并高亮新版内联的「选择目标角色」区（新版已有该 UI）。
风险：第 2、3 项若遗漏，症状是「分析跑完了但页签里还是旧结果」，不容易第一时间联想到副作用迁移，因此这两项必须有测试覆盖。

另外，旧版「角色识别 → 生成 Skill」弹窗随卸载消失；新版有自己的「识别角色／生成选中角色」（workbench.tsx，workbenchVersion === 2 的任务），功能不丢，但入口与旧版不同。这是本次接受的取舍。

5. 明确不做的事

  • 不删除 LegacyBookAnalysisView 及其 277 行测试。本次只停止挂载，让回归面最小；确认新版外观没问题后再单独一次删干净。
  • 不把旧版数据迁移进 WorkbenchRevision（会丢失 personalityProfile、styleProfile.layers、samples）。
  • 不改动新版分析流水线、不改数据结构、不动旧版页签内部的既有逻辑。

6. 验证策略

  • TDD：每项行为先写失败测试再实现。variant="embedded" 的断言点在不出现操作按钮与重复标题；副作用迁移的断言点在依赖变化后确实重新读取了作品库。
  • 真实浏览器几何检查：沿用 docs/book-workbench-relayout/check.mjs 的方式（真实 Chromium + 真实 CSS），确认三个页签各自的旧版结果区确实出现在页签内容内、操作按钮不存在。jsdom 无法计算布局。
  • 全量回归：基线为 195 项既有失败；本仓库的基线由 git stash 对照确认过。新增失败即视为自伤。
  • 打包验证：npm run build:portable 后确认产物中包含新组件、不含已删除的 .wb-legacy 标记。
