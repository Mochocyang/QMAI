test(便携版): exe 校验补上记忆中心单页结构，并修掉引号/简写两处假失败

verify-in-exe.mjs 增加第四轮（记忆中心单页重构）判据 18 项：
- 存在侧 9 项：快照总数 / 显示更多 / 两种空态 / 清除区间，
  以及 memory-tabs、memory-stats、memory-snapshot-collection、outline-snapshots 标记
- 消失侧 5 项：selectedMemoryCenterEntry、MemoryCenterListButton、
  中间栏占位文案、以及内层双栏的两个选择器（memory-snapshots 复数、memory-chapter-filter）
- 样式侧 4 项：标签条/统计条 nowrap、标签条横向滚动、快照集合纵向堆叠

本轮的主判据是"消失侧"：这一轮的命题几乎全是结构拆除。
另外 needle 用**复数** memory-snapshots —— 卡片选择器 [data-ui="memory-snapshot"]
（单数）改造后仍然存在，用单数会把它误判成旧结构还在。

修掉两处会**假失败**的写法（都是产物与源码写法不同造成的）：
1) 引号：lightningcss 输出 [data-ui=memory-tabs]，源码写的是
   [data-ui="memory-tabs"]。拿带引号的选择器查产物永远查不到 ——
   4 项样式断言第一版因此全红，且红得很有欺骗性（像是"规则没进产物"）。
   加 normalizeSelector 统一去引号。
2) 简写：overflow-x:auto + overflow-y:hidden 被合并成 overflow:auto hidden，
   按 overflow-x:auto 子串断言必然落空。改为按语义判定横向分量。

新增 prove-exe-checks.mjs：在**真实 dist 产物**上做 8 个变异，重跑校验脚本，
确认每一项都真的会变红，然后原样恢复。8/8 命中。

这份脚本自身也修了两个会让"变异没落地"的缺陷：
- 撞上第一个含 needle 的文件就放弃（选择器名同时出现在 JS chunk 和 CSS 里，
  先撞上的是不含 flex-wrap 的 JS），导致 P1~P4 四项静默跳过；
- 用 text.replace 改声明，压缩后 CSS 是一整行，flex-direction:column 出现多次，
  只改到第一个（多半属于别的规则），于是"变异没落地、校验仍全绿" ——
  看起来像断言被喂饱，其实是变异没改到目标。改为在选择器规则块内部替换。

验证：verify-in-exe.mjs 50/50 通过；prove-exe-checks.mjs 8/8 变异如期变红，
恢复后基线仍全绿。
