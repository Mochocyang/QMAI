02 / PRODUCT SCOPE

第一版 APP 应该做什么

移动端的价值不是复制全部工具，而是让作者在离开电脑后仍能接着写、查设定、问 AI，并安全回到桌面继续深度创作。

APP 定位：青幕随身创作台

桌面端负责重型生产，移动端负责碎片化创作、随时查阅和跨端续写。两端共享项目数据，但不强求能力完全对称。

轻创作
重连续
能力V1 建议原因移动端形态
书架 / 项目切换必须进入任何工作流的起点卡片列表 + 最近项目
章节阅读与轻编辑必须移动场景最高频全屏编辑器 + 自动保存
AI 对话 / 续写 / 润色必须保留青幕核心价值独立全屏会话，不与正文并排

本地 CLI / MCP / 字体安装不迁移依赖桌面系统能力由桌面端保留
03 / OPTIONS

三套开发方案

Tauri Mobile 直接延展

在现有 Tauri 2 工程上增加 Android / iOS 目标，保留 React 页面与一部分 Rust 命令。适合快速做内部 Demo，但不是最稳妥的正式路线。

MOBILE APP · INTERACTIVE CONCEPT

从“功能截图”
变成一套真实流程

点击手机底部导航切换页面。原型围绕一个任务链展开：从书架回到章节，在正文中调用 AI，以草稿方式查看生成结果，再去记忆中心核对角色与伏笔。

书架 · 回到最近的故事

突出最近项目、当前章节与同步状态。首页直接提供“接着写”，让用户不必先钻入目录再定位章节。

阅读优先正文留白与行高延续青幕的纸感，避免把编辑器压缩成密集控制面板。
关键状态可见保存、同步、AI 草稿状态直接标出，不把数据安全藏在设置页。
单屏任务AI 对话与正文分开呈现，避免窄屏双栏；生成内容先预览再采纳。
记忆可追溯每条设定注明来源章节与当前状态，创作时快速验证前文事实。
设置可达把模型、同步、外观、备份、安全、反馈收纳在“我的”，头像也提供快捷入口。
视觉基调：静水色板 · 暖纸白 · 竹绿强调 · 低对比细分割 · 触控优先
导航原则

一次只做一件事

桌面的“三栏并排”改为“目录抽屉 → 正文全屏 → AI 全屏”的可逆切换；设置入口固定放在底部“我的”。

写作原则

永不丢稿

输入即本地事务保存；后台/锁屏前再次落盘；同步是第二层保障，不是唯一保障。

AI 原则

草稿与正式内容隔离

延续桌面版机制：AI 生成先进入草稿，用户确认后才替换正文或进入记忆。

05 / DESIGN SYSTEM

如何保持相同风格

视觉一致靠令牌、排版和动效语气，而不是照搬桌面组件。以下数值直接来自当前主外壳，并做触屏尺寸适配。

Canvas#EDF1EC · 页面底色
Paper#FCFDFB · 内容表面
Soft#E4ECE3 · 选中 / 提示
Accent#45624F · 主按钮 / 焦点
字体界面用系统无衬线；书名、页标题用宋体/思源宋体层。正文默认 18px、行高约 1.8–1.95。
圆角基础 10px；卡片 14–16px；底部面板 22–28px。保持克制，不做“全是胶囊”。
阴影低透明、长扩散，只用于浮层和关键卡片。列表主要靠底色与 1px 分隔线分层。
触控尺寸桌面 30px 图标按钮需放大到至少 44×44px 的触控区域；图标仍保持 18–20px。
动效150–220ms，轻淡入与位移；同步和 AI 生成使用安静的状态变化，不做强烈跳动。
三套皮肤首发保留“静水”；“纸间”与“星夜”在 V1.5 迁移，均由同一 token schema 驱动。
移动端组件规范：顶部栏 52–56px；底部导航 56px + 安全区；页面横向边距 16px；卡片间距 12px；正文编辑宽度全屏但左右留白 18–22px；所有危险操作必须二次确认并提供可恢复路径。

08 / NEXT ACTIONS

接下来应该怎么做

先用一周消除最贵的不确定性，再决定是否全面投入。以下顺序比先画几十张页面更重要。

冻结 V1 边界

确认只做书架、章节、大纲、AI、记忆与同步；明确暂不迁移的桌面能力。

建立真实测试样本

准备 1 个约 30 章项目、1 个超长章节、1 组同步冲突与 1 个离线编辑场景。

做编辑器真机 Spike

Android 与 iOS 各验证中文输入法、撤销、选区、粘贴、软键盘和后台恢复。

定义数据契约

为项目、章节、记忆、同步清单建立版本化 schema；所有路径改用 projectId + relativePath。

拆出 design-tokens

把现有静水/纸间/星夜色板、字体和圆角转为平台无关 JSON/TS token。
