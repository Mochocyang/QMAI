QMAI 4.1.2

修复 v4.0.0 起收不到应用内更新提示的问题。

根因：26f80ee（2026-09-25 调整对话输入框与界面资源）在改界面时一并删掉了
App.tsx 里的 import 与 void checkForAppUpdate()。此后 checkForAppUpdate 全仓
只剩自己的定义、没有任何调用者，app-updater 模块被 bundler 整体 tree-shake，
那段代码根本没进安装包 —— 不是"弹窗没弹出来"，而是代码不在包里。
原代码的守卫 if (!IS_UI_TEST_BUILD) 本身还恒为假（该常量硬编码为 true，
且没有构建期替换），照抄恢复等于没修。

影响范围：v4.0.0 至 v4.1.1 共 6 个稳定版。v3.2.16 不受影响。

重要：受影响版本的用户永远收不到自动更新提示 —— 他们的检查逻辑是死的，
再发布多少新版本都不会被感知。请通过「设置 → 更新日志 → 检查更新」
手动更新一次，此后自动更新即恢复正常。该手动入口经逐版核实，
在 v4.0.0 至 v4.1.1 每一版都可用。

本版更新说明（2 条）：
1. 【自动更新提示恢复】启动时自动检查更新，发现新版本即弹窗询问是否下载安装；
   此前只能手动进设置页检查
2. 【受影响的旧版本请手动更新一次】给出上述手动更新路径与说明

验证：
- 产物级前后对照：app-updater 独有的 5 条对话框文案，修复前在 dist 中一个都没有，
  修复后全部进包
- 真实端到端：已发布的 v4.1.0 便携版对真实 GitHub 端点 60 秒内无任何提示（复现
  用户报告）；修复版对同一端点弹出「检测到新版本 4.1.1」+ 14 条真实更新说明
- 运行时负向对照：同一构建配置与端点，仅去掉那一行调用 → 无任何弹窗
- 变异证明：5 项变异 5/5 如期变红（含"套回恒假守卫"一项）
- test:mocks A/B 新增失败文件 0 个；tsc 双配置通过

已知未覆盖：updateCheckStarted 并发守卫无测试。并发动态 import 被 vi.mock 的模块
在本仓库 vitest 下不可靠（实测其中一次拿到真实模块），任何此类用例都恒真；
第一版写的并发用例就是假绿，已删除并在测试文件写明原因。
