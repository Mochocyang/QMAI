# AI 大纲输出协议

本协议用于 AI 大纲对话区。AI 生成任何大纲、章纲、人物、设定、伏笔内容时，必须同时给出可保存的结构化结果；系统解析后弹出确认，用户确认后才写入左侧大纲文件树。

## 1. 输出边界

- 本协议只服务 AI 大纲体系，不生成正文。
- AI 可以生成：题材卡、总纲、卷纲、章纲、人物小传、世界观、力量体系、势力、地图、伏笔、质量检查报告。
- 正文协作区后续可以读取已确认章纲，但不通过本协议直接写正文。

## 2. 必须返回的保存元信息

每次生成可保存内容时，AI 必须返回以下字段：

| 字段 | 说明 |
|---|---|
| `targetFolder` | 保存目标文件夹，例如 `大纲`、`章纲`、`人物小传` |
| `fileName` | 文件名，必须包含可排序编号或明确主题 |
| `fileType` | `outline`、`volume-outline`、`chapter-outline`、`character`、`setting`、`foreshadowing`、`quality-report` |
| `writeMode` | `create`、`append`、`replace`、`patch` |
| `referencedSkills` | 本次调用或遵循的 Skill 列表 |
| `sourceIntent` | 用户本轮意图摘要 |
| `content` | 实际保存内容，Markdown 格式 |

## 3. 标准结果块

AI 回复中必须包含一个 `outlineSaveRequest` 代码块。八类设定一律令 `content` 为 ""，正文由软件从结构化数据生成。系统优先读取此代码块，弹出确认后由用户决定是否写入；禁止静默落盘，禁止调用 `write_outline_node` 作为替代写入通道。

```json
{
  "outlineSaveRequest": {
    "targetFolder": "章纲",
    "fileName": "章纲-第001章.md",
    "fileType": "chapter-outline",
    "writeMode": "create",
    "referencedSkills": [
      "TicaiSkill/male-xuanhuan-xianxia",
      "ZhanggangSkill/chapter-outline-builder",
      "SheDingSkill/power-system"
    ],
    "sourceIntent": "用户要为男频玄幻长篇生成第001章章纲",
    "content": "# 章纲-第001章\n\n..."
  }
}
```

## 4. 多文件输出

当一次对话需要同时生成多个文件时，使用 `outlineSaveRequests` 数组。

```json
{
  "outlineSaveRequests": [
    {
      "targetFolder": "大纲",
      "fileName": "题材卡.md",
      "fileType": "outline",
      "writeMode": "create",
      "referencedSkills": ["TicaiSkill/male-urban-system"],
      "sourceIntent": "创建新书题材定位",
      "content": "# 题材卡\n\n..."
    },
    {
      "targetFolder": "设定/世界观",
      "fileName": "世界观-基础规则.md",
      "fileType": "setting",
      "writeMode": "create",
      "referencedSkills": ["SheDingSkill/world-rules"],
      "sourceIntent": "保存世界观基础规则",
      "content": "# 世界观-基础规则\n\n..."
    }
  ]
}
```

## 5. 写入模式规则

- `create`：新建文件。目标文件已存在时，系统应提示用户确认或自动追加序号。
- `append`：追加到文件末尾。适合伏笔记录、角色出场记录、设定更新记录。
- `replace`：整体替换文件。只用于用户明确要求重写时。
- `patch`：局部修改。必须说明要修改的标题段落或字段。

## 6. 文件命名规则

- 题材卡：`题材卡.md`
- 总纲：`总纲.md`
- 卷纲：`卷纲-第01卷.md`
- 章纲：`章纲-第001章.md`
- 人物小传：`角色-男主-角色名.md`、`角色-女主-角色名.md`、`角色-反派-角色名.md`
- 世界观：`世界观-主题.md`
- 力量体系：`力量体系-主题.md`
- 势力：`势力-组织名.md`
- 伏笔：`伏笔-主题.md`
- 质量报告：`质量检查-对象名.md`

## 7. 失败与澄清

如果 AI 无法判断保存目标，必须先输出澄清问题，不得默认乱存。

必须澄清的情况：

- 用户只说“完善一下”，但没有指定文件或内容对象。
- 同名文件存在且用户没有说明覆盖、追加或另存。
- 生成内容跨越大纲和正文边界。
- 题材、男频/女频、长篇/短篇冲突。

## 8. 质量门

输出保存请求前检查：

- 是否包含 `targetFolder`、`fileName`、`fileType`、`writeMode`、`referencedSkills`、`content`。
- 是否使用中文用户提示和中文文件名。
- 是否没有生成正文。
- 是否引用了题材、大纲/章纲、人物或设定 Skill。
- 是否符合 `OUTLINE_FOLDER_STORAGE_STANDARD.md` 的目标文件夹规则。

## 9. HTML 版本（AI 直接写网页，不再套模板）

保存时每个 `.md` 都可以有一份同名 `.html` 伴生文件。**HTML 由你（模型）直接写完整网页**——系统模板已下线：它把内容压成固定卡片流，样式呆板，体验很差，用户明确要求停用。

硬性要求：

1. **完整文档**：在 ```html 围栏里给出从 `<!DOCTYPE html>` 到 `</html>` 的完整页面；不要只给片段，不要用 Markdown 冒充。
2. **自包含**：样式全部写在页面内的 `<style>`；**禁止** `<script>`、`on*=` 事件属性、外部字体/图片/CDN、`@import`。离线打开必须完整可用。
3. **多份文档**：一次保存 N 个文件，就按保存请求顺序给 N 个 ```html 围栏，一一对应。
4. **必须好看**（这也是本次改动的核心）：
   - 配色：定义 CSS 变量（1 个主色 + 1–2 个辅助色 + 中性灰阶），不要默认白底黑字；
   - 页头：`h1` 标题 + 一句话副标题 + 2–4 个概览徽章（如「47 个分区 · 九境九重 · 十二州」）；
   - 版式：内容用**分区卡片**承载（`display:grid; grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))`），
     每个分区一张卡（`section`），卡内是段落 / 列表 / 少量对照表；
   - **禁止「整页只有一张表格」**：表格只能用于真正的对照数据（境界↔标志、区域↔势力），
     且一张表不超过页面篇幅的一半；其余内容必须用卡片、要点、时间线、徽章来表达；
   - 细节：圆角 10–14px、柔和阴影（`box-shadow: 0 8px 24px rgba(0,0,0,.06)`）、
     分区标题带序号或左侧色条；关键状态用彩色徽章；
   - 字体：`font-family: -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`，正文 15–16px，`line-height: 1.8`，`letter-spacing: .01em`；
   - 布局：`max-width: 1080px` 居中，窄屏自动单列；页头下方留 32–48px，卡片内边距 20–28px；
   - 写完后自检：**有没有页头？有没有 ≥3 个分区卡片？是不是变成一张大表？** 不满足就重写。
5. **内容一致**：网页必须与同批 `.md` 正文是同一份内容（可以重排版式，不得新增未经确认的设定，也不得漏掉关键条目）。
6. **不要写入敏感信息**：页面里不得出现项目绝对路径（如 `C:\…`）、记忆库原文、邮箱、任何 API Key / 令牌 / 口令。
   记忆与设定只作为创作依据，不得逐字搬到页面上。
7. 系统不再为**任何**类型渲染 HTML：没有 ```html 围栏就没有 `.html`，保存框里的「HTML 形式」会置灰。

结构化数据（`volumeOutlineData` / `chapterOutlineData` / `characterProfileData` / `factionProfileData` / `powerProfileData` / `foreshadowingProfileData` / `goldenFingerProfileData` / `geographyProfileData` / `locationProfileData` / `backgroundProfileData` / `settingOutlineData`）仍照常输出在 ```json 围栏里：后续「从大纲生成章纲/正文」等功能依赖它。它与 HTML 是两件事，两者都要给。

保存确认对话框中，勾选「HTML 形式」才会写入 `.html`；未给出网页时该选项不可用。


## 八类详细设定的内容等价要求

第二版详细档案标准：不是展示简介。基本身份、生活与供给、运行机制、权限与例外、失败后果、当前时点、知情范围、关联对象及写作场景均须具体；每个重要机制给出可核验的条件和后果，而非只增加段落数量。
数值闭合：组织收入、成本、利润、分配与现金流分开；人员分组与总人数吻合；同一行程的距离、速度、有效行进时长和等待时间一致；人物的收入、生活费、债务与储蓄互相成立。缺少依据时给明确假设，不硬凑精确数字。
同一事实只设一个当前基准：说明章节或时点，将未来升级、人物出场、伏笔回收与当前状态分开。跨人物、组织、地图、地点、卷纲和章纲的名称、时间、位置与证据应能相互核对。关联对象写名称和作用，不自行捏造文件路径或链接。
完整不是堆字数：覆盖本类全部分区与关键字段。重要对象逐项写清对象、机制、条件、代价、变化及正文用法，不能只列名词或写一句空泛评价；同一信息不反复复制充数。
区分【已确认】【设计提案】【待确认】。新建设定允许基于题材和已有材料提出具体、内部一致的设计，不用整页待补充敷衍；补完已有设定不得改写正史。关键未知写清问题、影响与可选设计，不能编造成已确认事实。
记录必须区分【计划】与【已发生】，注明章节或时点及依据；没有正文证据不得虚构出场、解锁、埋设或回收记录。无明确章号用阶段，作者真相不得越过人物认知边界。
按题材适配：非营利组织解释收支平衡，无任务金手指写使用史，无分级力量写可验证能力边界；不适用项说明原因及等价约束，不硬套仙侠、系统或公司模板。
跨档案核对人物、势力、地点名称、时间线、交通耗时、经济口径、能力边界、关系和伏笔ID；新增提案不得静默覆盖已确认内容，冲突明确列出。
每个分区包含能够指导具体场景的细节，关键机制给触发—行动—结果—代价的示例。数字写单位、周期、依据或估算假设，不能伪造精确度；禁止省略号、略、同上、其余同理等占位。
结构化字段必须承载完整正文：每个分区、字段、表格、说明和例子均须保留，不能缩成摘要。长说明用kv条目；表格长解释保留在对应单元格，禁止因排版删除内容。
多个对象分别完整输出并保持名称匹配，禁止混用他人档案。输出预算不足时缩小批次或继续完成当前对象，不压缩必填分区，不把截断草稿冒充完整档案；沿用现有保存确认流程。

## 第二版空间图形

地理与地点的档案对象可以附带 diagram（kind=map/floorplan，title、note、nodes、regions、routes）。它必须与当前对象对应；坐标是0—100的相对位置，不是实测地理坐标。完整字段按地图推进技能契约，不输出原始SVG/HTML。没有空间依据时省略，不假造地图。

第二版模板使用常驻分区目录与语义版式；不要用HTML写死装饰或引用不存在的文件链接。旧文档和项目内自定义模板不因本协议自动覆盖。

## 设定类单对象低重复输出

每轮最多生成一个完整对象；保留全部分区、详细字段，不减少信息深度。只输出一个完整的结构化JSON围栏，不写MD正文，最后输出 outlineSaveRequest。保存请求的 content=""，正文由软件从结构化数据生成；不要在保存请求中重复抄写正文。其余保存字段照常填写，不调用写入工具替代用户确认。多个待生成对象仅列未完成名称，等用户继续，不把多个完整对象挤入本轮。

已收到正文但流式中断时仍是未完成草稿，不得声明生成或保存成功。不要为避免中断删减内容或编造已完成状态。

此例外仅减少八类设定保存协议中的重复文本；卷纲、章节细纲及其他既有输出协议保持不变。
