# 地图推进

## 适用范围

换地图、新地图、阶段地图、学校、宗门、城市、副本、领地、星际、秘境。

输出地图或场景文件时必须遵循上级目录的 `SETTING_PROFILE_STANDARD.md`，重点写清进入条件、离开条件、环境规则、资源、危险、新旧地图关联和阶段作用。

## 设计规则

1. 新地图必须带来新环境、新角色、新规则、新目标和新冲突。
2. 新旧地图要有关联：上级、仇怨、资源流向、历史因果或旧伏笔。
3. 换地图前，旧地图核心冲突至少阶段性解决。
4. 换地图后前 5 章快速建立代入感、资源目标和主要压力源。
5. 地位升高时，环境危险度也要同步升高。
6. 地图变化必须改变行动规则，不能只是地名变化。

## 章纲要求

- 本章若换地图，要写清旧地图收束和新地图期待。
- 地图不能只是地名变化，必须改变行动规则。
- 章尾钩子优先投放新地图传说、危险或资源。

## 文件要求

- 独立地图默认输出到 `设定/地图/{地图名}.md`。
- 关键场景可写入背景设定；反复出现并影响多章时独立成文件。
- 新地图前 5 章必须建立新目标、新压力和新规则。

## 结构化输出契约（地理设定，必须遵守）

生成**地理设定**时，除 MD 正文外**必须额外输出一个 ```json 围栏**，顶层字段为 `geographyProfileData`
（多区域用 `geographyProfiles` 数组）。软件用它渲染专属「地理卡」HTML（模板：本目录 `profile.html`）。

**sections 必须按下面顺序写满 12 项，一个都不能少**（每张 table 至少 3 行）：

```json
{
  "geographyProfileData": {
    "name": "九霄大陆",
    "tag": "大陆",
    "tagline": "一句话定位",
    "sections": [
      { "kind": "kv", "heading": "地理概览", "items": [{ "label": "世界格局", "text": "…" }, { "label": "核心舞台", "text": "…" }, { "label": "地理尺度", "text": "…" }, { "label": "整体气候", "text": "…" }] },
      { "kind": "kv", "heading": "区域格局", "items": [{ "label": "层级结构", "text": "…" }, { "label": "核心地带", "text": "…" }, { "label": "边缘地带", "text": "…" }] },
      { "kind": "table", "heading": "区域划分", "head": ["区域", "类型", "地域特征", "所属势力"], "rows": [["", "", "", ""]] },
      { "kind": "table", "heading": "重要地点", "head": ["地点", "所属区域", "作用", "可触发事件"], "rows": [["", "", "", ""]] },
      { "kind": "table", "heading": "地形与气候环境", "head": ["地形/气候", "分布", "对行动的影响"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "资源与物产", "head": ["资源", "产出区域", "稀缺度", "争夺情况"], "rows": [["", "", "", ""]] },
      { "kind": "table", "heading": "势力分布", "head": ["势力", "控制区域", "影响力", "与主角关系"], "rows": [["", "", "", ""]] },
      { "kind": "table", "heading": "交通与通行", "head": ["通道/方式", "连接", "耗时", "风险"], "rows": [["", "", "", ""]] },
      { "kind": "table", "heading": "危险区域与风险", "head": ["危险区域", "危险类型", "规避方式"], "rows": [["", "", ""]] },
      { "kind": "list", "heading": "地域特色", "items": ["…"] },
      { "kind": "list", "heading": "剧情作用", "items": ["…"] },
      { "kind": "list", "heading": "写作约束", "items": ["…"] }
    ]
  }
}
```

- 必须用 `table`：区域划分、重要地点、地形与气候环境、资源与物产、势力分布、交通与通行、危险区域与风险；
  必须用 `kv`：地理概览、区域格局；必须用 `list`：地域特色、剧情作用、写作约束。
- 内容要求：
  - **区域划分**：给出**可区分的空间层级**（如 大陆 → 国度 → 城市），每区写清类型、地域特征、所属势力；
  - **重要地点**：写清所属区域、作用与可触发事件，不能只是地名；
  - **交通与通行**：决定人物**如何移动**（通道、耗时、风险）；
  - **写作约束**：**地理变化必须改变行动规则**（资源、危险、通行限制），不能只是换地名。
- **不要**把 `**加粗**` 之类 Markdown 标记写进 JSON 的 label/text —— 卡片按纯文本渲染，标记会原样显示。

## HTML 地理卡

保存时软件会把 `geographyProfileData` 套 `profile.html` 渲染为同名 `.html` 地理卡
（经纬网格感头图 + 区域块表格）。用户可在 `.qmai/地理设定模板.html` 覆盖样式。
本目录另有 `reference-sample.html`（**详细参考样本**，可直接对照 12 分区与表格列设计）。

## 结构化输出契约（地点设定，必须遵守）

生成**地点设定**时，除 MD 正文外**必须额外输出一个 ```json 围栏**，顶层字段为 `locationProfileData`
（多地点用 `locationProfiles` 数组）。软件用它渲染专属「地点卡」HTML（模板：本目录 `location.html`）。

**sections 必须按下面顺序写满 12 项，一个都不能少**（每张 table 至少 3 行）：

```json
{
  "locationProfileData": {
    "name": "地点名",
    "tag": "城池/秘境/宗门驻地/遗迹/副本",
    "tagline": "一句话定位",
    "sections": [
      { "kind": "kv", "heading": "地点定位", "items": [{ "label": "所处区域", "text": "…" }, { "label": "地点类型", "text": "…" }, { "label": "在世界中的位置与意义", "text": "…" }] },
      { "kind": "kv", "heading": "所属势力", "items": [{ "label": "控制方", "text": "…" }, { "label": "势力态度", "text": "…" }, { "label": "与主角关系", "text": "…" }] },
      { "kind": "table", "heading": "空间规则", "head": ["规则", "说明", "违反后果"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "出入条件与限制", "head": ["条件", "说明", "限制"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "资源与限制", "head": ["资源/限制", "获取或使用条件", "危险"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "可触发事件", "head": ["事件", "触发条件", "影响"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "常驻人物", "head": ["人物", "身份", "立场", "可提供的信息或冲突"], "rows": [["", "", "", ""]] },
      { "kind": "list", "heading": "氛围与感官", "items": ["…"] },
      { "kind": "table", "heading": "隐藏信息", "head": ["信息", "谁知道", "揭示条件"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "危险与禁忌", "head": ["危险/禁忌", "后果", "规避方式"], "rows": [["", "", ""]] },
      { "kind": "list", "heading": "剧情作用", "items": ["…"] },
      { "kind": "list", "heading": "写作约束", "items": ["…"] }
    ]
  }
}
```

- 必须用 `table`：空间规则、出入条件与限制、资源与限制、可触发事件、常驻人物、隐藏信息、危险与禁忌；
  必须用 `kv`：地点定位、所属势力；必须用 `list`：氛围与感官、剧情作用、写作约束。
- 内容要求：
  - **出入条件与限制**：必须写清**进入条件与离开条件**，以及地点内独有的规则；
  - **可触发事件**：必须写明触发条件与影响，不能只列事件名；
  - **隐藏信息**：写明「谁知道」与「揭示条件」，供伏笔与反转使用；
  - **写作约束**：地点必须改变行动规则（通行、资源、危险、时间流速等），不能只是换地名。
- **不要**把 `**加粗**` 之类 Markdown 标记写进 JSON 的 label/text —— 卡片按纯文本渲染，标记会原样显示。

## HTML 地点卡

保存时软件会把 `locationProfileData` 套 `location.html` 渲染为同名 `.html` 地点卡
（同心定位环头图 + 地点块表格，与地理卡同族但配色区分）。用户可在 `.qmai/地点设定模板.html` 覆盖样式。
本目录另有 `location-reference.html`（**详细参考样本**，可直接对照 12 分区与表格列设计）。
