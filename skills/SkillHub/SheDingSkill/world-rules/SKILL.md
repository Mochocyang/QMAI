# 世界规则

## 适用范围

世界观、规则怪谈、修仙法则、社会制度、禁忌、信息公开度、设定一致性。

输出世界观、背景设定或规则文件时必须遵循上级目录的 `SETTING_PROFILE_STANDARD.md`，重点写清核心定义、运行规则、剧情功能和写作约束。

## 设计清单

1. 规则来源：自然法则、制度、神明、系统、宗门、国家、家族或副本。
2. 规则边界：能做什么，不能做什么，违反后代价是什么。
3. 信息公开度：读者知道、主角知道、配角知道、反派知道分别是什么。
4. 反制方式：规则是否能被绕开、利用、误读或升级。
5. 长期影响：规则会如何影响势力、地图、人物目标和伏笔回收。
6. 使用边界：哪些问题不能靠这个规则临时解决。

## 章纲要求

- 每次使用规则，都要写明规则依据和代价。
- 新增规则必须服务本章冲突或伏笔。
- 禁止临时新增万能规则解决剧情。

## 文件要求

- 背景设定默认输出到 `设定/世界观/背景设定.md`。
- 规则体系默认输出到 `设定/世界观/规则体系.md`。
- 影响多章的规则必须写更新记录。

## 背景设定详细内容契约

每个对象必须按顺序覆盖以下 12 个分区；逐条落实字段，不将一整区压缩成一句概述。

### 1. 世界观背景

时代、世界尺度、文明分布、核心舞台、普通人生活状态与核心矛盾；交代世界靠什么生产和维持秩序、当下为什么不稳定，以及主角进入世界时面对的现实问题，而非只给恢宏历史简介。

载体：kv；按上面的要求拆分具体字段和条目。

### 2. 世界前提与差异

写与现实或同题材常规世界不同的关键前提、形成原因及连锁后果；逐条落实到资源、生产、战争、家庭、交通与信息传播。特殊现象要有边界、成本和受益受损者，不只是装饰性奇观。

载体：kv；按上面的要求拆分具体字段和条目。

### 3. 时代风貌

技术及生产力、能源、农工商业、货币与交易、物价层级与收入、交通通信速度、医疗与卫生、城市和乡村日常；选取吃住行、生病、求职等生活场景说明时代规则，估算数值标注依据和口径。

载体：kv；按上面的要求拆分具体字段和条目。

### 4. 社会结构

写政权合法性、行政税赋、司法执法、财产继承、教育与知识垄断、职业和身份流动、家庭婚姻、弱势群体和救济；说明不同阶层如何谋生、获得保护或遭受剥夺，以及制度如何约束主角行动。

载体：table；表头：阶层或制度 / 权力与资源 / 义务与生计 / 流动与排斥 / 冲突及影响。

### 5. 文化习俗

覆盖适用的信仰、祭祀、节庆、饮食、婚丧、礼仪、审美和禁忌；写谁遵守、为何遵守、地区阶层差异和例外成本，给出可直接使用的场景细节，不把一种习俗无差别套给所有居民。

载体：table；表头：习俗与适用群体 / 历史或信仰来源 / 具体做法 / 利益和社会意义 / 违背后果及例外。

### 6. 语言与称谓

说明通用语、方言、书面语、官方和行业称谓、度量衡、纪年与时间表达；给出合乎身份的称呼示例，标注误称的后果、翻译或信息障碍，避免现代术语无解释混入或称谓前后漂移。

载体：table；表头：词语或称谓 / 使用者与场合 / 含义及权力关系 / 示例与禁用条件。

### 7. 历史沿革

按适用的起源、关键转折到当下说明因果链；区分史实、官方叙事、民间传说和待揭真相。每段历史至少解释一种当下制度、资源格局、敌对或禁忌，不为了分期数量编造无用年代。

载体：table；表头：时期与可靠性 / 事件及参与者 / 原因与代价 / 制度或地理变化 / 遗留矛盾。

### 8. 核心设定规则

分别交代自然、超凡或技术规则与人为法律，写能做和不能做、谁执行、如何发现违规、违反后果和已知例外；规则应可在情境中验证，解释为何强者、政权或技术不能绕过所有矛盾。

载体：table；表头：规则及适用范围 / 原理与边界 / 触发和代价 / 例外及验证方式 / 社会后果。

### 9. 信息公开度

区分作者层真相、读者已知、主角所知、配角和反派认知，写谎言与误解的传播者和获益者；重要信息注明渠道、时点及可靠性，未知保留，不能让角色使用尚未获知的世界设定。

载体：table；表头：事实或秘密 / 知情者与认知 / 公众说法 / 获知渠道与证据 / 揭示条件及后果。

### 10. 势力格局

解释主要权力中心、资源产销、贸易依赖、武力与合法性如何相互制衡；写公开秩序和地下秩序、边缘群体处境及近期导火索，与组织和地理设定使用同名同边界，避免重复造出冲突版本。

载体：table；表头：势力及控制范围 / 核心利益与资源 / 盟友及敌对 / 制衡与依赖 / 当前变局。

### 11. 剧情作用

将背景转成可触发的困难、机会、道德选择与信息差，说明涉及人物、现实代价、读者如何通过行动逐步理解；至少给出日常与重大冲突两种使用情境，不以百科介绍替代小说场景。

载体：list；按上面的要求拆分具体字段和条目。

### 12. 写作约束

锁定纪年、技术上限、物价口径、通信交通、阶层和法律的一致性；列可变与不可变条件、规则揭示顺序及新增设定影响。避免后设救场、时代错位和无成本制度变化，待确认项注明影响与解决途径。

载体：list；按上面的要求拆分具体字段和条目。

### 结构化与保存

同时输出完整 MD 与 JSON。单对象顶层字段 `backgroundProfileData`，多个对象用 `backgroundProfiles` 数组；每个对象为 `{name,tag,tagline,sections}`，section 使用 `{kind,heading,items}`（kv 的 items 为 label/text 对象，list 为字符串）或 `{kind:"table",heading,head,rows}`。各分区标题、顺序及内容必须与 MD 等价，不得缩成摘要。

软件套用 `world-rules/background.html`，不要自行输出 HTML/CSS。最后按既有 outlineSaveRequest 协议输出保存请求，只有用户确认后才落盘。

## 交付前自检

第二版详细档案标准：不是展示简介。基本身份、生活与供给、运行机制、权限与例外、失败后果、当前时点、知情范围、关联对象及写作场景均须具体；每个重要机制给出可核验的条件和后果，而非只增加段落数量。
数值闭合：组织收入、成本、利润、分配与现金流分开；人员分组与总人数吻合；同一行程的距离、速度、有效行进时长和等待时间一致；人物的收入、生活费、债务与储蓄互相成立。缺少依据时给明确假设，不硬凑精确数字。
同一事实只设一个当前基准：说明章节或时点，将未来升级、人物出场、伏笔回收与当前状态分开。跨人物、组织、地图、地点、卷纲和章纲的名称、时间、位置与证据应能相互核对。关联对象写名称和作用，不自行捏造文件路径或链接。
完整不是堆字数：覆盖本类全部分区与关键字段。重要对象逐项写清对象、机制、条件、代价、变化及正文用法，不能只列名词或写一句空泛评价；同一信息不反复复制充数。
区分【已确认】【设计提案】【待确认】。新建设定允许基于题材和已有材料提出具体、内部一致的设计，不用整页待补充敷衍；补完已有设定不得改写正史。关键未知写清问题、影响与可选设计，不能编造成已确认事实。
记录必须区分【计划】与【已发生】，注明章节或时点及依据；没有正文证据不得虚构出场、解锁、埋设或回收记录。无明确章号用阶段，作者真相不得越过人物认知边界。
按题材适配：非营利组织解释收支平衡，无任务金手指写使用史，无分级力量写可验证能力边界；不适用项说明原因及等价约束，不硬套仙侠、系统或公司模板。
跨档案核对人物、势力、地点名称、时间线、交通耗时、经济口径、能力边界、关系和伏笔ID；新增提案不得静默覆盖已确认内容，冲突明确列出。
每个分区包含能够指导具体场景的细节，关键机制给触发—行动—结果—代价的示例。数字写单位、周期、依据或估算假设，不能伪造精确度；禁止省略号、略、同上、其余同理等占位。
MD正文与结构化JSON必须内容等价：每个分区、字段、表格、说明和例子均须保留，不能把JSON缩成摘要。长说明用kv条目；表格长解释保留在对应单元格，禁止因排版删除正文。
多个对象分别完整输出并保持名称匹配，禁止混用他人档案。输出预算不足时缩小批次或继续完成当前对象，不压缩必填分区，不把截断草稿冒充完整档案；沿用现有保存确认流程。

## 第二版 HTML 阅读方式

软件按分区语义自动呈现档案卡、时间线、等级阶梯、资源与关系清单，并保留完整原始对照表。只提供内容和结构化数据，不自行装饰 HTML，不省略长字段来适应排版。

## 设定类单对象低重复输出

每轮最多生成一个完整对象；保留全部分区、详细字段及配套结构化JSON，不减少信息深度。先输出完整MD正文，再输出本对象的完整JSON，最后输出 outlineSaveRequest。保存请求的 content=""，由软件从同一回复的MD正文回填；不要在保存请求中重复抄写同一篇正文。其余保存字段照常填写，不调用写入工具替代用户确认。多个待生成对象仅列未完成名称，等用户继续，不把多个完整对象挤入本轮。

已收到正文但流式中断时仍是未完成草稿，不得声明生成或保存成功。不要为避免中断删减内容或编造已完成状态。
