# 伏笔与悬念

## 适用范围

伏笔、线索、隐藏身份、旧案、规则真相、反转、悬念节奏、回收计划。

输出伏笔或悬念追踪文件时必须遵循上级目录的 `SETTING_PROFILE_STANDARD.md`，重点写清伏笔状态、预计回收、回收方式、回收后果和过期处理。

## 生命周期

1. 埋设：自然出现，不解释。
2. 推进：重复出现但换角度。
3. 提示：回收前让线索汇聚。
4. 回收：产生“原来如此”的情绪。
5. 后果：回收后改变人物关系、规则或主线。
6. 追踪：每个伏笔必须有状态，不能只写灵感。

## 章纲要求

- 每章标注新增、推进、回收、延后处理的伏笔。
- 如果本章无新增伏笔，也要明确写“本章无新增伏笔”。
- 伏笔回收必须影响后续剧情，不能回收完就消失。

## 文件要求

- 伏笔默认输出到 `追踪/伏笔.md`。
- 状态使用：未埋 / 已埋 / 推进中 / 已回收 / 已过期。
- 过期伏笔必须标注补回收、延后、转长线或放弃并说明。

## 结构化输出契约（必须遵守）

生成伏笔计划时，除 MD 正文外**必须额外输出一个 ```json 围栏**，顶层字段为 `foreshadowingProfileData`。软件用它渲染专属「伏笔台账」HTML（模板：本目录 `profile.html`），因此**不要自己写 HTML/CSS**。

**sections 必须按下面顺序写满 12 项，一个都不能少**（每张 table 至少 3 行）：

```json
{
  "foreshadowingProfileData": {
    "name": "伏笔计划",
    "tag": "主线",
    "tagline": "一句话定位",
    "sections": [
      { "kind": "kv", "heading": "伏笔总览", "items": [{ "label": "伏笔总数", "text": "12" }, { "label": "主线/支线分布", "text": "…" }, { "label": "整体埋收节奏", "text": "…" }, { "label": "核心悬念", "text": "…" }] },
      { "kind": "table", "heading": "埋设与回收节奏", "head": ["卷次/阶段", "埋设数", "回收数", "悬念压力"], "rows": [["", "", "", ""]] },
      { "kind": "table", "heading": "伏笔状态表", "head": ["ID", "伏笔内容", "埋设章节", "预计回收", "状态", "重要度"], "rows": [["", "", "", "", "", ""]] },
      { "kind": "table", "heading": "线索链", "head": ["线索", "关联伏笔", "出现章节", "指向"], "rows": [["", "", "", ""]] },
      { "kind": "table", "heading": "表层误导与真相", "head": ["伏笔", "表层误导（读者以为）", "真实指向", "揭穿节点"], "rows": [["", "", "", ""]] },
      { "kind": "table", "heading": "回收日志", "head": ["章节", "回收伏笔", "回收方式", "后果"], "rows": [["", "", "", ""]] },
      { "kind": "table", "heading": "过期与风险", "head": ["ID", "问题", "处理方式"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "关联人物", "head": ["人物", "关联伏笔", "承担作用"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "关联设定与主线", "head": ["主线/设定", "关联伏笔", "如何呼应"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "悬念分级", "head": ["悬念", "级别", "维持手法", "计划回收"], "rows": [["", "", "", ""]] },
      { "kind": "list", "heading": "剧情作用", "items": ["…"] },
      { "kind": "list", "heading": "写作约束", "items": ["…"] }
    ]
  }
}
```

- 必须用 `table`：埋设与回收节奏、伏笔状态表、线索链、表层误导与真相、回收日志、过期与风险、关联人物、关联设定与主线、悬念分级；
  必须用 `kv`：伏笔总览；必须用 `list`：剧情作用、写作约束。
- 「状态」列取值只能用 **未埋 / 已埋 / 推进中 / 已回收 / 已过期**，「重要度」与「级别」列只能用 **高 / 中 / 低**
  —— 软件会按枚举渲染成彩色状态徽章。
- 内容要求：
  - **伏笔状态表**：核心台账，逐条写全；每条伏笔必须有完整生命周期（埋设章节 → 推进节点 → 预计回收章节 → 状态）；
  - 章节号必须具体，不得写「后期」「某章」；
  - **表层误导与真相**：写清读者以为是什么、真实指向什么、何时揭穿；
  - **埋设与回收节奏**：防止某卷全埋不收或全收无埋；
  - **过期与风险**：为高风险伏笔给出处理方式（补回收 / 延后 / 转长线 / 放弃并说明）。
- **不要**把 `**加粗**` 之类 Markdown 标记写进 JSON 的 label/text —— 卡片按纯文本渲染，标记会原样显示。

## HTML 伏笔台账

保存时软件会把 `foreshadowingProfileData` 套 `profile.html` 渲染为同名 `.html` 伏笔台账
（线轴感头图 + 伏笔线贯穿竖线 + 回收兑现绿调 + 状态/重要度彩色徽章）。
用户可在 `.qmai/伏笔计划模板.html` 覆盖样式。
本目录另有 `reference-sample.html`（**详细参考样本**，可直接对照 12 分区与表格列设计）。
