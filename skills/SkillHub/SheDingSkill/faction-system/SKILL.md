# 势力系统

## 适用范围

门派、家族、公司、官方机构、地下组织、反派阵营、宫廷、宗门。

输出势力、组织、阵营文件时必须遵循上级目录的 `SETTING_PROFILE_STANDARD.md`，重点写清势力目标、资源来源、内部矛盾、外部关系、代表人物和剧情功能。

## 设计清单

1. 势力目标：它当前最想得到什么。
2. 资源来源：金钱、武力、情报、人脉、地盘、制度、技术。
3. 内部矛盾：继承权、派系、利益差、理念差。
4. 外部对手：竞争、合作、互相利用或仇恨。
5. 主角关系：加入、利用、反抗、被追杀、继承因果。
6. 剧情功能：提供资源、压力、试炼、反转、伏笔或升级通道。
7. 更新记录：势力立场或资源变化必须记录。

## 章纲要求

- 势力登场必须推动一个核心事件。
- 势力要有代表人物和可见行动。
- 不要连续刷同类势力事件，至少保留节奏变化。

## 文件要求

- 独立势力默认输出到 `设定/势力/{势力名}.md`。
- 组织型势力也可输出到 `设定/组织/{组织名}.md`。
- 势力不能只有名字，必须有目标、资源和代表人物。

## 结构化输出契约（必须遵守）

势力/组织小传除 MD 正文外，**必须额外输出一个 json 代码块**，顶层字段为 `factionProfileData`
（多势力时为 `factionProfiles` 数组）。软件用它渲染专属「势力卡」HTML（模板：本目录 `profile.html`），
因此**不要自己写 HTML/CSS**。

**sections 必须按下面顺序写满 11 项，一个都不能少**（每张 table 至少 3 行）：

```json
{
  "factionProfileData": {
    "name": "青云门",
    "tag": "门派",
    "tagline": "一句话定位",
    "sections": [
      { "kind": "kv", "heading": "基本信息", "items": [{ "label": "组织名称", "text": "…" }, { "label": "规模", "text": "…" }] },
      { "kind": "kv", "heading": "组织使命", "items": [{ "label": "使命", "text": "…" }, { "label": "长期目标", "text": "…" }] },
      { "kind": "kv", "heading": "地理位置与作用", "items": [{ "label": "所在区域", "text": "…" }, { "label": "在该地的作用", "text": "…" }] },
      { "kind": "table", "heading": "组织架构", "head": ["层级/部门", "职能与权限", "负责人"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "人员构成", "head": ["核心人物", "职位", "能力或作用", "立场"], "rows": [["", "", "", ""]] },
      { "kind": "table", "heading": "经济来源", "head": ["来源", "运作方式", "规模或依赖风险"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "组织历史", "head": ["时期", "关键事件", "造成的影响"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "内部派系与矛盾", "head": ["派系", "核心诉求", "冲突点"], "rows": [["", "", ""]] },
      { "kind": "table", "heading": "外部关系", "head": ["对象", "关系", "冲突/合作点"], "rows": [["", "", ""]] },
      { "kind": "list", "heading": "剧情作用", "items": ["…"] },
      { "kind": "list", "heading": "写作约束", "items": ["…"] }
    ]
  }
}
```

- `sections[].kind` 三选一：
  - `kv`：字段（label）→ 内容（text），用于 **基本信息 / 组织使命 / 地理位置与作用**；
  - `table`：`head` + `rows` 二维数组，用于 **组织架构 / 人员构成 / 经济来源 / 组织历史 / 内部派系与矛盾 / 外部关系**；
  - `list`：纯条目数组，用于 **剧情作用 / 写作约束**。
- 内容要求：
  - **地理位置与作用**：这个组织在哪个地方、控制范围多大、它在这个地方的作用是什么；
  - **组织架构**：权力层级、下设部门或堂口、各层级职能与权限、负责人；
  - **人员构成**：核心人物（职位 · 能力或作用 · 立场），并写清人员都是哪一些、成员主要来源；
  - **经济来源**：产业、税收、掠夺、资助、技术提成等，写清运作方式与依赖风险；
  - **组织历史**：至少 3 个时期（时期 · 关键事件 · 造成的影响）；
  - **组织使命**：使命宣言、长期目标、对外立场。
- 人员构成与经济来源必须**具体**（名字、职位、来源渠道），禁止「一些成员」「多种收入」这类空话。
- **不要**把 `**加粗**` 之类 Markdown 标记写进 JSON 的 label/text —— 软件按纯文本渲染，标记会原样显示出来。
- 缺失信息写「原文未明确」或「待后续补充」，不得编造成事实。

## HTML 势力卡

保存时软件会把 `factionProfileData` 套 `profile.html` 渲染为同名 `.html` 势力卡
（印章式头图 + 11 个分区卡片 + 真表格；历史分区走时间线首列，架构 / 人员 / 关系走名册调），
与人物角色卡、卷纲折叠树、章纲卡片流同族。用户可在 `.qmai/组织势力模板.html` 覆盖样式。
本目录另有 `reference-sample.html`（**详细参考样本**，可直接对照 11 分区与表格列设计）。
