# 章纲结构化（17 节标准 + 卷纲骨架对齐）

## 触发与适用范围

- 适用于：把某一个故事（10–12 章）拆成逐章可执行章纲；补全/改写已有章纲。
- 不适用于：卷纲、总纲（全书大纲）、人物小传、设定、伏笔规划、正文。

## 章纲定义

章纲不是正文摘要，而是**后续写正文时读取的单章执行单元**。它必须写清本章承接什么、发生什么变化、如何场景化、留下什么钩子，以及哪些内容要写回设定/角色/伏笔文件。

一个故事的章纲 = 该故事 10–12 章的逐章执行单元，**章顺序、章号、节拍、所属环节必须与卷纲骨架逐字一致**。

## 生成前必须先读

1. 该故事所属的**卷纲**（拿到：章号区间、12 章节拍、10 环节、三层线、伏笔埋收、人物出场、对手出手）；
2. 总纲 / 人物小传 / 设定 / 伏笔文件（保证人物与设定自洽）；
3. 前一个故事的章纲（保证跨故事连续性）。

## 必须遵循（遵循即可，不要输出到界面）

### 一、17 节章纲标准

| 节 | 要写什么 |
|---|---|
| §1 基础信息 | 章节编号 / 标题 / 所属环节 / 本章节拍 / 字数目标 / 章节属性（铺垫·冲突·反转·高潮·过渡·关系）/ 核心情绪标签 / 主期待感 / 章内时间 / 主要地点 / 一句话目标 |
| §2 上章承接 | 上章结尾钩子 / 遗留问题 / 主角与角色当前状态 / 未回收伏笔 / 本章必须承接的读者期待 |
| §3 本章定位 | 主线承接与推进 / 人物变化 / 关系变化 / 读者追读目的 / 本章结束后必须产生的新期待 |
| §4 浓缩剧情 | 一句话公式：`{角色}因为{入场条件}进入{场景}，在{触发事件}中完成{变化}，并留下{下一章钩子}` |
| §5 核心事件链 | **6–10 条，每条必须有起因→行动→结果→作用**，不允许只罗列「发生了什么」 |
| §6 关键词与必要条件 | 场景/情绪/道具线索/关系/爽点冲突关键词；必要条件四类：入场 / 触发 / 互动 / 结果 |
| §7 四段式 | 开篇入戏（三行内进入场景）/ 中段冲突 / 核心爆点（含核心记忆点）/ 强钩收尾 |
| §8 情绪曲线 | 开局 / 中段 / 峰值 / 结尾四节点的情绪状态、触发事件、读者感受 |
| §9 爽点与看点 | 章首看点 / 主要爽点 / 铺垫 / 释放 / 反应层对象 / 爽点之后的新期待 / 是否与核心卖点一致 |
| §10 关键信息与扩写方式 | 每条关键信息 → 如何扩写成场景 + 扩写技法（对话·行动·反应层·信息差·延迟揭示·细节）+ 情绪作用 |
| §11 画面细节 | 环境细节 / 动作微细节 / 信息暗线细节 / 可替代抽象心理描写 / 本章必须出现的视觉记忆点 |
| §12 伏笔与钩子 | 回收旧伏笔（来源·如何回收·回收程度）/ 预埋新伏笔（内容·埋设位置·后续用途）/ 章尾钩子（类型·读者会问的问题·下一章必须回应） |
| §13 出场角色与状态变化 | 每角色：本章作用 / 入场状态 / 结束状态 / 关系变化 |
| §14 设定与道具更新 | 本章新增的设定 / 地点 / 势力 / 道具 / 需要写回设定文件的内容（只写增量） |
| §15 写作约束 | 必须写 / 禁止写 / 不能泄露的信息 / 节奏要求 / 文风要求 / 不可偏离的核心卖点 |
| §16 下一章交接 | 下一章开头必须承接 / 需要解决 / 可以延迟揭示 / 推荐情绪 / 推荐章尾钩子 |
| §17 写作检查清单 | 逐条勾选：三行内入戏、有明确变化、事件链有因果、有核心记忆点、有动作微细节、有爽点、回收旧信息、埋新信息、有追读钩子、已写明下一章交接 |

### 二、对齐补字段（每章必填，软件据此自动体检）

`stage`（所属环节，起①~合②）、`beat`（本章节拍）、`expect`（本章主期待感，8 类之一）、`time`（章内时间）、`place`（主要地点）、`seedFores` / `payFores`（本章预埋 / 回收的伏笔名，多个用「、」分隔）。

**这七项是软件做「章纲↔卷纲骨架对齐」的唯一依据，必须与卷纲逐字一致，不许自创。**

### 三、8 类期待感（每章只主推 1 类）

好奇｜危机｜关系｜成长｜反转｜情感｜爽点｜续航。

### 四、12 章节拍纪律

节拍取自：平 升 起 落 缓 紧 顶 悬。**不连续 3 章同节拍**（顶最多 2 连）；**顶后必须接落或缓**（故事收尾的「顶 → 悬」除外）；**悬必须落在故事末章**；章纲各章节拍串起来必须与卷纲 `beats` 逐字一致。

### 五、三层线落章

主线约 60% / 支线约 25% / 日常约 15%；**支线落在主线降速处**（标准模板：第 2 / 6 / 7 / 10 / 12 章）；**日常只能落在 平 / 落 / 缓 / 悬**；每段日常必须埋至少一个伏笔或后面被真正用掉。

## 完整性硬约束（违反即视为生成失败）

1. **章数 = 故事骨架章数**：`chapters` 必须写满该故事的每一章，禁止只写首尾章。
2. **章号连续递增**，不得跳号、不得重复。
3. **每章 17 节全写**（§1–§17 一节不落）。
4. **§5 事件链 ≥6 条**，每条 `cause` / `action` / `result` / `use` 齐全。
5. **§6 必要条件四类齐全**。
6. **§13 `castChanges` 至少 1 条**，§8 `moodCurve` 写满 4 个节点。
7. **关键节不得留空**：§10 `expand` 至少 1 条且含 `info` / `how`；§11 `visual.env` 与 `visual.memory` 必须有内容；§14 `worldUpdate` 至少一项有内容（确无新增就写「无新增」）。
8. **§17 `checks` 覆盖 10 条固定项**：三行内入戏 / 有明确变化 / 事件链有因果 / 有核心记忆点 / 有动作微细节 / 有爽点 / 回收旧信息 / 埋新信息 / 有追读钩子 / 已写明下一章交接。
9. **对齐补字段七项全填**，且 `beat` 与骨架 `beats` 逐字一致。
10. **章间交接链闭合**：第 N 章 `handover.nextStart` 必须与第 N+1 章 `carry.hook` / `carry.left` 呼应。
11. **伏笔闭环**：`payFores` 里的每一条都必须在本故事更早章节的 `seedFores` 出现过。
12. **逐章字数合计**与 `words` 偏差不超过 20%。

**禁止出现的写法**：「…」「等等」「略」「（略）」「参考上文」「其余同理」「同上」「此处省略」。一律视为生成失败。

## 输出规格

本技能产出两种格式，**由 AI 只产出内容数据，HTML 由软件套模板渲染**（你不需要写 HTML、CSS 或任何标签）：

- 章 × 环节 × 节拍对照表、字数配比、期待与钩子链、爽点节奏表、伏笔账本、人物出场与状态变化、地点与时间切换、情绪曲线、一致性体检 —— 全部由软件依据你写的数据自动生成。

## 分批输出（一次只写 3 章）

17 节标准体量很大，**一次输出整故事的章纲必然被截断**。因此按软件指定的批次逐批输出：

1. 每批只输出该批章的完整 17 节数据，JSON 顶层字段固定为 `chapterOutlineBatch`，且必须带上骨架：

```json
{
  "chapterOutlineBatch": {
    "title": "故事一 雨夜无我 · 章纲",
    "story": { "index": 1, "name": "雨夜无我", "range": "第1–10章", "beats": "平升起紧落缓升顶落缓紧悬" },
    "words": 30000,
    "chapters": [ { "n": 1, "title": "…", "stage": "起①", "beat": "平", "expect": "…" } ]
  }
}
```

2. 中间批次**不要**输出 `outlineSaveRequest`，也不要重复已完成的批次；
3. 软件会把各批合并为一份完整章纲并渲染 HTML，最后统一保存 —— 你不需要自己合并。

## 输出顺序

1. 本批的 MD 正文（该批章的 17 节）；
2. ```json 围栏的 `chapterOutlineBatch`（该批章全写满）；
3. 若这是最后一批，再附 `outlineSaveRequest`（content 为整故事的 MD 正文）。

## 常见错误

- 章数不足、跳号，或用「…」跳过中间章。
- 章纲自带骨架与卷纲不一致（`range` / `beats` 抄错）。
- §5 事件链只写事件不写因果；§6 四类必要条件缺项。
- `payFores` 里的伏笔在本故事更早章节没有 `seedFores`。
- 日常章落在「紧 / 顶」拍。
- 自己手写 HTML/CSS/标签（不需要，软件会按技能目录下的 template.html 渲染）。
- 在中间批次输出 `outlineSaveRequest`。
