# 角色设计

## 适用范围

男主、女主、男配、女配、反派、导师、盟友、工具人反工具化。

完整角色文件必须遵循上级目录的 `CHARACTER_PROFILE_STANDARD.md`。人物小传是「写正文时真的会去查」的那几张卡：角色卡、语言风格卡、关系卡 —— 不是台账，也不是给 AI 看的执行守则。

## 动机三角

每个重要角色都要有：

1. 想要：当前具体目标。
2. 害怕：最怕失去什么或发生什么。
3. 信念：他相信世界、自己和他人是什么样。

## 设计规则

- 主角的缺陷要能制造剧情，不只是性格标签。
- 反派要有独立目标和资源，不为推动剧情而发疯。
- 配角要补主角缺口：信息、情绪、资源、冲突、镜像、背叛。
- 每次重大选择必须能追溯到动机三角。
- 缺少原文信息时写“原文未明确”或“待后续补充”，不能编造成已确认事实。

## 章纲要求

- 写清本章出场人物的目标、行动、结果。
- 标注人物关系变化和认知变化。
- 防止角色为了剧情需要突然变蠢或变善。

## 只写 6 个分区（正文由软件从数据生成）

人物小传**只输出结构化数据**，不要手写 MD 正文：软件会把 JSON 一个字段不落地还原成 .md 与角色卡 HTML，模型再写一遍等于让用户为同一份内容付两次钱。

只写这 6 个分区，顺序固定，标题一致：

### 1. 基本信息

姓名、年龄与时间基准、性别、显性及隐藏身份、阵营、职业与生计、收入与债务、住所及日常活动范围、家庭与教育、能力与资源、伤病及当前处境；说明这些条件如何限制行动，而非只列标签。

载体：kv；按上面的要求拆分具体字段和条目。有化名、尊称、组织代号就写在这里。

### 2. 角色定位

在主线中的独立目标、故事功能、情绪功能、主题立场、与主角的对照和不可替代性；区分短期任务与长期欲望，说明利益冲突、主动行动、登场阶段及退场条件，配角也有不围绕主角运转的生活。

载体：kv；按上面的要求拆分具体字段和条目。

### 3. 外在表现

外貌辨识点、衣着及磨损、姿态、步态、惯用动作、饮食作息、随身物品、职业习惯；分别写放松、受压、说谎时可观察的变化，给出可直接入正文的动作细节，不用形容词堆砌代替表现。

载体：kv；按上面的要求拆分具体字段和条目。

### 4. 内在分析

成长经历按时间说明家庭、教育、关键创伤和成败如何形成信念；写欲望、恐惧、羞耻、底线、缺陷、认知偏差、防御机制和秘密；分别写他知道、误以为知道、不知道的事实及获知渠道，防止角色越界用上还没得知的信息；设计诱因—选择—代价—信念变化的弧线，列出可能做与绝不会做的事。

载体：kv；按上面的要求拆分具体字段和条目。

### 5. 语言风格

区分面对亲近者、上位者、敌人、陌生人及极端压力时的说话方式；写句长、语气、口头习惯、称呼、隐瞒与禁用措辞。每种重要场景给出原创示例对白和潜台词，语言差异应源于经历与利益。

载体：table；表头：对象与场景 / 措辞与节奏 / 潜台词与回避 / 示例对白 / 变化条件。

### 6. 关系网络

写亲缘、师承、盟友、敌对、债权和情感关系；逐个交代双方各想得到什么、掌握对方什么秘密、权力是否对等、信任程度、最近变化及决裂或修复条件。关系变化必须有事件和成本，不能只有好友或敌人标签。

载体：table；表头：对象与共同经历 / 公开关系与真实态度 / 利益与依赖 / 秘密与冲突 / 变化触发与代价。

### 不属于小传的三类内容

- **出场记录**：章节记忆在每章入库时自动维护，档案里再排一张静态表必然过期，没有正文时更只能编「计划出场」。
- **当前状态**（位置、伤病、体力、资源、任务）：由 `.novel/character-states.json` 每章更新，档案里再写一份就是两个基准。
- **写作使用规则**：那是给模型的执行约束，不是设定内容，用户读它拿不到新信息。

## 结构化与保存

只输出一个 JSON 围栏：单对象顶层字段 `characterProfileData`，多个对象用 `characterProfiles` 数组；每个对象为 `{name,tag,tagline,sections}`，section 使用 `{kind,heading,items}`（kv 的 items 为 label/text 对象，list 为字符串）或 `{kind:"table",heading,head,rows}`。

软件套用 `character-design/profile.html` 渲染角色卡，不要自行输出 HTML/CSS。最后按既有 outlineSaveRequest 协议输出保存请求（`content=""`），只有用户确认后才落盘。

## 设定类单对象低重复输出

每轮最多生成一个完整对象；保留全部分区与详细字段，不减少信息深度。多个待生成对象仅列未完成名称，等用户继续，不把多个完整对象挤入本轮。

已收到内容但流式中断时仍是未完成草稿，不得声明生成或保存成功。不要为避免中断删减内容或编造已完成状态。
