# 卷纲折叠树（1 卷 = 10 故事 = 1 大高潮）

## 触发与适用范围

- 适用于：用户要求生成某卷的卷纲、分卷大纲、卷一大纲，或要求按「10 个故事 / 折叠树 / 十环节 / 大高潮」结构整理卷级大纲。
- 不适用于：章纲、总纲（全书大纲）、人物小传、设定、伏笔、正文。

## 卷纲定义

1 个卷纲 = **10 个小故事 = 1 个大高潮**。每个小故事固定跑满 **10 个环节**（起3 + 承3 + 转2 + 合2），约 12 章 / 3 万字；10 个故事靠「引线」首尾咬合，最终汇聚成卷级大高潮。生成前应读取项目大纲目录下已有的总纲、人物小传、设定、伏笔文件作为素材，确保人物与设定自洽。

## 生成时必须遵循（遵循即可，不要输出到界面）

### 一、10 环节体系（每故事固定顺序）

| 环节 | 要完成什么 | 主期待感 | 人物任务 |
|---|---|---|---|
| 起① 常态与破口 | 先立「正常」，再用异常捅破 | 好奇期待 | 主角 + 常态锚点人物 |
| 起② 人物站定 | 新增人物一次交代清楚并标明功能位 | 关系期待 | 引路 / 阻力 / 镜子 / 代价 四类各就位 |
| 起③ 目标与代价预告 | 把好奇升级成「必须」 | 危机期待 | 主角自定目标；世界开价 |
| 承① 尝试与失败 | 旧方法解决问题 → 失败 | 翻盘期待 | 阻力人物发力或规则否决 |
| 承② 资源拼图 | 攒信息/物件/人情/规则，显性化可编号 | 成长期待 | 每个新增人物交出一件可复用物 |
| 承③ 中点反转 | 换掉问题的「性质」 | 反转期待 | 镜子人物或伏笔点破 |
| 转① 认知反转 | 从 7 类反转库选一类执行 | 真相期待 | 反转执行者（人/规则/物件/主角） |
| 转② 代价抉择 | 付出一样东西换取前进资格 | 情感期待 | 主角独自面对 |
| 合① 小高潮兑现 | 结账：表层矛盾解决、代价落地 | 爽点期待 | 前面攒的资源合流 |
| 合② 引线与余震 | 未解之物 + 状态改变 + 下故事钩子 | 续航期待 | 留一个具体可追的「下次一定」 |

### 二、8 类期待感（每环节只主推 1 类）

好奇（这是什么/为什么反常）｜危机（会不会失败）｜关系（两人会怎样）｜成长（攒够了吗）｜反转（我猜对了吗）｜情感（他会怎么选）｜爽点（兑现/翻盘/打脸）｜续航（后面还有什么）。

### 三、7 类反转库（承③ 与 转① 必须不同类型）

认知（换事实）｜规则（换游戏规则）｜立场（换阵营）｜身份（换人物标签）｜时间（换因果顺序）｜代价（换谁付账）｜主体（换敌人在哪）。**反转的本质是「换掉一个前提」，不是「多一个帮手」**。全卷 10 故事至少覆盖 5 类以上。

### 四、8 种情绪结构（节奏轴）

平（铺陈/埋伏笔）· 升（蓄势）· 起（事件启动）· 落（代价消化）· 缓（日常/支线）· 紧（倒计时/逼近）· 顶（兑现/翻盘）· 悬（留钩子）。12 章节拍纪律：**不连续 3 章同节拍**（顶最多 2 连）；**顶后必须接落或缓**（故事收尾的「顶 → 悬」除外）；**悬必须落在故事末章**。

### 五、三层线 + 12 章排布

主线约 60%（约 7 章）+ 支线约 25%（约 3 章，每故事 1-2 条）+ 日常约 15%（约 2 章）。**日常只能落在「平 / 落 / 缓 / 悬」节拍**；**支线落在主线降速处**（标准模板：第 2 / 6 / 7 / 10 / 12 章）；每段日常必须埋至少一个伏笔或后面被真正用掉。

### 六、跨卷复用

结构、10 环节、7 类反转库不动；只换「大高潮目标 / 代价阶梯起点 / 人物池（保留 3-4 个旧人当引路，旧人不做反转）」。接口规则：上一卷合② 引线 = 下一卷起① 破口。

## 七、10 种叙事结构与选用纪律

起承转合只是其中一种，而且它管不了所有问题。有的管**全卷骨架**，有的管**单个故事的节奏**，有的管**多线怎么交汇**：

| 结构 | 段落构成 | 管哪一层 |
|---|---|---|
| 起承转合（东亚） | 起 · 承 · 转 · 合（4） | 通用 |
| 三幕式（亚里士多德 / 好莱坞） | 建置 · 对抗 · 结局（3） | 卷级 |
| 五幕式（弗莱塔格金字塔） | 展示 · 上升 · 顶点 · 回落 · 收束（5） | 卷级 |
| 序破急（世阿弥） | 序 · 破 · 急（3） | 单故事 |
| 英雄之旅（坎贝尔 / 沃格勒） | 12–17 阶段 | 全卷 |
| 七点式结构（Dan Wells） | 钩子 · 转折1 · 夹点1 · 中点 · 夹点2 · 转折2 · 解决（7） | 单故事 |
| 故事圈（Dan Harmon） | 舒适→需求→进入→搜寻→找到→付出→回归→改变（8） | 单故事 + 全卷 |
| 单元剧 / 卷单元 | 每卷一个自足小世界 | 卷级 |
| 多线叙事 | 主线 + N 条支线 | 全卷 |
| 环形叙事 | 结尾回到开头 | 全卷 |

**三条选用纪律**：① **不要叠加**——选 1 个管全卷、1 个管单故事、1 个管逐章节奏就够了（本技能默认：10 环节管单故事、8 情绪结构管逐章）；② 结构之间要能互相翻译，给出矛盾建议说明故事还没想清楚；③ 结构是体检工具不是写作模板，落笔按人物与情绪走。

生成的卷纲必须把这三条落进 `position.structure`：写明本卷选了哪几个结构（分别管哪一层），以及为什么不用其余几种。

## 完整性硬约束（违反即视为生成失败）

1. **故事数 = 10**：`stories` 数组必须包含 10 个故事对象，禁止只写第 1 个和第 10 个。
2. **每故事环节数 = 10**：`st` 必须写满 起①起②起③承①承②承③转①转②合①合②，每环节带 `stage`、`who`、`use`、`p`。
3. **每环节条目数 = 3**：`p` 必须是 3 条具体条目（不是概括句）。
4. **每故事头行字段填全**：`range` `deliver` `gift` `mid` `twist` `hook` `climax` `beats`。
5. **每故事含线/拍数据**：`line`（主线＋支线＋日常＋日常作用）、`beats`（12 章节拍序列）。
6. **承③(mid) ≠ 转①(twist)**：两者必须是不同的反转类型。
7. **每故事补 `link`**：本故事合②的引线在下一故事起①如何被接住（最后一卷写通往下一卷的落点）。
8. **每环节补 `pay`**：该环节埋下的期待在哪里兑现（如「合①」「故事五 承②」）。
9. **顶层补 `foreshadows`**：伏笔追踪数组，每条 `{ v, seed, pay }`（内容 / 埋设位置 / 回收位置）；至少要覆盖每个故事的日常伏笔。
10. **顶层补 `cast`**：人物出场表数组，每条 `{ n, role, stories, u }`（人物 / 功能位 / 出场故事 / 作用）；功能位取「引路 / 阻力 / 镜子 / 代价 / 主角 / 预埋」。
11. **顶层补 `position`**：卷级定位，含 `pitch` 卷定位 / `theme` 主题句 / `narrative` 叙事形态 / `structure` 结构选用声明（见第七节）/ `chapters` 建议章数 / `ending` 卷末落点，六项都要写。
12. **顶层补 `roles`**：卷级功能位总览，六个功能位（引路 / 主角 / 阻力 / 镜子 / 代价 / 预埋）各一条 `{ n, v }`。
13. **顶层补 `escalation`**：大高潮分解 + 代价阶梯，必须写满 10 条（对应 10 个故事），每条 `{ id, stake, lose, rise }`——赌注等级 / 本故事付出的代价 / 抬升到什么。10 个故事必须是**逐级抬升**，不是并列。
14. **顶层补 `debts`**：悬念债务表，每条 `{ q, from, plan }`（悬而未决的问题 / 起始位置 / 计划回收位置）；本卷结束时仍未收回的悬念必须列出来。
15. **顶层补 `rivals`**：对手推进表，每条 `{ n, moves: [{ id, v }] }`；每个对手至少 2 次出手，禁止反派只在被打时才出现。
16. **顶层补 `growth`**：人物成长与资源表，每条 `{ n, gains, state }`（人物 / 获得物与资源演进 / 能力与状态变化）；获得物要与各故事 `gift` 对得上。
17. **顶层补 `places`**：地点 / 组织索引，每条 `{ n, kind, stories, u }`（名称 / 类型（地点或组织）/ 出场故事 / 剧情作用）。

**禁止出现的写法**：「…」「等等」「略」「（略）」「参考上文」「其余同理」「此处省略」。一律视为生成失败。

## 输出规格

本技能同时产出两种格式，**由 AI 只产出内容数据，HTML 由软件套模板渲染**（你不需要写 HTML、CSS 或任何标签）：

- 章号定位：软件按固定映射给每个环节标章号（起①=第1章…合②=第12章）；
- 卷级定位卡：来自顶层 `position`（卷定位 / 主题句 / 叙事形态 / 结构选用 / 建议章数 / 卷末落点）；
- 卷级人物功能位总览：来自顶层 `roles`；
- 整卷账本 + 三层线配比：软件按各故事章号范围汇总章数与字数，并核对日常是否落在 平/落/缓/悬 拍；
- 期待感强度曲线：软件用 inline SVG 把全卷逐章 `beats` 画成强度曲线（平 1 → 顶 5）；
- 反转类型分布：统计全卷承③/转① 的类型覆盖与重复情况；
- 支线推进矩阵：按支线名汇总其在 10 个故事里的推进；
- 引线闭环表：故事N 引线 → 故事N+1 起①破口；
- 节拍体检：按 12 拍纪律（不连续 3 章同拍 / 顶最多 2 连 / 顶后接落或缓 / 悬落末章）逐故事体检；
- 环节完整性矩阵：10 故事 × 10 环节的 ●/○/· 热力表；
- 大高潮分解 · 代价阶梯：来自顶层 `escalation`；
- 悬念债务表：来自顶层 `debts`；
- 对手推进表：来自顶层 `rivals`；
- 人物成长与资源表：来自顶层 `growth`；
- 地点 / 组织索引：来自顶层 `places`；
- 伏笔追踪表：来自顶层 `foreshadows`；
- 人物出场表：来自顶层 `cast`；
- 期待兑现标签：来自每个环节的 `pay`；
- 故事锚点导航：点击直达对应故事（`:target` 高亮，纯静态）。

因此你只需把数据写全，界面会自动长出上面这些视图；缺失的条目会在对应面板里明确提示，不会静默空白。

### 一、MD 正文（给人阅读）

按故事逐个输出文本版卷纲：

1. 开头先写**卷级定位**（卷定位 / 主题句 / 叙事形态 / 结构选用 / 建议章数 / 卷末落点）与**卷级人物功能位总览**（引路 / 主角 / 阻力 / 镜子 / 代价 / 预埋）；
2. 再逐个故事写：章数范围、小高潮、交付人物、获得物、引线、承③/转① 反转类型、12 章节拍、三层线，以及 10 个环节的要点；
3. 结尾附**跨故事台账**：大高潮分解 · 代价阶梯（10 条）、悬念债务、对手推进、人物成长与资源、地点/组织索引、伏笔追踪、人物出场表。

### 三、保存请求

最后附加 `outlineSaveRequest`：

```json
{
  "outlineSaveRequest": {
    "targetFolder": "卷纲",
    "fileName": "卷纲-第XX卷.md",
    "fileType": "volume-outline",
    "writeMode": "create",
    "referencedSkills": ["DagangSkill/juangangzhedieshu"],
    "sourceIntent": "生成第XX卷卷纲",
    "content": "# 卷纲-第XX卷：……（与上方 MD 正文一致）"
  }
}
```

**不需要**在 `outlineSaveRequest` 里提供 `htmlContent` —— 软件会自动用卷纲数据套模板渲染 HTML。

## 输出顺序

1. MD 正文；
2. ```json 围栏的 `volumeOutlineData`（10 故事 × 10 环节全写满）；
3. `outlineSaveRequest`（content 为 MD 正文）。

## 常见错误

- 故事不足 10 个，或用「…」跳过中间故事。
- 环节不足 10 个，或每环节条目不足 3 条。
- 承③ 与 转① 用了同一类反转。
- 节拍连续 3 章相同；「顶」后没接「落/缓」；「悬」不在故事末章。
- 日常落在「紧/顶」节拍；日常没有埋伏笔。
- 自己手写 HTML/CSS/标签（不需要，软件会按技能目录下的 template.html 渲染）。
- 输出 8 个方法论板块（被禁止）。
