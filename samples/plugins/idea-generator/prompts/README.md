# 提示词怎么改（不需要写代码）

声明式插件的业务逻辑**全部在提示词里**。改提示词 = 改产品，不需要写 JS、不需要改宿主、
不需要重新构建 —— 改完重启 App（或重新安装插件目录）就生效。

## 提示词在哪

提示词是 `plugin.json` 里的内联字符串，不在本目录：

```jsonc
"contributes": {
  "actions": [
    {
      "id": "generate-titles",
      "prompt": {
        "system": "你是中文网文的资深书名策划……",     // ← 定角色与约束
        "user":   "书名风格：{{config.titleStyle}}\n核心灵感：{{idea}}……"  // ← 定任务与输出格式
      }
    }
  ]
}
```

> **本目录为什么是空的（只有这份说明）**：设计里给 `prompts/*.md` 留了位置（便于长提示词与
> 将来多语言），但**当前宿主只读清单里的内联 `prompt`**，不读外部 `.md` 文件 —— 全仓没有任何
> 代码去加载 `prompts/`。所以在这里放 `.md` 草稿可以，但**必须把最终文本粘回 `plugin.json`**，
> 否则不生效。等宿主支持「`prompt` 引用文件」以后，本目录才会真正装东西。

## 两条分工要说清

| 字段 | 该写什么 | 不该写什么 |
|---|---|---|
| `prompt.system` | 角色、专业背景、硬约束、"你只输出 X，不解释" | 具体这次要生成什么 |
| `prompt.user` | 变量（`{{idea}}`）、输出格式、条数、取值范围、反面例子 | 重复 system 里的角色设定 |

`system` 定「你是谁」，`user` 定「这次做什么」。两者混着写，作者改一次 A 就得回头改 B。

## 变量插值规则

| 写法 | 来源 | 需要权限 |
|---|---|---|
| `{{idea}}` | 用户在表单里填的字段（`form.fields[].key`） | 不需要 |
| `{{config.titleStyle}}` | `configSchema` 对应的用户配置 | 不需要 |
| `{{project.bookTitle}}` | 当前项目信息 | **需要 `fs:project-read`** |
| `{{chapter.title}}` / `{{chapter.text}}` | 当前打开的章节（标题 / 正文） | **需要 `fs:project-read`** |
| `{{selection}}` | 编辑器当前选区 | **需要 `fs:project-read`** |

规则细节（与 `src/lib/plugins/declarative/interpolate.ts` 一致）：

- 变量名**区分大小写**，写错不会报错，只会替换成空串并记进 `missing`（作者排查用）；
- 数组按**顿号**连接（`{{project.bookTags}}` → `玄幻、修仙`）；
- 转义：写 `\{{idea}}` 输出字面量 `{{idea}}`（表单里要教用户写模板时用得上）；
- 引用了 `{{project.*}}` / `{{chapter.*}}` / `{{selection}}` 的 action，**插件必须声明
  `fs:project-read`**，否则该校验阶段就被拒（设计 §3.3）；
- `{{count}}` 这类数字变量替换后是**字符串**（`5`），提示词里要写「{{count}} 个」而不是靠它算数。

## 输出格式：让 `mode` 好解析

`output.mode` 决定宿主怎么解析模型输出（解析失败永不报错，只降级为原文展示）：

| `mode` | 提示词里必须要求 | 本样例 |
|---|---|---|
| `list` | **每行一条，不要编号、不要解释**（宿主会去编号、去成对引号，但别指望它救回一段散文） | 书名、标签 |
| `text` | 直接写正文，不要「以下是」之类的开场白 | 人设 |
| `json` | 只输出 JSON，不要代码块围栏（宿主能从噪音里抽第一个 `[` / `{`，但抽取不是保证） | 未使用 |

### 一段好提示词的四个特征

1. **有角色**："你是中文网文的资深书名策划，做过十年签约书名" 比 "你是一个助手" 强十倍。
2. **有硬约束**：字数、条数、每行一条、不要编号 —— 能被机械检查的约束要写死。
3. **有反面例子**：明确点出"不要给正确的废话""不要「精彩」「爆款」这类词"，比只给正面要求有效。
4. **短**：3-8 行足够。提示词越长，模型越容易漏掉其中某一条；能用一句话说清就别写三句。

## 改完怎么验

1. 在插件设置页改配置（`configSchema` 会渲染成表单），确认 `{{config.*}}` 取到值；
2. 点 action 按钮，填表单跑一次；结果面板如果显示"降级为原文"，说明模型没守格式，
   回去把 `user` 里的「每行一个、不要编号、不要解释」写得更硬；
3. `list` 模式想验证清洗是否生效，可以故意让模型带编号跑一次 —— 结果里不该出现 `1.`。

> 提示词即产品：声明式插件没有代码兜底，模型的输出质量就是用户对插件的全部印象。
> 这也是设计里宁可把 `prompts/` 目录留给长文本的原因。
